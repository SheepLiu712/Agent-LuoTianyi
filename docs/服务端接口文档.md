本文的“全部接口”指服务端实际注册的**网络入口**，不把内部 Python 方法、服务端调用的第三方 API 或未挂载的历史请求类计为对外接口。没有独立的 HTTP 文本聊天、上传语音、唱歌或触摸路由；聊天和相关互动通过 `/chat_ws` 输入，由角色决定后续动作。

## 地址与运行状态

默认地址为 `http://127.0.0.1:60030`，WebSocket 为 `ws://127.0.0.1:60030/chat_ws`。由启动环境变量 `SERVER_HOST`、`SERVER_PORT` 控制。部署 TLS 后使用 `https://`、`wss://`，反向代理前缀由部署决定，源码没有统一 `/api/v1` 前缀。

服务端 Web 进程与业务运行时可以分别处于可用和不可用状态：配置不完整时仍可打开管理页面修复配置。普通用户 HTTP 接口（包括公钥和模型类型查询）都依赖业务运行时；未启动返回 HTTP 503：

```json
{
  "detail": {
    "ok": false,
    "code": "SYSTEM_RUNTIME_NOT_READY",
    "message": "服务端尚未完成配置或系统运行时未启动",
    "runtime": {}
  }
}
```

这里的 `runtime` 是公开运行状态对象，实际字段由 `RuntimeSupervisor.public_status()` 产生，不是固定空对象。WebSocket 相应发送 `system_not_ready` 并关闭，详见协议文档。

## 客户端接入顺序

1. 读取公钥，用 RSA-OAEP SHA-256 加密密码，然后注册或登录。
2. 保存 `login_token` 供下次自动登录；使用 `message_token` 调用业务 HTTP 和认证 WebSocket。
3. 建立 `/chat_ws`，收到 `system_ready` 后发送 `user_auth`；收到 `auth_ok` 再发聊天输入。
4. 每个业务事件使用唯一 `client_msg_id`，建议协商 `negative_ack_v1`，处理接纳确认、拒绝及不确定投递。
5. 按消息 `uuid` 和 `packet_sequence` 聚合回复；以 `is_final_package` 结束该消息，音频逐片 base64 解码。
6. 用 `/history` 补取持久化历史，图片按消息 UUID 从 `/get_image` 读取。重连没有自动历史重放。

## 通用约定与边界

- JSON 请求使用 `Content-Type: application/json`。示例中的令牌、密文、UUID 是占位符。
- 未显式指定时成功为 HTTP 200；接口没有统一的成功 envelope，有对象、数组、图片和 HTML 等返回形式。
- 常规 HTTP 错误为 `{"detail": ...}`；`detail` 可为字符串、结构化对象或 Pydantic 校验错误数组。缺字段、错误类型等框架校验通常返回 422。
- 用户名与内部用户 UUID 不同。登录返回的 `user_id` 当前是用户名，而历史/动态内部关联使用用户 UUID；不要把字段名相近理解为可互换。
- 历史、动态常用 `YYYY-MM-DD HH:mm:ss`，没有时区偏移；WebSocket `ts` 是 Unix 毫秒，可观测数据通常为含时区的 ISO 字符串。不要对所有时间字段使用同一解析规则。
- 文档描述当前源码读取和测试中的行为；本次不启动依赖真实模型、资源与凭据的完整服务，不对生产部署地址或真实外部服务可用性作承诺。
