# 代码地图

本图用于定位代码、理解模块职责和选择修改位置。描述当前分支的实现。函数签名、配置值和验证结果直接查看源码、配置与测试，不在这里维护副本。

## 1. 子项目与入口

项目由一个服务端和多个客户端组成。角色认知、对话与记忆、世界任务主要运行在服务端；客户端负责交互、展示、音频播放及本地设备能力，通过 HTTP / WebSocket 使用服务端。

| 子项目 | 当前职责与技术 | 代码入口 |
| --- | --- | --- |
| `server/` | Python / FastAPI 服务端；角色运行时、对话、技能、持久化、世界任务和管理接口 | [server_main.py](../server/server_main.py)、[ServerRuntime](../server/src/server_runtime.py) |
| `client/` | Python / PySide6 桌面客户端；窗口、Live2D、消息收发、音频播放 | [main.py](../client/main.py)、[MessageProcessor](../client/src/message_process/message_processor.py) |
| `cli-client/` | 独立的无 GUI 客户端；通过自身的 HTTP / WebSocket 实现完成注册、登录、历史加载、输入、状态观察、等待回复和场景判定 | [README](../cli-client/README.md)、[cli.py](../cli-client/cli.py)、[ActionExecutor](../cli-client/cli_client/cli/actions.py) |
| `app/` | Expo / React Native 移动客户端，当前重点为 Android；Live2D 通过 WebView 展示 | [路由布局](../app/app/_layout.tsx)、[聊天页面](../app/app/index.tsx)、[消息处理](../app/utils/message_processor.ts) |
| 管理控制台 | 服务端附带的 Web 前端，用于配置、账号和运行时管理；不是另一套角色聊天客户端 | [server/res/admin_ui/src/main.tsx](../server/res/admin_ui/src/main.tsx)、[服务端注册](../server/src/web/admin/ui_register.py) |

后续客户端方向：

- **Godot 客户端**：后续客户端迁移方向；当前 `dev` 尚无对应源码目录，不能将 `client/` 或 `app/` 视为已经替换。

## 3. Server 模块职责与边界

下表是功能归属的第一判断依据。模块允许有自己的内部实现；不因为一个实现调用了模型、读取文件或使用网络，就自动将它搬到公共基础设施。

| 模块 | 拥有的职责 | 职责边界与入口 |
| --- | --- | --- |
| `domain` | 共享业务语言、值对象、请求与结果、跨模块端口契约 | 不装配服务、不执行网络或数据库操作。Agent 契约从 [domain/agent](../server/src/domain/agent/__init__.py) 进入 |
| `web` | 对外 HTTP / WS、请求响应、认证与连接维护、管理页面接入 | 角色输入交给 Adapter；账号、管理操作调用 Application。物理 `WebSocketConnection` 在 [websocket/service.py](../server/src/web/websocket/service.py)；路由入口为 [bindings.py](../server/src/web/bindings.py) |
| `application` | 非角色认知的应用用例：账号、历史查询、管理、运行时启停 | 负责用例编排，不依赖 FastAPI / WS 实现；不决定角色说什么。入口为 [ServerLifecycle](../server/src/application/server_lifecycle.py)、[admin](../server/src/application/admin/admin_shell.py)、[user](../server/src/application/user/account.py) |
| `adapter` | 把外部信道输入转换成 Stimulus，把 Agent / Stage 输出转换成信道消息；管理逻辑绑定与投递 | 不拥有物理连接服务，不维护回复批次，也不生成角色决策。当前只有 [WebSocketAdapter](../server/src/adapter/websocket/adapter.py)，不预建通用 World Adapter |
| `stage` | 一次持续交互的生命周期、输入准备状态、待回复批次、期限、取消、计划队列与输出结算 | 拥有交互调度，不接管角色认知；生产 Agent 两个业务入口由 Stage 调用。[ChatStage](../server/src/stage/chat_stage.py) 面向聊天，[WorldStage](../server/src/stage/world_stage.py) 面向角色与世界的长期交互，[StageManager](../server/src/stage/stage_manager.py) 管理聊天连接接入、重连与离线回收 |
| `agent` | 根据刺激理解和决策、生成计划、实现行动、更新角色认知内容 | [Agent 门面](../server/src/agent/facade.py) 的两个业务入口为 `handle_stimulus`、`realize_action_plan`。Handler 编排行为，Skill 承载能力；不接管 socket、交互队列和计时器 |
| `agent_runtime` | 角色注册，构造各角色 Agent、路由、角色资源、上下文工厂和共享技能，管理关闭 | 是 Agent 子系统的装配与生命周期模块，不是新的认知入口，也不是每用户会话容器。见 [AgentRuntime](../server/src/agent_runtime/agent_runtime.py) |
| `infrastructure` | 中立的模型调用、存储、媒体处理、配置与可观测机制 | 提供技术能力，不决定角色行为，不反向依赖 Agent / Stage / World / Adapter / Web / Application。模型入口为 [LLMService](../server/src/infrastructure/models/service.py)，数据库入口为 [DatabaseManager](../server/src/infrastructure/persistence/database/database_service.py) |
| `world` | 外部环境、世界事实、采集与学习工作流、定时任务及世界侧结算 | 任务提供事实或到期条件；角色表达、记忆与接纳决定交给 Agent。世界时钟只负责唤醒。见 [WorldRuntime](../server/src/world/world_runtime.py)、[WorldTask](../server/src/world/types/world_task.py) |
| `utils` | 低层可复用的日期、日志、音频、异步等辅助代码 | 不作为新业务的兜底目录；公共 LLM / VLM 实现在 `infrastructure/models`，角色记忆在 Agent 内 |
| `server_runtime.py` | 构造、连接并关闭服务端业务对象图，初始化失败回滚 | 顶层组合根，向各子系统注入依赖；不承载角色决策或 HTTP 路由。见 [ServerRuntime.initialize](../server/src/server_runtime.py) |

各个模块应该避免直接依赖`ServerRuntime`，然后从顶层组合根再拿自己需要的依赖。在组装时，各个模块应该直接接受自己需要的依赖，不需要知道组合根的组装逻辑。

当前仍有 WorldTask 通过初始化注入的 `server_runtime` 取得数据库、角色标识或 WorldStage，这是现有实现的耦合，不能把它误读为已经完全改成窄端口注入。新增依赖应参考已注入的 [SingingBackendPort](../server/src/world/learn_sing_songs/ports.py)，避免扩散对组合根内部对象的访问。

## 4. 关键调用链

以下箭头表示运行时消息或调用流，不是完整的 Python import 图。依赖装配由组合根完成，返回路径通过 sink / 回调连接。

```text
用户交互：
client / app
  → web.websocket（接收与认证）
  → adapter.websocket（转换、定位绑定的交互）
  → ChatStage（准备输入、组织批次、触发 InteractionDeadline）
  → Agent.handle_stimulus → stimulus handler → skills
  → ActionPlanSink → ChatStage 的计划队列
  → Agent.realize_action_plan → action handler → skills
  → AgentOutputSink → adapter.websocket → web 的连接 → 客户端

世界交互：
WorldClock → WorldTask（观察 / 采集 / 完成工作流）
  → WorldStage.fact_sink → Agent.handle_stimulus
  → WorldStage 的计划队列 → Agent.realize_action_plan
  → 技能执行及世界侧结算

非角色用例：
HTTP / 管理页面 → web → application → infrastructure
```

World 并非每项维护任务都要调用 Agent：凭据维护、事件清理等可以完成世界侧技术工作。需要角色理解、接受知识或表达时，才进入 WorldStage。具体注册项见 [WorldRuntime](../server/src/world/world_runtime.py)，不在地图复制周期和开关。

## 5. 需要特别保留的设计理由

### 5.1 Web、Adapter、Stage 各自对应不同的变化来源

登录、鉴权、状态查询、管理控制台和物理 WS 连接是网络服务，归 Web。把某种信道的消息解释成角色输入、将交互绑定到信道，归 Adapter。积累哪些输入、何时回复、如何打断与重连，归 Stage。

这让客户端换成 Godot 或 CLI 时可以继续使用同一服务端协议；未来新增不同信道时，转换规则也有明确归属。World 当前直接构造领域事实并投递给 WorldStage，暂时无需为了形式统一再套一层 Adapter。

### 5.2 Agent、Skill、交互上下文具有不同的实例范围

- 每个角色有自己的 Agent 门面、路由和角色资源。
- 一个 AgentRuntime 中只有一套 [SharedSkills](../server/src/agent/skills/facade.py)，所有角色、用户共用；角色资源作为其内部映射依赖存在。
- 每次技能调用通过 [SkillInvocation](../server/src/agent/skills/contracts.py) 等调用参数显式提供身份；共享 Skill 不保存“当前用户 / 当前角色”的会话状态。
- [InteractionContext](../server/src/agent/context/interaction_context.py) 的实现位于 Agent，但实例生命周期由 Stage 管理，调用时借给 Agent；它不是 Agent 的角色全局上下文。

这样共享昂贵能力与资源，同时保持不同用户和交互的数据隔离。更改 Skill 时必须考虑并发调用；不能通过往共享实例写入当前用户来简化参数。

### 5.3 角色能力的技术实现跟随能力归属

图片理解、TTS、唱歌属于角色能力，相关实现随 Skill 保存在 Agent 中，包括 TTS 后端和进程管理。Infrastructure 保留通用 LLM / VLM / Embedding 服务、媒体持久存储和其他中立机制。

预制语音的业务目录在 [PreparedSpeechCatalog](../server/src/agent/skills/expression/prepared_speech.py)，文件仍属于资源。歌曲的可唱目录、元数据和路径由 Singing 技能管理，演唱时再读取音频；下载、清洗和生成歌曲产物的重任务在 `world/learn_sing_songs`。文件已生成不自动等于角色已经形成“学会歌曲”的记忆。

### 5.4 待回复输入、上下文和用户历史不是同一个容器

Stage 保存待处理输入、准备结果和本轮回复批次；Agent context 保存用于认知的用户资料、近期对话、总结和召回信息；Infrastructure 保存底层持久事实。准备完成不等于已经回复，处理完成也不等于全部输入被消费，Stage 按 HandlingReport 的输入 ID 结算。

一张图片在业务上保持一条用户消息：[图片预处理](../server/src/agent/handlers/stimulus/chat.py) 把图片理解文本与媒体引用放在同一条对话记录中。Agent 读取理解文本，用户历史显示图片；不会额外生成一条“图片理解”消息，也不假定图片附带 caption。历史展示入口见 [user_conversation_helper.py](../server/src/application/user/user_conversation_helper.py)。

### 5.5 Reflection 是 Agent 产生的行动，Stage 只调度

`InteractionDeadline` 的 [ChatReplyHandler](../server/src/agent/handlers/stimulus/chat.py) 在本轮成功处理并交付其他计划后追加 Reflection 计划。Stage 按队列执行；[ReflectionActionHandler](../server/src/agent/handlers/action/reflection.py) 调用技能提取记忆、压缩上下文、更新画像并清理本轮召回内容，不产生用户可见消息。

因此 Action 不只表示说话或唱歌，也可以表示认知维护。不要在 Stage 中另外发 Reflection 刺激，或让 Stage 调用记忆与画像技能。

### 5.6 交付、网络发送与客户端播放是不同的完成时点

`handle_stimulus` 可以交付多个计划，`realize_action_plan` 实现计划中的行动。回复处理器形成实际 Say / Sing 后会关闭本次 handle 的普通打断许可；开始思考信号本身不等于已经产生回复内容。Stage 取消前读取对应调用的许可，进程关闭等生命周期取消另有处理。

输出 sink 接受只说明输出已进入投递流程，不能据此声称网络已送达或客户端播放结束。客户端播放由各自的消息与多媒体处理模块负责。修改相关行为时同时查看 [Stage sinks](../server/src/stage/_sinks.py)、[Adapter 投递](../server/src/adapter/websocket/_delivery.py) 和客户端消费者。

Agent 当前使用单次调用内存状态，不依赖 `agent/ledgers` 中的 outbox 做恢复。目录存在不代表生产链已启用持久执行账本；不能从历史命名推断重放或重试保证。

### 5.7 服务端进程与业务运行时具有不同的生命周期

正式入口为 `python server_main.py`。`run_server` 在一个事件循环中启动 ServerLifecycle、运行 Uvicorn，并在 `finally` 释放资源；Uvicorn lifespan 关闭。

[ServerLifecycle](../server/src/application/server_lifecycle.py) 管理 AdminShell；[RuntimeSupervisor](../server/src/application/admin/runtime_supervisor.py) 控制 ServerRuntime。配置不完整导致业务运行时未启动时，管理 Web 仍可用于修复配置。ServerRuntime 负责业务对象图，AgentRuntime 负责其中的角色子系统，这些范围不应合并成一个含糊的“startup”。

### 5.8 客户端可以执行模型请求，但角色编排仍在服务端

当前客户端具有模型调用实现。Infrastructure 通过中立的 [ClientModelExecutor](../server/src/infrastructure/models/client_execution.py) 契约表达委托能力，具体 WS 请求路由在 [ClientLLMExecutor](../server/src/adapter/websocket/client_model_executor.py)。这样模型服务不必依赖 WebSocket 实现；客户端执行模型请求也不意味着客户端拥有 Agent 的对话决策流程。

## 6. Server 测试管理与运行

`server/tests` 按验证边界组织，而不是逐级复制 `src` 的内部目录。测试文件只放在 `unit/`、`integration/`、`e2e/`；可跨目录复用的 fake、样例构造器与测试装配集中放在 `support/`，不放业务断言。根目录的 `conftest.py` 负责公共 fixture、标记和外部依赖开关；`support/` 模块使用 `from support.<模块> import ...` 导入。

| 目录 | 用途 | 默认运行条件 |
| --- | --- | --- |
| `unit/<module>/` | 单一顶层模块的快速离线测试；外部系统使用 fake | 默认运行 |
| `integration/<boundary>/` | 在同一进程连接多个真实组件，可使用临时数据库、文件系统或 TestClient | 默认运行 |
| `e2e/chat/` | 从生产装配或真实入口验证完整离线业务链 | 默认运行 |
| `e2e/external/` | 需要公网、凭据、模型或其他真实外部依赖的探测 | 默认跳过，显式启用 |
| `support/` | 各层共用的 fixture、fake 与数据构造器 | 被测试导入，本身不收集为测试 |

在 `server` 目录运行：

```powershell
python -m pytest tests/unit -q --tb=short
python -m pytest tests/integration -q --tb=short
python -m pytest tests/e2e -q --tb=short
python -m pytest tests -q --tb=short
```

默认全套会跳过标记为 `external` 或 `real_llm` 的探测。需要真实外部依赖时运行 `python -m pytest tests/e2e/external -q --run-external --tb=short`；真实 LLM 测试另加 `--run-real-llm`。覆盖率门禁、标记和环境开关的完整说明见 [server/tests/README.md](../server/tests/README.md)；架构边界验证位于 `tests/integration/architecture/`。
