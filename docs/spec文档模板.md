# 功能描述标题
## 用户故事
从用户、运维、数据分析师的视角描述功能需求。使用`作为 <角色>，我希望 <功能>，以便 <目的>`的格式描述用户故事。分条列出所有用户故事。

注意：
1. 功能和目的不要描述具体的技术实现，而只描述用户的需求和目标。
2. 对功能的实现需要精确到用户的具体操作，例如写`点击按钮后发送请求`，而不是泛泛地写`实现对话功能`。
3. 涉及`UI/UX`的功能需要画图。

## 验收标准
验收标准是对用户故事的具体实现要求，必须可验证。每条验收标准都应包含：
1. **状态**：执行验收标准的条件，例如`点击按钮后`、`收到消息后`等。
2. **输入**：执行验收标准的输入数据，例如`输入文本`、`选择文件`等。具体的输入内容需要明确。
3. **输出**：执行验收标准的预期输出结果，例如`显示文本`、`发送请求`等。具体的输出内容需要明确。

将验收标准分条或分节列出，确保每条验收标准都能独立验证。

## 模块与架构
描述功能涉及的模块和架构设计。包括模块之间的关系、数据流向和系统架构图。

### 模块划分
描述功能中各个模块的职责和功能，以及归属于当前哪个架构中模块。

### 接口规范
描述模块之间的接口规范，包括输入输出数据格式、调用方式和约束条件。确保接口规范清晰、可实现和可验证。

## 备注
### 关键技术选型
如果在当前阶段已经确定了技术方案选型，则写在这里。

### 非目标
描述当前功能不涉及的内容，明确功能边界，避免后续开发中出现范围蔓延。
