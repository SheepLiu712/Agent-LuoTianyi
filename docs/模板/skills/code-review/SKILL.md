# 规范与需求双轴审查

本技能将 [code-review 的双轴方法](https://github.com/mattpocock/skills/tree/main/skills/engineering/code-review)用于本仓库，作为 [PR 审查技能](../pr-review-report/SKILL.md)中的实现审查步骤。主审负责测试预期核查、分级、复审和最终报告。

## 准备输入

使用主审固定的起止提交与比较范围。确认提交可解析，通过 `git diff <目标提交>...<被审提交>` 检查共同祖先以来的改动，并核对提交清单；存在前置 PR 时采用主审指定的增量范围。若差异为空，应先核对比较对象。准备[《开发守则》](../../../开发守则.md)中的项目规范，以及本次交付对应的工单或功能规格说明。缺少确认过的需求时，告知主审哪些行为无法判断。

## 分别检查两方面

两项审查共享提交范围，独立形成结论。可用并行审查时，给两个审查者分别提供相同差异和各自所需依据。

- **规范符合性（STANDARD）**。核对改动是否符合仓库对模块职责、接口边界和代码风格的要求。每项违反规范的发现须给出规范出处和被审代码位置。名称含糊、重复逻辑、重复分支、职责分散、访问其他对象内部数据、只做转发的抽象等可用于发现维护问题；须结合具体影响区分明确违规和设计建议。项目规则优先，工具已检查的格式问题无需重复报告。
- **需求符合性（SPEC）**。从确认过的验收要求检查遗漏、实现错误和超出交付目标的行为。每项发现应说明对应要求、实际入口、触发条件和可观察结果，附文件位置和实测或静态证据。缺少依据时指出待确认问题。

分别将两方面查到的事实、证据位置、未验证范围交给主审。一方面通过不能替代另一方面的判断。最终报告由主审按项目模板统一编写。
