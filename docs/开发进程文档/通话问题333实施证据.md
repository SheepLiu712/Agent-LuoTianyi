- **N1 return callback generation**：保存 `oldOwnerGeneration`，先释放旧 owner，再设置 `returnGeneration = oldOwnerGeneration + 1`；microtask 只在 `returnGeneration === generationRef.current` 且 mounted 时调用。`calls onReturnToChat exactly once when the failed attempt remains retired` 验证 callback exact-one；`calls onReturnToChat exactly once after failure and suppresses a queued return when a new attempt starts` 验证旧 microtask 隔离。
- **N2 closed 正常终态**：消费 `snapshot.status === 'closed'` 并派发无 error code 的 `call_ended`。`returns normally when transport closes after an active call and does not show a failure notice` 验证 ACTIVE → closed → IDLE、无 banner；既有 transport/state 测试继续覆盖 duration 与 334 monotonic 合同。

### 补齐调用链

`call.ended` → 协议校验/顺序接纳 → `CallTransportSession.terminate` 在一个终态快照中保留 `outcome`、`endReason`、时长 → `CallSession` 转发 → `useCallSession` 根据结束原因选择安全提示 → 返回聊天并清理；提示独立于生命周期状态重置。

- `setup_timeout` → 呼叫超时；`provider_failed` → 通话服务异常；`recovery_timeout` → 通话连接中断；`system_failure` → 通话异常结束。
- `closed` 不等于业务成功；`cancelled_before_answer` 不等于用户主动取消。正常挂断、拒接、时间上限保持无错误提示。本地主动取消/挂断后，旧连接的异常终态仍受 attempt generation 隔离。
- Hook 收到终态会同步释放 Session 并调用 `close()`。Transport 现在先登记唯一清理 Promise，再通知终态，防止重入覆盖首次结束原因、时长或 `failed` 错误码，以及重复注销音频监听和启动清理。
- Spec 补充了上述行为规则。模块职责未改变，本次不更新代码地图。

### 组合测试与实际结果

`call_failure_composition.test.tsx` 使用真实协议编解码、Transport、CallSession、hook/reducer 和 Banner，仅替换 socket/native 外部端口，覆盖：

- 四种异常结束原因在接通前/后显示安全提示，并保留终态事实和时长；结束后音频停止、Socket 关闭、监听释放、返回聊天各按约定完成。
- 用户取消、用户正常挂断、角色挂断、拒接、通话时限结束不提示错误。
- 本地取消/挂断后迟到异常、重复终态、关闭提示、旧 Socket 干扰新尝试、新尝试清除旧提示。
