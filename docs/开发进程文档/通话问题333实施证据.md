## attempt2 N1–N3 红绿证据

- **N1 return callback generation**：保存 `oldOwnerGeneration`，先释放旧 owner，再设置 `returnGeneration = oldOwnerGeneration + 1`；microtask 只在 `returnGeneration === generationRef.current` 且 mounted 时调用。`calls onReturnToChat exactly once when the failed attempt remains retired` 验证 callback exact-one；`calls onReturnToChat exactly once after failure and suppresses a queued return when a new attempt starts` 验证旧 microtask 隔离。
- **N2 closed 正常终态**：消费 `snapshot.status === 'closed'` 并派发无 error code 的 `call_ended`。`returns normally when transport closes after an active call and does not show a failure notice` 验证 ACTIVE → closed → IDLE、无 banner；既有 transport/state 测试继续覆盖 duration 与 334 monotonic 合同。
- **N3 同步与初始化失败**：createSession 同步 throw、subscribe 安装失败、initialize false/reject、start/prepare reject 统一进入 attempt failure reporter；已知 code 与未知 raw 映射安全文案，权限拒绝仍走原权限 UX。`shows a safe notice for synchronous create and initialization failures, while permission denial stays non-failure` 与 `covers subscribe installation, initialize rejection, prepare rejection, and start rejection as safe failures` 覆盖实际路径。
- **N3 observer exception**：`reportAttemptFailure` 先安全设置 notice，再以 try/catch 调用 `onFailure`，异常交给既有 cleanup reporter；不会阻断 `call_ended`、cleanup 或 return-to-chat。参数化 `keeps terminal cleanup when onFailure throws for a snapshot/callback failure` 与 `does not reject or leak when synchronous creation fails and the failure observer throws` 验证 state `IDLE`、安全 notice、callback/return exact-one、close exact-one。`AUTH_REJECTED` 与 `CALL_AUTH_REQUIRED` 共用重新登录文案并有映射回归。

## 当前绿证据

### 用户提示与生命周期回归

测试文件：`app/__tests__/call_failure_ui.test.tsx`

- `maps known and unknown codes to safe actionable copy without raw details`
  - 稳定 code `CALL_CONNECTION_LOST` 映射为“通话连接失败 / 未能建立通话连接，请检查网络后重试。”
  - 未知字符串含 provider URL、token、stack 时使用安全 fallback，不渲染原文。
- `renders a dismissible banner using the normal app theme affordance`
  - 显示普通 banner，使用主题 surface/border/text，提供“知道了”，非阻断 Modal、无额外动画。
- `keeps one failure notice after return-to-chat, deduplicates callback and snapshot, and clears it for the next attempt`
  - callback 与失败 snapshot 同一 attempt 只保留一条提示；cleanup/reset 后提示仍在；dismiss 后清除。
- `does not create a failure notice for a user hangup`
  - 主动挂断不显示失败提示。
- `clears the previous notice at a new attempt and ignores a retired attempt failure`
  - 新 attempt 清除旧提示；旧 generation 的迟到错误不覆盖当前状态；新 attempt 的真实失败仍可显示。

## 错误码与文案

| 内部 code | 用户标题 | 用户说明 |
|---|---|---|
| `SERVER_CALL_UNAVAILABLE` | 通话暂不可用 | 服务暂未准备好，请稍后再试。 |
| `NATIVE_CALL_UNAVAILABLE` | 无法使用麦克风 | 请检查设备音频权限和通话能力后重试。 |

| `AUDIO_FOCUS_LOST` | 通话音频已中断 | 设备音频被其他应用占用，请重试通话。 |
| `CONTROL_OUTBOX_FULL` | 通话暂时繁忙 | 通话请求未能及时送达，请稍后再试。 |
| 其他未知 code | 通话失败 | 通话未能建立，请检查网络和设备权限后重试。 |
