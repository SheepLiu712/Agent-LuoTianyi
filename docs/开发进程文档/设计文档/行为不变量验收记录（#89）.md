### F1：world → `system_runtime.agent_runtime` 只读属性耦合（已知偏差，非本次引入）

- **事实**：5 个 world 模块通过 `getattr(system_runtime, "agent_runtime", None)` 读取 Agent 侧属性，共 7 处：
  - `world/world_runtime.py:257/267`（`character_runtimes`、`default_character_id`，用于枚举/取默认角色以注册任务）
  - `world/citywalk/task.py:171/220`（`default_character_id`、`vector_store`，用于构造 `CitywalkRuntimeService`）
  - `world/dynamic_interaction/task.py:288`、`world/get_new_songs/task.py:96`、`world/learn_sing_songs/task.py:126`（`default_character_id`，用于取得本角色 WorldStage）
- **定性**：**只读属性访问，不调用任何 Agent 业务方法**；`git show 9ed8d1c:` 逐文件比对显示与旧架构**完全同源、数量一致**（同一模式计数在新旧提交上逐文件相同），**非本次重构引入**。
- **影响**：违反 G2 的「world 不依赖 Agent 内部」的严格表述，但属装配层读取（角色枚举 + 向量库句柄），不影响任何副作用正确性；已在 `check_architecture_boundaries.py` 的 B7 中以 allowlist 形式**冻结**，一旦扩散到新文件即 FAIL。
- **建议**（独立工单，不在本次范围）：world 侧改为读自身角色配置，`vector_store` 由 `SystemRuntime` 以显式端口提供。
