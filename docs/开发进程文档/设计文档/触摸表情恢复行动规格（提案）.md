# 触摸表情恢复行动规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录方案与冲突，不实现、不改 interface 文档。
- 关联工单：Issue [#74](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/74)（15 触摸预制反应、独立表情恢复与失败丢弃）
- 相关规范：总 SPEC 第 4.5、7.14、8.4 节；[交接清单](../开发进度/Agent重构交接清单.md) 的「触摸失败与表情恢复的迁移约定」

## 1. 要解决的问题与冲突

交接清单要求：成功触摸由 handler 交付**瞬时 SAY 计划**，再交付**独立的表情恢复计划**（目标 `normal`），SAY 不隐含恢复；Stage 按序 realize。

但当前领域接口存在冲突：

- `ActionKind`（`server/src/domain/agent/realization_enums.py`）只有 `START_THINKING / SAY / SING / WRITE_DIARY / PUBLISH_DYNAMIC / REPLY_DYNAMIC / REQUEST_SONG_LEARNING`，**没有表情恢复类型**；
- `ChangeExpression` 目前只是 `Say` / `Sing` 的内嵌值对象；
- 总 SPEC 7.14 明确写「**`ChangeExpression` 只保留为 `Say`/`Sing` 内嵌值对象；没有独立 Action**」，与 8.4 / 交接清单的「独立恢复 ActionPlan」直接冲突。

**必须先裁决这一冲突**，否则 15 无法实现。

## 2. 备选方案

| 方案 | 做法 | 与 SPEC 7.14 的关系 | 代价 |
| --- | --- | --- | --- |
| A. 新增独立 Action `RestoreExpression` | 新增 `ActionKind.RESTORE_EXPRESSION` + Action（含 `expression_id`、`delivery`），handler 输出 `ExpressionDraft` | 需**修订 7.14**（取消“无独立 Action”的约定） | 公开领域枚举扩大；`plan_identity._types` 白名单新增 |
| B. 复用 `Say` 承载恢复 | 用 `Say` 且不带音频、正文为空 | 违反 `Say.__post_init__`（空白正文仅在带预制音频时合法） | 需改 `Say` 校验，影响面更大 |
| C. 由 Stage/Adapter 隐式恢复 | 触摸 SAY 结束后由 Stage 补发 normal | 与 8.4「SAY 不默认恢复、需独立计划」冲突 | 角色行为决策泄漏到 Stage |

倾向 **A**：把「恢复到 normal」建模为角色的一次外部动作（ActionPlan + realize），语义清晰、可由 Stage 按序执行并结算；代价是修订 7.14 并扩大一个受控枚举。

## 3. 若采用 A 的建议 interface（目标，未实现）

```python
class ActionKind(str, Enum):
    ...
    RESTORE_EXPRESSION = "restore_expression"

@dataclass(frozen=True, slots=True, kw_only=True)
class RestoreExpression(Action):
    kind: ClassVar[ActionKind] = ActionKind.RESTORE_EXPRESSION
    expression_id: str          # 目标领域表情代码，触摸恢复为 "normal"
    delivery: OutputDelivery    # 触摸为 EPHEMERAL_REACTION
```

- **调用者**：触摸 handler 在交付 SAY 计划后，作为独立 `plans.emit(...)` 交付。
- **实现**：新增 action handler，输出 `ExpressionDraft(delivery, ChangeExpression(expression_id))`，返回完成结果；无需新的输出类型（`ExpressionOutput` 适配层已存在）。
- **失败行为**：失败停止后续行动并返回稳定错误；不隐式重试。

## 4. 影响面

- `domain/agent`：新增 `ActionKind` 成员与 Action 类（公开领域接口扩大）。
- `agent/processing/plan_identity.py`：`_types` 白名单必须加入新类，否则 `emit` 运行时报 `unsupported plan value`。
- `agent_runtime`：注册新 action handler。
- 文档：需修订总 SPEC 7.14，并在 `接口文档/domain/realization.md` 记录新 Action（当前未改）。
- 测试：领域契约、handler、Stage 顺序（SAY → 结束标志 → 恢复计划）。
