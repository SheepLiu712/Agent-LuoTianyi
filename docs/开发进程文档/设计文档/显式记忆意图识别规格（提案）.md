# 显式记忆意图识别规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录行为契约与识别方式取舍，不实现。
- 关联工单：Issue [#71](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/71)（12 显式记忆与成功承诺边界）
- 相关规范：总 SPEC 第 6.4、6.7、6.10 节；现有能力 `subconscious/memory/`（`MemoryWriter`）、`agent/skills/reflection/`（`ReflectionSkill`）

## 1. 要解决的问题

用户明确要求「请记住……」时，角色必须**先可靠写入记忆、再承诺成功**；失败则保留刺激并返回失败，`retryable=False`。当前新链路没有任何显式记忆路径，也**没有意图识别**：

- 设计 6.7 把 `RecordIntentionalMemory` 定为 Agent 内部 `IntentionalMemoryCommit` 技能；
- 设计 6.4 要求「模型可见 tool schema 只来自 allowlist」——该工具调用链**尚未实现**；
- 因此需要一个**过渡期的意图识别方式**，否则 12 无法落地。

## 2. 建议行为契约（无论识别方式如何都成立）

1. 识别为显式记忆请求后，在**本次 handle 内**调用内部 `IntentionalMemoryCommit`（幂等），**等待提交结果**；
2. 仅当提交成功，才交付表示「已记住」的 `Say` 计划；
3. 提交失败：返回 `FAILED` + 稳定错误码，**保留刺激**（不消费）、不承诺成功；
4. 该写入不进入 `ActionPlan`（它是 Agent 自有状态变更，不是外部行动）；
5. 不引入 Ledger/重投/自动重发。

## 3. 识别方式的取舍

| 方案 | 说明 | 风险 |
| --- | --- | --- |
| A. 过渡期关键词/短语 allowlist | 命中「请记住 / 记住 / 记一下」等固定短语即触发 | 召回/误报有限；行为可预测、可测试；**不是** SPEC 目标形态 |
| B. 等模型工具调用（6.4 allowlist） | 由模型决定是否调用 `IntentionalMemoryCommit` | 依赖尚未实现的 tool-calling 与 allowlist；12 会被长期阻塞 |
| C. 两者并存：A 作过渡，B 落地后替换 | 先交付可验证行为，后续替换 | 需明确 A 的移除条件 |

倾向 **C**：先用 A 交付可独立验证的切片，并在 PR/进度文档标注「临时启发式，待 B 替换」；A 的短语表与启用开关写入配置，避免硬编码扩散。

## 4. 影响面与未决问题

- 影响：新增内部 mutation 技能（`IntentionalMemoryCommit`）；回复/预处理链路增加一次识别与提交；配置新增短语表（属跨模块配置字段，需一并定 spec）。
- 未决：
  1. 是否同意先用关键词启发式（方案 C）并标注待替换？
  2. 短语表放配置还是代码常量？是否需要开关？
  3. 记忆写入复用 `write_topic_memories` 的通道，还是需要一条「显式记忆」专用通道（幂等键是什么）？
  4. 命中但写入失败时，是否需要给用户一个明确的失败表达，还是仅记录日志并保留刺激？

## 5. 明确不包含

- 不实现意图识别、记忆写入技能或 tool-calling allowlist。
- 不改变 `HandleStimulusRequest` / `HandlingReport` 等现有公开 interface。
