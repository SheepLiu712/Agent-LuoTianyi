## 2. 聊天主链（文本/图片/语音 → 预处理落库 → 批次回复 → SAY/SING → 客户端）

- **触发节奏**：客户端 Stimulus（`TEXT_MESSAGE`/`IMAGE_MESSAGE`/`VOICE_MESSAGE`）→ Stage 汇聚为批次 → `INTERACTION_DEADLINE` 触发回复。
- **旧架构**：`chat_session/chat_pipeline/chat_stream.py`、`topic_planner.py`、`ingress_helper.py` @9ed8d1c；入口由 `ChatSessionManager`/`ChatStreamManager` 持有，回复经 `AgentRuntime` 的 `preprocess_chat_event`/`extract_topic`/`plan_topic_turn`/`realize_topic_plan` 代理完成（均为旧业务代理）。
- **副作用**：
  - 落库：单条输入预处理后落会话记录（`handlers/stimulus/chat.py` 的 `ChatPreprocessingHandler` → `TextPreprocessingSkill`/`ImagePreprocessingSkill`）；批次回复正文落库（`ResponseCompositionSkill`，`chat.py:293` 交付 `ActionPlanDraft`）。
  - LLM：`main_chat`（`agent_runtime.py:509`）、`conversation_context_summary`（`skills/conversation/compaction.py:53`）、图片理解能力。
  - 发送：`Say`/`Sing` 行动 → `realize_action_plan` → 输出序列 → WebSocket + TTS/预制语音（`resources/prepared_speech`）。
- **必须保持的不变量**：
  1. 混合输入（图片慢、文本快）按完成顺序落库且等待最后一条完成后才回复（#09）。
  2. 一次 realize 收尾完成后才开始下一次；不等待客户端播放完成（G5/交接清单）。
  3. Say/Sing 计划次序与输出身份/序号稳定；失败停止后续但保留已完成效果（G6）。
- **证据**：`tests/agent/test_chat_preprocessing.py`、`tests/agent/test_chat_reply.py`、`tests/stage/test_chat_stage.py`、`tests/stage/test_concurrent_handling.py`（含 Windows 35ms 时序断言，本机偶发 32–34ms 抖动，隔离复跑通过）。
- **验收状态**：已有回归；真机端到端（真实客户端/TTS）未验收。

- **触发节奏**：周期＝world `proactive_topic_check` 每 300 秒唤醒 Stage 扫描；登录＝当天首次普通登录。

- **必须保持的不变量**：
