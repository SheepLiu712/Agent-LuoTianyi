## 一、范围

Android 端实时语音通话（`call.v1`）：独立 `call_ws`、CallStage、RealtimeSpeechSession（阿里云首个实现）、Agent 主导决策、TTS CALL 路由、呼叫账本与结算、认知维护迁移。

非目标与未来目标见 spec；本计划只覆盖 spec 声明的第一版。

按《开发守则》：从 `feat/voice` 开工作分支，各工单 PR 合入 `feat/voice`；功能完成后以集成 PR 合入 `dev`；完成后关工单、新增清理 issue，并在 `dev` 删除已完成的 spec。

## 二、当前基线（侦察结论，与 spec 预期的差异）

- 服务端只有 `/chat_ws`（`web/websocket/endpoint.py`）；纯 JSON（`receive_json`），无二进制帧、无入站帧上限。
- Stage：ChatStage + StageManager（进程内 `_stages`、60s 离线保留）；`InteractionEndingReason` 仅 `USER_LEFT/SHUTDOWN`；无租约、无切换意图、无通话原因。
- 认知维护现状 = 每次正式回复后执行 Reflection（`handlers/action/reflection.py`、`skills/reflection/consolidation.py`）；InteractionEnding 不触发维护，context 在 `finally` 关闭——spec AC-15 要求迁移为「压缩点＋交互结束」并重命名深化。
- `ConversationContext` 经 `_storage.py` 直连 ConversationService（无 `DatabaseConversationStore` 类；Ephemeral Store 不存在）。
- TTS：`speaking` 已有流式与取消（CancellationToken/TTSStreamCancelled）；输出链路 JSON base64（48KiB/包），无 CALL 路由字段。
- 幂等表（adapter）与投递队列（256/16MiB/64）均为进程内内存态；单 worker 仅是事实约定，无检查。
- App：无权限/录音基础；`MessageType` 无 audio；TTS 播放经 expo-av + WebView；16k PCM 采集与 24k 流式播放方案未定（Spike-B）。
- 桌面端/CLI 历史渲染：未知类型无占位；桌面端严格 `ConversationItem` 构造（新字段会静默清空历史）。
- 无 ADR 目录；`call.v1` 帧布局 ADR 缺；`call_sessions` 表、账本、概要、结算均不存在。

## 三、执行标准（《开发守则》摘要）

1. 工单 = 可独立说明交付结果的单位；工作分支 PR 合入 `feat/voice`；集成 PR 入 `dev`。
2. 确认 spec 非作者审核记录；PR 前补齐并运行证明验收范围的测试；相关通过不得写成全量通过。
3. 模块归属以《代码地图》为准；深模块、单一职责；新增转发接口要有真实第二实现才建。
4. 代码风格：black 120 + ruff（含 C901≤10）；app 用 Expo 默认。
5. 提交规范：工单内按逻辑单元**原子化提交**——每个提交自洽、可独立解释、配套其测试，不混入无关改动；工单 PR 由这组原子提交组成。

## 五、详细工单

### CL-1 认知维护迁移（前置，AC-15）

1. 先用现有 ChatStage 写**锁定测试**固定当前 Reflection 行为（每次回复后执行）。
2. `ReflectionSkill` → `CognitiveMaintenanceSkill`（`maintain_if_compaction_needed`/`maintain(reason=...)`）。
3. 触发点改为「压缩阈值＋InteractionEnding」；InteractionEnding 经 Agent 行动触发维护（保持「Stage 不直接调 Skill」边界）。
4. 维护进度幂等：聊天推进覆盖进度；通话路径的 `maintenance_turn_seq` 在 CL-10 接入。

验证：迁移前后行为差异有测试逐一说明；聊天回归不退化。

### CL-2 上下文 Store 拆分

1. `ConversationContext` 保持接口，内部组合 `DatabaseConversationStore`（聊天）/`EphemeralCallConversationStore`（通话）。
2. `ContextFactory` 按交互类型注入，不给调用方逐次 persist 开关。

验证：context 单测：两 Store 的 append/compact 可观察语义、通话内容不落库。

### CL-3 call.v1 契约与 ADR

1. 冻结 ADR：二进制帧头（协议版本/音频路由/stream_id/seq/flags/payload_length）、字节序、最大 payload、稳定错误码。
2. 控制消息 schema 与统一 seq 游标 + ACK/NACK + 重放缓冲规则、resume 握手不占 seq。
3. 协议夹具入库（客户端与服务端共享）。

验证：契约测试夹具 + 解析骨架；未知版本可拒绝。

### CL-4 web/adapter 信道扩展

1. `/call_ws` 端点：鉴权复用、`receive()` 分派 text/binary、入站帧上限。
2. Adapter：控制帧解析、`call_id` 与 CallStage 绑定、统一连续游标 ACK、缺口 NACK、30s/4MiB 重放缓冲、取消范围替换、有序背压投递、resume 重放。
3. `_protocol` 增加 CALL 路由字段（audio_route/stream_id/response_id/seq/final）。

验证（integration/websocket）：帧协议、游标推进、缺口、重放、协议冲突断连。

### CL-5 StageManager 切换与租约

1. `InteractionLeaseRegistry`：同用户同角色原子所有权；`CallTransitionIntent`（一次性、10s、绑定 user/char/interaction/client_request_id）。
2. `switch_prepare` → `switch_ready`；`call.start` 消费意图 → 建 `PREPARING` 账本 → 旧 ChatStage 以 `SWITCH_TO_CALL` 终止（先回收、关旧 Context 后才交权）。
3. 多 worker 启动闸门（配置为多 worker 时禁用/拒绝通话能力）。
4. 普通意外断线仍保留 60s 与重连（回归锁定）。

验证（integration/stage）：意图消费、竞态、其他设备拒绝、超时、两个 Context 不同时存在、普通断线回归。

### CL-6 CallStage

1. 状态机 PREPARING→RINGING→ACTIVE→RECONNECTING→ENDING/DECLINED/FAILED。
2. PCM 顺序/背压/去重；`audio.stream_started` 先登记待播放项；播放完成按 `(response_id, stream_id)` 幂等结算。
3. 沉默时钟：5s、重复完成不重置、RECONNECTING 暂停。
4. 打断：`playback.stop`（范围校验）+ 200ms 停发 + tombstone + `UserInterrupted` 事实。
5. 3s 恢复：快照、缓冲重放（30s/4MiB/回复、不淘汰最旧未确认）、计时口径。
6. 终态快照冻结；与 Agent 的刺激接口（CallStarted/CallTurnCompleted/CallSilenceElapsed/CallEnding）。

验证：stage 集成测试按 spec AC-19 清单逐条。

### CL-7 RealtimeSpeechSession

1. 协议/工厂（`infrastructure/models/realtime_speech`）。
2. 阿里云实现（16k 上行、事件归一化：speech_started/stopped/turn_completed/turn_invalid/ambient_audio/provider_failed）；供应商生成的回答一律取消丢弃。
3. 内存假适配器；工厂按 `call_id` 创建。

验证：unit（归一化/取消/失败）+ 真实 smoke（独立开关，不做 CI 前提）。

### CL-8 Agent 通话集成

1. 通话刺激与 handler；音频语义拼接（spec 表）。
2. `CallRecallDecisionSkill`：DIRECT/RECALL + ack_style + memory_queries；快速模型；失败降级 RECALL。
3. 开场语、沉默决策（SPEAK/WAIT/END_CALL）、`EndCall` 行动。
4. `Say` 增加 CALL 路由属性（audio_route=CALL、display_in_chat=false、is_ephemeral=true）；禁 Sing/预制长音频/聊天气泡。
5. 通话记忆池：容量 10 近似 LRU + 向量召回编排。

验证：unit/agent：决策、降级、池行为、开场、结束。

### CL-9 TTS 通话路由与取消

1. 请求级取消补全（未完成块不得发送）、200ms 停止窗口。
2. response_id/stream_id/seq 与 CALL 路由字段透传到投递。

验证：unit+integration：取消时序、块丢弃、路由不串道。

### CL-10 账本/结算/历史/隐私/观测

1. `call_sessions` 表 + repository（spec 字段表、启动幂等）；服务启动处理陈旧账本。
2. 概要生成（≤200 字；失败回退）+ 稳定 UUIDv5 通话记录（[语音通话] 渲染）+ 历史投影。
3. 15s 结算期限；清除临时转录与记忆池；账户重置覆盖通话数据。
4. 无内容日志与 AC-18 指标（按 call_id 关联）。

验证：unit+integration：渲染/UUIDv5/幂等、结算、重启、重置、脱敏断言。

### CL-11 App 通话界面与生命周期

1. 菜单入口与平台隐藏；互斥切换流程（switch_prepare→断 chat_ws→call_ws→call.start）。
2. 页面：PREPARING/RINGING（深灰+头像+呼叫音+挂断）、ACTIVE（全屏 Live2D+计时+挂断）、RECONNECTING（覆盖层）。
3. 返回键确认；后台即结束；历史通话记录样式（[语音通话] 05:23 / 已取消 / 未接听）。

验证：jest（状态流转、计时、返回键、样式）+ 真机清单。

### CL-12 App 通话音频链路

1. 16k PCM 采集（依赖 Spike-B 结论）与 3s 上行缓存、上行 seq。
2. 24k CALL 播放处理器：实际消费后才 `playback.completed`、tombstone、stop 处理、重连重放。
3. 通信音频模式/AEC/路由；口型驱动。

验证：jest（完成判定/墓碑/重连）+ 真机 AEC/路由手工。

## 七、风险与注意

1. App 实时音频链路（Spike-B）是全计划最大不确定性；不通过会影响 CL-12 排期。
2. 认知维护迁移触及现有聊天行为——先锁定、后迁移。
3. 二进制帧/入站帧上限是从零新建，call.v1 全部压在这块地基上。
4. 切换链路影响聊天体验：`SWITCH_TO_CALL` 只允许经准备信号的绑定客户端触发；普通断线行为不变（需回归）。
5. 单 worker 只是事实约定——启动闸门不做会悄悄坏。
6. 内存态扩展（重放缓冲、幂等表、租约）在通话规模下的上限与清理策略要显式。
7. 供应商选型与降级口径（Spike-A）；成本与用量观测纳入 AC-18。
8. 隐私约束（临时转录/记忆池只存内存、日志无内容）要测试化，不靠自觉。
9. 桌面端历史字段风险传导：通话记录同样携带结构化字段，配合 VM-8 兼容处理。
10. `call_sessions` 建表与数据库迁移说明同步更新。
