# CLI 端到端测试客户端规格

- 状态：特性分支开发中；验收标准与规格待非作者开发者审核
- 日期：2026-09-19
- 修订：2026-09-25 —— 同步当前代码地图与服务端架构；保留待审核的验收标准。
- 修订：2026-09-26 —— 纳入注册、自动登录、初始历史、输入延迟与动态回复的实测验收场景。
- 目标：提供一个可由 AI 和开发者在终端中稳定驱动的真实客户端，用于 AgentLuo 客户端—服务端端到端调试。
- 规格边界：本文定义外部行为、协议边界、验收方式与当前链路缺口，不包含实现代码。

## Problem Statement

本特性开发前，桌面端已有登录、WebSocket 通信、消息处理、音频缓存、动态和偏好等能力，但这些能力主要绑定在 GUI 交互流程中。AI 调试服务端时难以稳定地完成“执行一个真实客户端动作—等待服务端响应—阅读结果—判断是否符合预期”的闭环，只能直接拼装协议包、调用零散接口或依赖人工观察界面。

这会产生四类问题：

1. 调试入口绕过当前客户端的鉴权、重连、ACK、图片编码和回复聚合语义，不能证明真实客户端链路可用。
2. 原始 WebSocket 包不等同于用户可理解的回复。文本、音频、表情可能分包到达，只有终止包才能证明一次回复已经结束。
3. 服务端 ACK 只表示输入已被当前进程接纳，不表示 Agent 已回复、音频已生成或业务数据已持久化；现有临时调试脚本容易混淆这些完成条件。
4. 动态、偏好等 HTTP 能力与 WebSocket 对话能力缺少同一个可编排入口，AI 无法在一个会话中连续执行用户动作并保留分页游标、已选图片、回复音频和偏好快照等客户端状态。

此外，触摸、开始选图和取消选图曾被描述为待补齐的协议缺口：客户端已有这三类发送能力，领域层也有相应概念。经对当前源码核查，三类事件已被业务事件集合接纳并完成转换与 ACK；受测部署是否包含该链路须在 e2e 前确认，且直接拼装协议包不能替代真实客户端链路。

## Solution

本特性提供一个无 GUI、可长期保持会话的 CLI 测试客户端。它复用当前客户端的认证、HTTP 和 WebSocket 能力，把每个用户动作翻译为真实客户端请求，把服务端分包聚合为用户和 AI 都能理解的事件与结果，并在动作定义的完成边界上执行断言。当前实现入口见[代码地图](../代码地图.md)；本文的验收标准仍需按实际测试结果逐项审查。

CLI 同时提供两种呈现方式：

- 面向开发者的交互式终端，使用简洁文本展示连接状态、回复文本、音频状态、表情、动态和偏好。
- 面向 AI/自动化的非交互模式，从参数、标准输入或场景文件接收动作，以 JSON Lines 输出事件和最终判定；标准输出只承载机器结果，诊断日志写入标准错误。

一次 CLI 进程持有一个客户端会话。会话包含认证身份、WebSocket 连接、HTTP 客户端、服务端事件收集器、当前图片选择、按回复 UUID 聚合的内容、可重放音频索引、动态分页视图和偏好快照。CLI 不直接调用 Agent、Stage、数据库或其他服务端内部对象。

核心动作如下：

| 动作 | 用户含义 | 成功完成条件 |
| --- | --- | --- |
| 注册 | 使用邀请码创建测试账号 | 有效邀请码与一致的两次密码注册成功；无效邀请码或密码不一致明确失败 |
| 连接 | 登录并建立可用会话 | 登录成功、WebSocket 鉴权成功且进入 ready 状态 |
| 自动连接 | 使用显式保存的登录令牌建立会话 | 无需再次输入密码即可进入 ready；CLI 凭据与 GUI 凭据隔离 |
| 初始历史 | 登录完成后读取聊天记录 | 登录时自动加载一次，结果可由 CLI 读取；再次显式加载仍可用 |
| 打字状态 | 告知服务端输入框当前文本长度 | 获得肯定 ACK，可结合状态事件验证回复时序 |
| 发送文本 | 向天依发送一条文字消息 | 输入获得肯定 ACK；需要回复时，收到同一回复 UUID 的终止包并通过内容断言 |
| 选择图片 | 告知服务端用户开始选图，并在本地选定待发送文件 | 选择开始事件获得肯定 ACK，且本地文件可读、类型与大小可接受 |
| 取消选图 | 放弃当前图片选择 | 取消事件获得肯定 ACK，且本地选择状态被清空 |
| 发送图片 | 发送当前选中或命令指定的图片 | 图片输入获得肯定 ACK；需要回复时，收到完整回复并通过内容断言 |
| 触摸 | 发送一个符合当前客户端语义的触摸信号 | 触摸输入获得肯定 ACK；需要反应时，收到完整的会话回复或临时反应并通过断言 |
| 等待/阅读回复 | 阅读文本、音频和表情 | 指定等待条件满足，或在超时后给出明确失败结果 |
| 重放音频 | 重放一条已完整接收且成功保存的回复音频 | 本地音频存在、可解码且播放任务成功开始并正常结束；该动作不向服务端发送消息 |
| 打开动态 | 进入动态视图 | 获取首屏成功；成功呈现后再标记已读，并保存分页游标 |
| 阅览动态 | 阅读指定动态及其评论 | 已找到指定动态，详情和首批评论获取成功并输出为可读结构 |
| 加载动态 | 加载下一页动态 | 使用当前游标取回下一页并追加到视图；无下一页时返回稳定的结束状态而非错误 |
| 发动态 | 发布一条用户动态 | 创建接口成功，并通过返回项或重新读取确认新动态可见 |
| 打开偏好 | 进入偏好视图 | 从服务端读取偏好并保存为当前快照 |
| 阅读偏好 | 输出当前偏好 | 已有最新快照，或先自动读取服务端再输出 |
| 更新偏好 | 修改用户偏好 | 覆盖接口成功，随后重新读取并确认目标值已生效 |

对交互模式、场景文件和 JSONL 事件统一使用以下稳定动作名，展示层可以为它们提供更自然的命令别名：

| 动作名 | 含义 |
| --- | --- |
| `session.connect` / `session.status` / `session.close` | 建立、检查和关闭客户端会话 |
| `account.register` / `session.auto_connect` | 注册账号、使用 CLI 独立保存的令牌自动登录 |
| `history.initial` / `history.load` | 读取登录时自动加载的历史、显式加载历史 |
| `events.read` / `events.wait` | 读取或等待 Agent 状态、历史加载和回复完成事件 |
| `chat.send_text` | 发送文本，可选择只验 ACK 或继续等待完整回复 |
| `chat.send_typing` | 发送当前输入长度，包含零长度 |
| `image.select` / `image.cancel` / `image.send` | 开始并完成本地图片选择、取消选择、发送图片 |
| `touch.send` | 发送触摸信号 |
| `reply.wait` / `reply.read` | 等待新的完整回复、读取已聚合回复 |
| `audio.replay` | 按回复 UUID 重放本地音频 |
| `dynamics.open` / `dynamics.read` / `dynamics.load` / `dynamics.post` | 打开、阅览、翻页和发布动态 |
| `preferences.open` / `preferences.read` / `preferences.update` | 打开、读取和更新偏好 |
| `scenario.run` | 在同一会话内顺序执行一组动作与断言 |

## User Stories

1. 作为负责 e2e 调试的 AI，我希望用单条命令连接指定服务端并完成鉴权，以便在不启动 GUI 的情况下进入真实客户端会话。
2. 作为负责 e2e 调试的 AI，我希望凭据通过命令参数、环境注入或受控配置提供，并在输出中被遮蔽，以便自动化调试不会泄露密码和 token。
3. 作为开发者，我希望连接结果明确区分登录失败、WebSocket 鉴权失败、服务端未就绪和连接超时，以便快速定位失败层级。
4. 作为开发者，我希望 CLI 保持 WebSocket 心跳、断线状态和重连语义，以便验证长连接行为而不是一次性脚本行为。
5. 作为负责 e2e 调试的 AI，我希望发送文本后获得唯一动作 ID 和客户端消息 ID，以便把后续 ACK、诊断信息和断言结果关联起来。
6. 作为负责 e2e 调试的 AI，我希望把肯定 ACK、否定 ACK、超时和业务回复分别观察，以便不把“已接纳”误判为“已回复”。
7. 作为开发者，我希望可以断言回复文本非空、包含字符串或匹配正则表达式，以便覆盖确定性和非确定性回复场景。
8. 作为开发者，我希望 CLI 按回复 UUID 和包序号聚合文本、音频、表情与终止状态，以便看到与用户体验一致的一条完整回复。
9. 作为负责 e2e 调试的 AI，我希望终端默认只输出音频的存在性、字节数、格式、摘要和本地引用，而不打印 Base64 正文，以便结果可读且不会污染上下文。
10. 作为开发者，我希望可以断言音频存在、可解码、非空或预期缺失，以便区分正常语音、纯文本回复和 TTS 失败。
11. 作为开发者，我希望音频失败终止包仍能结束等待并保留已收到的文本，同时丢弃失败流的部分音频，以便 CLI 与当前客户端语义一致。
12. 作为开发者，我希望可以阅读每次表情变化并断言表情值，以便验证服务端表达输出而不依赖 Live2D 渲染。
13. 作为开发者，我希望临时触摸反应能实时展示但不进入可重放音频和持久聊天回复索引，以便保持当前客户端的临时反应语义。
14. 作为负责 e2e 调试的 AI，我希望发送图片前显式执行选择动作、校验本地文件并显示 MIME 类型和大小，以便在发送前发现路径或格式错误。
15. 作为负责 e2e 调试的 AI，我希望取消选图后不能误发之前选中的文件，以便验证图片选择状态正确清理。
16. 作为开发者，我希望图片实际通过当前客户端的编码和 WebSocket 发送能力进入服务端，以便 e2e 不绕过真实媒体边界。
17. 作为负责 e2e 调试的 AI，我希望以命令指定触摸区域、点击频率和触摸元数据，以便复现桌面端会发送的触摸场景。
18. 作为开发者，我希望 CLI 默认遵守当前客户端在服务端音频活跃期间抑制触摸的规则，并把“本地抑制”报告为可观察结果，以便测试行为与产品客户端一致。
19. 作为负责 e2e 调试的 AI，我希望能单独等待下一条完整回复，设置超时并组合文本、音频、表情断言，以便把发送和验证拆成可编排步骤。
20. 作为负责 e2e 调试的 AI，我希望能按回复 UUID 重放已经成功保存的音频，以便确认客户端侧的音频缓存和回放链路。
21. 作为开发者，我希望重放不存在、未完成、临时或生成失败的音频时得到明确失败原因，以便区分服务端无音频和本地回放问题。
22. 作为用户，我希望打开动态时看到首屏内容，并在首屏成功呈现后清除未读状态，以便 CLI 行为接近现有客户端。
23. 作为负责 e2e 调试的 AI，我希望动态项目以稳定字段输出，并保留原始未知字段，以便既可阅读又不会丢失调试证据。
24. 作为负责 e2e 调试的 AI，我希望按动态 ID 阅读正文和评论，以便检查详情链路和可见性规则。
25. 作为负责 e2e 调试的 AI，我希望使用服务端返回的游标加载下一页，并在到底时得到成功的 `end_of_feed` 状态，以便稳定循环分页。
26. 作为负责 e2e 调试的 AI，我希望发布动态后确认新内容可见，以便创建接口返回成功但读取链路失败时能够被发现。
27. 作为用户，我希望打开偏好时读取服务端最新值，以便后续阅读和修改基于真实状态。
28. 作为负责 e2e 调试的 AI，我希望偏好以完整 JSON 对象输出，以便读取当前客户端 UI 尚未展示的扩展字段。
29. 作为用户，我希望默认按字段合并更新偏好而不是意外删除未提及字段，以便自动化调试更安全。
30. 作为开发者，我希望仍可显式请求完整覆盖偏好，以便验证服务端现有 overwrite 语义。
31. 作为负责 e2e 调试的 AI，我希望偏好更新后自动重新读取并断言目标字段，以便数据库写入、缓存刷新和读取链路一起得到验证。
32. 作为负责 e2e 调试的 AI，我希望把多个动作写入场景文件并在同一会话顺序执行，以便重现一条完整用户旅程。
33. 作为负责 e2e 调试的 AI，我希望每个动作都有稳定退出状态、错误码、耗时和结构化证据，以便无需解析自然语言日志即可判断结果。
34. 作为开发者，我希望场景失败时默认停止后续有副作用的动作，同时可显式选择继续收集诊断，以便避免失败后继续修改数据。
35. 作为开发者，我希望可以保存经脱敏的场景报告，并选择是否保留图片、音频和响应原文，以便在可复核性和隐私之间做明确选择。
36. 作为维护者，我希望 CLI 只依赖客户端公开能力和外部协议，不导入服务端内部对象，以便它持续代表一个真实的远端客户端。

## Implementation Decisions

- CLI 作为当前 Python 客户端的无 GUI 入口实现，复用认证、HTTP、WebSocket 传输、事件规范化和媒体处理能力。若现有能力与 GUI 生命周期耦合，应先抽成无 GUI 的窄客户端接口，再由 GUI 和 CLI 共同调用；不得在 CLI 中复制第二套协议实现。
- 唯一主要测试缝是“客户端动作”。动作接收用户意图，经过真实客户端传输访问公开 HTTP/WebSocket 端点，最终产生结构化结果。协议收发、回复聚合、分页状态和读后验证都隐藏在该缝之后。
- CLI 支持交互式会话和非交互式场景，两者使用同一动作执行器。交互模式只改变输入和展示，不形成第二套业务路径。
- 非交互模式采用 JSON Lines 作为标准机器输出。每条记录至少包含 schema 版本、时间、会话 ID、动作 ID、事件类别、状态、耗时、关联 ID、数据摘要和稳定错误对象。人类日志写入标准错误，不能破坏标准输出的可解析性。
- 每个动作最终只能是 `passed`、`failed`、`timed_out`、`skipped` 或 `suppressed`。进程退出码至少稳定区分全部通过、断言失败、输入/配置错误、认证/传输错误和超时。
- 凭据不得出现在命令回显、JSONL、异常堆栈或报告中。默认不把凭据写入客户端现有的自动登录存储；需要持久化时必须显式请求。
- `session.connect` 仅在 `remember_login=true` 时保存 CLI 专用加密令牌；`session.auto_connect` 使用该令牌，不能修改 GUI 的自动登录状态。
- 连接进入 ready 后自动读取一次最近聊天历史；`history.initial` 展示该次结果，`history.load` 供后续显式翻页或复核。
- `events.read` 与 `events.wait` 暴露状态转换和已完成回复；回复没有输入消息的稳定因果 ID，时序场景必须同时保存输入 ACK、事件时间与回复内容证据。
- WebSocket 会话必须完成 system ready、鉴权和 ready 三阶段后才允许业务动作。连接维护继续使用当前心跳和重连机制，明确鉴权失败后不得用同一凭据无限重连。
- 所有会触发服务端处理的动作都生成客户端消息 ID。ACK 通过 `reply_to` 与该 ID 关联；肯定 ACK 只满足“已接纳”断言，不能自动满足“收到 Agent 回复”断言。
- 在当前服务端输出没有稳定携带原始客户端消息 ID 的前提下，CLI 默认一次只允许一个“期待 Agent 回复”的动作处于等待状态。它以动作开始后的下一条新回复 UUID 为候选，并等待该 UUID 的终止包。并发调试模式可以观察原始事件，但不得声称回复已与输入确定关联。
- 回复聚合以回复 UUID 为主键、包序号为顺序依据。重复包不得重复追加；序号缺失时保留到达顺序并在结果中标记证据较弱；一个 UUID 只有收到 `is_final_package=true` 后才算完整。
- 文本、表情和音频分别保留，不以其中任一字段替代其他字段。文本以用户可读形式输出；表情按到达顺序输出；音频 Base64 解码后聚合，默认只输出元数据。
- `audio_error=true` 或音频错误终止码结束等待，但判定为音频失败。已收到的文本仍可通过文本断言，失败流的部分音频不得进入可重放索引。
- `display_in_chat=false` 或 `is_ephemeral=true` 的临时反应仍可被实时观察和断言，但不作为持久聊天内容，也不进入重放索引。
- 重放音频是纯客户端动作，只能引用已完整结束、无音频错误、非临时且成功保存的回复 UUID。重放结果应区分文件不存在、格式不可读、播放设备不可用、播放被中断和正常结束。
- 图片选择是有状态动作：开始选择先发送选择开始信号，再校验并记录本地图片；取消动作发送取消信号并清空记录；发送动作读取当前选择或显式路径，经当前客户端媒体编码后发送。CLI 不把本地绝对路径发送到报告，除非用户显式开启诊断。
- 图片允许的类型和大小必须来自当前客户端/服务端媒体规则，不能在 CLI 中维护独立常量。图片发送失败时不得自动改用新的客户端消息 ID 重发同一业务输入。
- 触摸动作使用当前客户端支持的区域、点击频率和元数据形状。服务端音频活跃时，默认按当前产品客户端语义抑制触摸并返回 `suppressed`，不伪造 ACK 或回复。
- 要使触摸与图片选择动作满足真实 e2e，生产 WebSocket 的业务事件集合、Adapter 输入转换和 ACK 行为必须接纳 `user_touch`、`user_image_selecting`、`user_image_selecting_cancel`，并转换为现有强类型领域刺激。网络层负责鉴权、去重和 ACK；Stage/Agent 负责业务反应。不得为 CLI 建立专用服务端后门。
- 图片选择开始/取消属于瞬时状态信号，成功标准是肯定 ACK，不要求 Agent 消息。文本和图片默认可配置为“只验 ACK”或“验 ACK 后等待完整回复”。触摸默认验 ACK，并可选择是否要求临时反应或会话回复。
- 动态视图保存当前项目、下一页游标和是否还有更多。打开动态先获取首屏，只有首屏成功呈现后才调用标记已读；标记已读失败必须单独报告，不能抹掉首屏读取成功的证据。
- 阅览动态按动态 ID 输出帖子并获取首批评论。加载动态只能使用服务端返回的游标，追加时按稳定 ID 去重；`has_more=false` 是成功结束状态。
- 发布动态是有副作用动作，必须输出待发布内容摘要并要求显式动作。成功后使用返回项或重新读取确认内容可见；重复运行场景不会自动发布第二次，除非场景明确允许非幂等重放。
- 偏好打开动作从服务端读取完整对象并保存版本内快照。阅读动作只读取当前快照，但允许在没有快照时自动执行打开。
- 偏好更新默认执行“读取最新对象—按键合并—调用现有覆盖接口—重新读取—比较目标键”。完整覆盖只能通过显式 replace 模式执行。更新失败后保留更新前快照和差异摘要，但报告不得默认保存完整个人信息。
- 断言属于动作结果的一部分。首版至少支持 ACK 成功/失败、完整回复、文本非空/包含/正则、音频存在/缺失/可解码、表情相等/集合包含、JSON 路径存在/相等、列表数量、动态可见、偏好键值相等及超时。
- 超时分层配置：连接、ACK、完整回复、HTTP、音频播放分别有独立默认值和命令级覆盖。超时结果必须指出等待的阶段和已收到的证据。
- 场景默认串行执行。动作失败后停止后续有副作用动作；只读诊断动作是否继续由场景策略决定。报告按动作保留开始、关键事件、最终判定和耗时。
- 默认报告只保存脱敏结构化元数据。保存回复全文、动态/偏好内容、图片副本或音频文件必须由调用方显式开启，并明确输出目录和清理策略。
- CLI 不负责启动、停止、重置或修改服务端运行时；测试账号可通过公开注册接口与有效邀请码创建。CLI 不直接读取数据库，也不通过内部接口注入确定性回复。

### 本轮产品验收场景

| 范围 | 验收行为 |
| --- | --- |
| 账号 | 有效邀请码注册成功；无效邀请码与两次密码不一致失败；正确手动登录成功、错误账号或密码失败；选择自动登录后再次登录无需密码。 |
| 初次登录与历史 | 首次登录收到两句欢迎语：“你好呀，我是洛天依”“欢迎来到这里，今天想聊些什么”；每次登录自动加载一次聊天历史。 |
| 文本与图片 | 两类输入分别收到成功 ACK；完整回复含文本、表情、音频；普通回复音频落本地；登出再登录后可从历史看到输入和回复。 |
| 回复状态 | 文本或图片输入且无后续输入时约 1 秒进入 `thinking`，开始回复后回到 `waiting`；正长度打字延迟约 10 秒、零长度打字立即触发、后发文本或图片重置为约 1 秒、选图延迟约 30 秒、取消选图后约 1 秒。计时应同时报告图片预处理及调度耗时，不能只用 ACK 推断状态。 |
| 触摸 | 非回复期触摸产生无文字、有表情和音频的临时反应；音频不保存。 |
| 偏好 | 打开后拿到当前聊天偏好；更新后重新打开可读到新值；聊天回复能体现设置的两人关系。 |
| 动态 | 首屏包含洛天依和当前用户的动态，排除其他用户；发布后重新打开可见；洛天依在五分钟内回复该动态。 |

## Testing Decisions

- 好测试只断言 CLI 对外承诺的动作、事件、退出码和公开协议结果，不断言私有队列、线程、类名、日志文案或内部调用次数。
- 主要验收缝是完整 CLI 进程：给定配置和动作输入，观察 JSONL、退出码、公开服务端副作用和明确选择保留的媒体产物。
- 客户端模块测试覆盖动作解析、状态机、回复分包聚合、重复包处理、终止包、音频失败、脱敏、断言和稳定错误分类。外部服务使用轻量 fake，不复制服务端业务。
- 客户端集成测试以可控 HTTP/WebSocket 测试端点连接认证、ACK、断线、重连、分页和读后校验。优先复用现有 ACK 与 TTS 终止事件测试的协议样例。
- 服务端集成测试补齐触摸和图片选择事件的认证、去重、ACK、强类型刺激转换与拒绝行为，并证明网络层不解释业务反应。
- 离线 e2e 只保留少量核心用户旅程：文本到完整回复；图片选择到图片回复；触摸到临时反应；动态打开/分页/发布；偏好读取/合并更新/读后确认。它们从 CLI 或真实公开入口贯穿完整装配，不重复模块测试的边界组合。
- 真实 LLM、VLM、TTS、音频设备、远程服务和生产凭据属于 external e2e，默认跳过并显式启用。此类测试可使用“非空、格式合法、在时限内结束”等稳健断言，不断言模型的固定自然语言句子。
- 测试必须覆盖 ACK 成功但业务回复超时、否定 ACK、ACK 超时、回复有文本无音频、音频失败终止、表情分包、重复包、缺失序号、连接中断、没有下一页、发布后不可见、偏好写入成功但读回不一致等失败路径。
- 测试必须证明标准输出始终是合法 JSONL，日志与堆栈不会混入；同时证明密码、message token、Authorization 值和音频 Base64 不会出现在默认输出或报告中。
- 测试必须证明同一场景默认不并发等待两条无法关联的 Agent 回复；启用并发观察时，结果明确标记为未确定关联。
- 验收不以测试数量或覆盖率替代行为证据。每项核心动作至少有一个成功路径和一个最重要失败路径，并记录它经过的真实外部边界。

### 最低验收矩阵

| 能力 | 必须证明的外部行为 |
| --- | --- |
| 连接 | 正确凭据进入 ready；错误凭据稳定失败且不泄露凭据 |
| 文本 | 肯定 ACK 与完整回复分别可观察；文本断言可判定 |
| 图片 | 选择、取消、发送三种状态可观察；真实媒体进入服务端；完整回复可判定 |
| 触摸 | 非播放期可接纳并观察反应；播放期按客户端规则抑制 |
| 回复 | 文本、表情、音频、终止包正确聚合；TTS 失败不会留下可重放音频 |
| 重放 | 合法回复可重放；非法、临时或失败音频被明确拒绝 |
| 动态 | 首屏、详情/评论、下一页、到底、发布与可见性确认均可判定 |
| 偏好 | 读取、合并更新、完整覆盖和读后确认均可判定 |
| 自动化 | 场景可串行执行，JSONL 可解析，退出码稳定，敏感信息被遮蔽 |

## Out of Scope

- 不实现新的 GUI、TUI、Live2D 渲染或移动端界面。
- 不通过截图、像素或 GUI 控件状态判断 e2e 成功。
- 不在 CLI 中实现新的 Agent、Stage、记忆、动态或偏好业务规则。
- 不绕过公开 HTTP/WebSocket 协议直接访问数据库或服务端内部 Python 对象。
- 不把服务端 ACK 当作 Agent 回复、持久化完成或音频播放完成证明。
- 不保证自然语言回复逐字确定；真实模型场景使用结构、存在性和宽松语义断言。
- 不在首版支持动态评论发布、历史记录删除或编辑、电话、唱歌、客户端 LLM/VLM 配置、重置账号或管理后台功能。
- 不自动创建、清理或恢复真实用户数据；涉及发布动态和更新偏好的场景必须使用明确的测试账号与外部清理策略。
- 不把触摸和图片选择的协议不一致隐藏在 CLI mock 中；部署或受测服务未接纳时，按测试类型明确 failed 或 skipped，并报告版本/能力差异。
- 不在本规格中规定具体源码文件路径、内部类组织或第三方 CLI 框架。

## Further Notes

### 术语

- **动作**：用户或场景要求 CLI 执行的一项客户端行为。
- **接纳结果**：服务端通过 ACK 表示是否接收某个 WebSocket 输入。
- **业务回复**：由一个回复 UUID 标识、由若干 `agent_message` 包组成并以终止包结束的 Agent 输出。
- **临时反应**：可实时播放或展示，但不进入聊天展示和可重放索引的输出。
- **客户端视图**：CLI 为动态分页、偏好和图片选择保存的本地会话状态，不是新的服务端数据模型。
- **读后校验**：写操作成功后通过公开读取接口确认可观察结果，而不是读取数据库。

### 当前实现事实与完成前置

- 当前 WebSocket 使用用户名与 message token 鉴权，支持客户端消息 ID、ACK 和重复输入去重。
- 当前 Agent 回复包含 UUID、文本、Base64 音频、表情、终止标记、音频错误、展示语义和临时语义；协议中的 `packet_sequence` 可选，缺失时仍须按到达顺序处理并保留证据边界。
- 当前客户端已有文本、图片、触摸、图片选择通知、动态、偏好和音频缓存/重放的基础能力，可作为抽取无 GUI 接口的依据。
- 当前源码的链路已存在：触摸与图片选择事件已进入业务事件集合、由 [WebSocket Adapter](../../server/src/adapter/websocket/_input.py) 转换为强类型刺激，并支持 ACK；受测部署的能力须在 e2e 前确认。完成本规格仍必须经过真实客户端链路，而不是只完成 CLI 命令表面。
- 当前 Agent 输出没有稳定携带原始客户端消息 ID。首版以串行的“单个待回复动作”保证可判定性；若未来需要并发 e2e，应在公开协议中增加稳定的因果关联字段后再放开确定性并发断言。
