# 通话问题 #334 实施证据

> 下文记录 PR #352 原始实现时的验证；本地合并时的补充修复与最新结果见末尾“合并补充验证”。原始组合测试已扩展为参数化测试。

## 范围与语义

- Issue：#334；目标分支：`feat/call`；实现基线：`653ed507a6afdd41b4d214f001f22723e14bd6e3`
- `call.active.connected_at_ms` 由服务端 `stage_binding.py` 的 `connected.timestamp() * 1000` 产生，语义为 UTC 墙钟 epoch 毫秒，不是客户端单调时钟
- transport 保留该服务端锚点，并在收到 `call.active` 的瞬间以本地墙钟估计已过时长，转换为本地单调锚点；之后时长只使用本地单调时钟计算
- 同一锚点的重复 `call.active` 不重置时长或重复启动采集；恢复握手只恢复状态，不改写锚点。结束和未恢复的三秒断线仍沿用既有冻结策略
- 协议没有 `server_now` 或往返校准字段，因此无法区分单程网络延迟与客户端/服务端墙钟偏差。未来服务端时间戳按零已过时长处理；结构校验仍拒绝缺失、非整数、负数或超出安全整数的字段
