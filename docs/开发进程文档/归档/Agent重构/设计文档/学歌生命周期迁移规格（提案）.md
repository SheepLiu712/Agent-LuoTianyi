# 学歌生命周期迁移规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录切分与接口，不实现。
- 关联工单：Issue [#82](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/82)（23 迁移学歌派发、完成事实及学会后的行为）
- 相关规范：总 SPEC 第 6.7、8.6 节 `learn_sing_songs:{character_id}` 行；现状 `server/src/world/learn_sing_songs/task.py`（`import CharacterRuntime`）

## 1. 要解决的问题

现状：学歌任务在 world 内跑完整流水线，并**直接**记录事件、刷新媒体库、打标签、发布动态；角色「学会了一首歌」的经历没有经过 Agent。目标：机械长任务留 world/capability；只有**验证完成**才形成 `SongLearned`，由 Agent 记录经验并决定表达。

## 2. 归属切分

| 环节 | 归属 | 说明 |
| --- | --- | --- |
| 凭据检查/刷新、wishlist 状态、扫描 pending | world | 机械准入与状态维护 |
| 下载、清理、分段、模型处理、工件校验、重试状态 | world / capability | 外部长任务；中间进度不是 Stimulus |
| 媒体库刷新、情绪标签生成 | world / capability | 技术产出 |
| `already learned` 判定与不重复通知 | world | 业务去重 |
| 验证成功 → `SongLearned` | world 产出，经 WorldStage 投递 | 稳定完成事实 |
| 记录「学会」经验 | Agent 内部 `LearnedSongExperienceCommit`（幂等） | Agent 自有状态 |
| 事件 / 通知 / 动态 | `PublishDynamic`（及既有 event/通知写入） | 外部效果，经 realize |
| 启动学歌任务 | `RequestSongLearning` Action | 跨进程、可恢复，经 realize 派发 |

## 3. 建议契约（目标，未实现）

- `SongLearned` 只在**技术工件验证可用后**产生；任务的中间进度与模型结果留在任务内部 ledger/日志，不投递；
- 任务失败由 execution/task 记录；**失败事实不冒充 `SongLearned`**（未来若需要角色认知，另加强类型 Stimulus）；
- `RequestSongLearning` 的 `dedup_key` 标识同一业务请求；Agent 不等待完整学习流程；
- `SongLearned` 处理：记录经验 → 可选 `PublishDynamic`；不得对 `already learned` 重复通知或发布。

## 4. 影响面与未决问题

- 影响：`learn_sing_songs/task.py` 去掉 `CharacterRuntime`；新增 `handlers/action/song_learning.py`（派发持久任务）；`SongLearned` 刺激 handler；测试。
