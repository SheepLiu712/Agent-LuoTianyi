# 日记迁移规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录切分与接口，不实现。
- 关联工单：Issue [#84](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/84)（25 迁移日记筛选、生成与私密发布）
- 相关规范：总 SPEC 第 8.6 节 `diary:{character_id}` 行；现状 `server/src/world/diary/task.py`（`import CharacterRuntime`）

## 1. 要解决的问题

现状：日记任务直接取得角色能力生成并发布。目标：筛选与每日去重留 world；日记内容由 Agent 决定；发布经 `WriteDiary` Action + realize，保持私密与用户隔离。

## 2. 归属切分

| 环节 | 归属 | 说明 |
| --- | --- | --- |
| 每日 00:00、按角色统计当日每用户对话 | world | 机械统计 |
| 入选条件：当日 ≥50 条且当天尚无已发布日记 | world | 业务阈值 |
| 超过 20 人时随机取 20 | world | 上限与抽样 |
| 每日唯一（同一天只发一篇/人） | world 记录 | 业务去重 |
| 日记内容生成 | Agent（`DiaryPlanningDue` → WorldStage → handle） | 角色认知 |
| 发布 private dynamic | `WriteDiary` Action + realize | 外部效果；保持 source identity 与用户隔离 |
| 逐用户 created/failed 统计 | world 汇总执行结果 | 业务状态 |

## 3. 建议契约（目标，未实现）

- 为每个入选用户产生 `DiaryPlanningDue`（既有类型），经 WorldStage 投递；
- Agent 生成决定 → emit `WriteDiary(owner_user_id, local_date, body)`（`ActionKind.WRITE_DIARY` 已定义、无 handler）；
- 发布为 private、禁止评论的动态（沿用旧语义）；不建立独立日记表；
- LLM 不可用时整轮 skipped（world 决定跳过，不产生刺激）。

## 4. 影响面与未决问题

- 影响：`diary/task.py` 去掉 `CharacterRuntime`；新增 `WriteDiary` action handler；`DiaryPlanningDue` 刺激 handler；测试。
- 未决：
  1. `DiaryPlanningDue` 是「每用户一个刺激」还是「一次投递一批用户」？
  2. 发布失败的用户是否进入下一轮（与「当天仅一篇」去重的关系）？
  3. `source` 身份与既有动态去重键的对应。

## 5. 明确不包含

- 不实现迁移、不新增 Stimulus/Action、不改阈值/上限/调度与私密发布规则。
