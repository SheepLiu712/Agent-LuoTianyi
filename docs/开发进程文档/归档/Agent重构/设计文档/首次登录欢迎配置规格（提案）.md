# 首次登录欢迎配置规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录配置契约与归属，不实现、不改配置。
- 关联工单：Issue [#75](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/75)（16 首次登录欢迎到真实 handler）
- 相关规范：总 SPEC 第 8.5 节；现有实现 `server/src/chat_session/dependency/proactive_topic_maker.py`、`server/src/resources/prepared_speech.py`

## 1. 要解决的问题

首次登录需在约 1 秒后发送并持久化欢迎内容（文字 + 预制音频 + 表情），迁移到新 `handle_stimulus` 链路后，欢迎内容必须由配置驱动。当前旧链的配置位于 `activity_res["first_login"]`：

```jsonc
"first_login": {
  "manifest": "<prepared_speech manifest 路径>",
  "resource_names": ["welcome_1", "welcome_2"],   // 或
  "text": ["..."], "audio_path": ["..."]
}
```

新链路需要明确：**这份内容从哪里读、由谁传给 handler**。由于新增/改变跨模块配置字段属于公开 interface，必须先定 spec。

## 2. 归属原则

- 预制音频仍是**资源**（`PreparedSpeechResources`），由 `SystemRuntime`/`AgentRuntime` 统一装配；handler 不读文件系统。
- 欢迎文案属于**角色内容配置**，不是 Agent 内部硬编码。
- Stage 只负责在登录事实到达后触发处理与投递输出；内容选择与顺序由 Agent 决定（SPEC 8.5）。

## 3. 建议配置契约（目标，未实现）

沿用并固定现有结构，不新建一层配置：

```jsonc
{
  "prepared_speech": { "manifest": "<manifest>" },      // 已有：音频清单
  "proactive": {
    "first_login": { "prepared_names": ["welcome_1", "welcome_2"] }
  }
}
```

- **调用者**：`AgentRuntime` 读取该配置，把 `prepared_names` 注入首次登录 handler；
- **handler 行为**：按序为每个名称交付一个 `Say(prepared_audio_ref=MediaRef(name), delivery=CONVERSATION, expression="normal")` 计划，并用其文案写入 `source=agent` 会话记录；
- **文案来源**：优先取 `PreparedSpeechResources.get(name).text`（manifest 已含 text/expression），避免文案与音频不一致；
- **异常**：名称不在 manifest → 该条失败并记录；不静默跳过。

## 4. 备选方案

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| A. 复用 `prepared_speech` manifest + `proactive.first_login.prepared_names`（倾向） | 文案与音频同源，配置最小 | 需固定 `proactive` 配置段 |
| B. 保留旧 `activity_res["first_login"]` 结构 | 与旧链一致 | 旧结构含 `audio_path` 等本地路径，与新“受控引用”方向不符 |
| C. handler 内硬编码欢迎语 | 无配置 | 违反“内容由配置驱动”，不可接受 |

## 5. 影响面与未决问题

- 影响：`AgentRuntime` 配置读取与 handler 装配；`interface 文档/system` 或配置说明需记录 `proactive.first_login`；测试需构造 manifest。
- 未决：
  1. 是否同意把 `first_login` 文案与音频统一为 `prepared_speech` 名称列表？
  2. 登录「约 1 秒」延迟由 Stage 计时（`wait`）还是 handler？
  3. `RETURN_LOGIN`（久别问候）保持关闭的开关放在哪里？
