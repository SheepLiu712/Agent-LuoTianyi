# 每日规划与活动日程规格（提案，范围待确认，未实现）

- 状态：**范围待确认**（Issue #79 带 `question` 标签）+ **设计提案，待评审**。只记录选项与影响，不实现。
- 关联工单：Issue [#79](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/79)（20 每日规划与通用活动日程范围待确认）
- 相关规范：总 SPEC 第 4.9、6.3、8.6 节；现状 `domain/agent/stimulus.py` 中 `DailyPlanningDue` 与活动类刺激为**拒绝构造的占位类型**（第 419 行起）

## 1. 为什么需要先定范围

- `DailyPlanningDue` 及活动生命周期刺激（`ActivityDue/Started/Observation/Ended` 等）当前是**占位类型**：构造直接抛 `CONTRACT_STIMULUS_UNAVAILABLE`。要落地 20，必须先把它们变成可构造的真实领域类型——**属于公开领域接口扩大**。
- 同时 `CreateSchedule` / `CancelSchedule` 只在 PRD 中出现，`ActionKind` 里当前**只定义了 `START_THINKING/SAY/SING/WRITE_DIARY/PUBLISH_DYNAMIC/REPLY_DYNAMIC/REQUEST_SONG_LEARNING`**，没有日程相关 Action；持久 scheduler 的归属也未定。
- 因此 20 的实现前必须由负责人确认范围（Issue 的 `question` 标签正是为此）。

## 2. 范围选项

| 选项 | 覆盖 | 需要的接口工作 |
| --- | --- | --- |
| A. 仅「每日规划 → CreateSchedule」 | `DailyPlanningDue` → Agent 生成日程 → 持久 scheduler → 到期产生 `ActivityDue` | 新增 `DailyPlanningDue`/`ActivityDue` 真实类型；新增 `CreateSchedule`/`CancelSchedule` Action；scheduler 端口 |
| B. A + 通用活动生命周期 | 追加 `ActivityStarted/Observation/Ended` 与活动迁移 | 更多刺激类型与活动状态归属 |
| C. 本版不做 | 只保留占位类型与 PRD 描述 | 无（20 保持阻塞） |

倾向 **C 或 A**：本版以聊天/触摸/登录/world 机械边界为主；日程与活动体量大、且与 Call/Realtime 等未来场景耦合，建议单独排期。

## 3. 若选 A 的建议契约（目标，未实现）

- 新增真实 `DailyPlanningDue`（规划周期标识、时间、world/角色事实引用）；
- `CreateSchedule(action_id, due_at, future_stimulus, dedup_key)`：经 realize 写入持久 scheduler；`future_stimulus` 必须是**强类型**且由调用方显式选变体与 `source`，scheduler 不得改写；
- scheduler 到期投递 `ActivityDue`（或系统级重评），不直接调用 Agent；
- `ProactivePromptDue` / `InteractionDeadline` 不得直接作为 `future_stimulus` 保存（须由拥有 pending 的 stage 构造）。
