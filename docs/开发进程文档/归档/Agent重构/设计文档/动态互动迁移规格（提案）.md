# 动态互动迁移规格（提案，未实现）

- 状态：**设计提案，待评审**。只记录切分与接口，不实现。
- 关联工单：Issue [#83](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/83)（24 迁移动态回复和记忆，保留业务状态结算）
- 相关规范：总 SPEC 第 8.6 节 `dynamic_interaction` 行；领域词汇 Dynamic Message Thread；现状 `server/src/world/dynamic_interaction/task.py`（`import CharacterRuntime`）

## 1. 要解决的问题

现状：每轮动态任务直接调用角色能力生成回复并写记忆。目标：world 只选择/规范化待处理动态与评论；回复与记忆由 Agent 决定；业务状态（replied/ignored/failed、memory 状态）由执行结果驱动。

## 2. 归属切分

| 环节 | 归属 | 说明 |
| --- | --- | --- |
| 每 600 秒、选取 pending 正文/评论（当前上限 10/20） | world | 机械筛选与批量上限 |
| 规范化动态与其评论为 `DynamicObserved` | world | 保留作者、父子关系、一个显式回复目标（Dynamic Message Thread） |
| 是否回复/忽略及回复内容 | Agent（经 WorldStage → handle） | 角色认知 |
| 发布评论 | `ReplyDynamic` Action + realize | 外部效果 |
| 记忆写入/忽略 | Agent 内部幂等提交 | 与回复 LLM 是否可用解耦 |
| replied/ignored/failed 与 memory 状态 | 由执 receipt 回写（world 记录） | 业务状态结算 |

## 3. 建议契约（目标，未实现）

- `DynamicObserved` 携带结构化 thread（不是拼接字符串），含一个显式 `DynamicReplyTarget`；
- Agent 决定 reply → emit `ReplyDynamic(target, owner_user_id, body)`；决定忽略 → 无计划但报告明确结果；
- 记忆在 Agent 内部提交，**不依赖**回复 LLM 可用性；
- 执行 receipt（成功/失败）回写 world 侧业务状态；失败不冒充成功。

## 4. 影响面与未决问题
