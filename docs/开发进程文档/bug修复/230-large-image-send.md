## 触发条件
发送未压缩原图、等效超过服务端编码上限（≈6MiB 原图）时静默失败（红叉、无原因）。关联 #224（7MB+ 失败）。

## 被违反的不变量
超限图片不得无声失败：要么被处理（压缩），要么得到明确的「图片过大」提示。

## 根因（详见 #230 调查记录）
- 客户端 `quality: 1` 不压缩、无预检（`useChatLogic.ts:280`）；base64 膨胀（≈4/3）→ 超 `max_encoded_bytes`(8MiB)（`_input.py:168-172`）；
- `TOO_LARGE` 被吞成 `BAD_MESSAGE`；客户端仅把气泡标 `failed`。

## 修复点
1. 客户端预检 / 压缩（阈值与质量参数待定）；
2. 超限明确报错「图片过大（上限约 6MB）」——承接 #227 的错误透传机制；
3. 失败时可见提示（不再只有红叉气泡）；
4. 部署侧复核 `ws_max_size` / 反向代理上限。

## 改动范围
app：`useChatLogic.ts`、`network_client.ts`、`ws_transport.ts`、`message_processor.ts`；
server：复用 #227 透传；config 复核。

## 验收标准（拟 · 待人审）
- 超上限：压缩成功发送，或收到明确「过大」提示；
- 未超上限：正常发送；#224 的 7MB+ 场景被测试覆盖。

## 验证计划
- 模拟 3 / 5 / 7MiB 图片发送（单测 + 真机）；
- 部署层上限记录（uvicorn / 反代）。

## 待定与前置
- 产品策略（压缩 vs 拒绝+提示、上限数值）；
- 与 #227 的排期关系；#224 是否随本单一起收口。
