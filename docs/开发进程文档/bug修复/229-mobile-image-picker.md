# #229 · 手机端选图失败的提示、复位与诊断日志

## 范围与背景
部分机型点击选图后选择器不弹出，原代码未捕获原生 Promise rejection，用户看不到失败原因。
受影响机型与原生日志尚缺，不能将权限缺失认定为根因。本次按仓库主确认的范围交付异常处理与诊断能力，原机型无法弹出的根因继续由 #229 跟踪。

## 行为与实现
- 保留系统选图路径，单次启动；不新增媒体权限声明、权限申请、自动重试或插件配置。
- 成功选图后继续交给现有发送流程；用户取消或空结果时发送取消选图通知。
- 选图通知、原生选择器或选图后回调抛异常时，显示中文提示并尝试复位。
- 复位异常单独捕获、提示和记录，不覆盖原始异常，不重复复位。
- 日志接入 addDebugTrace，scope 为 image-selection，出现在现有“发送调试日志”。
- 记录开始、启动选择器、取消、选择成功、交给发送流程和复位完成；失败记录阶段及异常 name/code/message/stack，兼容非 Error rejection。
- 日志沿用当前进程内最近 200 条缓冲，发布模式同样记录；不是跨重启持久日志。
- 复位完成指调用现有取消通知接口完成（入队），不代表服务端已确认收到。

## 验收与验证
- 正常选择只启动一次选择器，资产正确交给发送回调。
- 用户取消与空选择无误报，调用一次复位。
- 各阶段异常无未处理 rejection，中文提示符合失败阶段。
- 原生错误详情进入真实日志缓冲；复位也失败时两次异常均保留。
- 运行相关 Jest、App 全量 Jest、TypeScript、相关文件 ESLint 和 git diff --check。
- 真机复现与具体厂商兼容性问题尚待验证，本次不宣称原机型问题已根治。
