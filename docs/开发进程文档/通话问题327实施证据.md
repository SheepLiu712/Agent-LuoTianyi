## 范围与状态机

- 固定基线：`5d88cbfd527c1b41e60f9ea0cd72e2610370f578`，包含已独立审核通过并提交的 #326
- 只修复播放完成回调早于 enqueue Promise 返回时丢失的问题，不修改播放竞态之外的通话行为
- 物理播放完成仍由 native completion 事件提供；enqueue Promise 只确认音频块已被播放端口接纳，不能代替物理播放完成

Transport 层的 final 状态为：

1. final enqueue 开始前设置 `finalEnqueuePending`
2. 早到 consumption receipt 只设置 `completionPending`，不发送 wire 完成
3. enqueue 成功且 stream generation 未被 stop/close 替换后，设置 `finalAccepted` 并兑现一次 pending completion
4. enqueue 拒绝、stop 或 generation 替换清除 pending completion，不产生虚假 `playback.completed`

Android adapter 层的状态为：

1. 调用 native enqueue 前登记 stream 身份，并仅为 final enqueue 建立 pending reservation
2. 同身份的早到 native generation 暂存；未知身份直接丢弃，不建立无界缓存
3. native enqueue 返回相同 generation 后登记 ledger，再兑现一次 completion
4. 每个 final enqueue 使用唯一 reservation token；成功、失败和 stale Promise 只能清理仍由自己拥有的 record
5. enqueue 拒绝、tombstone、stop、close 或 session generation 替换清除当前 reservation 和早到事件；旧 session
   Promise 的 resolve/reject 不能删除同 key 的新 session reservation、stream 或 ledger 状态
6. ledger 保持 generation 与完成去重权威，重复早/晚回调只通知一次

本地 #326 错误提示音仍由独立 native API 播放，没有 call.v1 stream 身份，不进入此 completion 状态机。

## 中文 PR 草稿

### 标题

`fix(call): 保留早到的物理播放完成回执`

### 说明

修复 native 物理播放完成事件早于 enqueue Promise 返回时被 Android adapter 和 call transport 丢弃的问题。两层现在都会在
enqueue 前建立有界 reservation，暂存匹配身份的早到完成，并且只有 enqueue 成功确认后才提交一次完成；enqueue 拒绝、stop、
close 或 generation/session 替换会取消暂存，不能形成虚假成功。

新增 Expo native fake → AndroidCallAudio → CallTransportSession → call.v1 wire 的正式组合回归，以及各层拒绝、去重与清理测试。
受影响范围 8 suites / 90 tests、TypeScript、ESLint 与 diff check 通过。未验证真实 Android 设备和供应商。
