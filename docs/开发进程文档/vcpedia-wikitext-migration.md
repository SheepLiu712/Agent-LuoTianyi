# VCPedia 采集迁移与提取验证 spec

状态：进行中，关联 [Issue #196](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/196) 与 [PR #195](https://github.com/SheepLiu712/Agent-LuoTianyi/pull/195)。本次修订的 staff 范围、默认开关与验证方案已由项目负责人在实施会话确认；仍需 PR 的非作者审核，不以 AI 自审代替。

本文是本功能唯一 spec。操作见[World 测试说明](../../server/tests/unit/world/README.md)，历史报告与未完成项见[审查记录](../../server/tests/support/vcpedia_review/README.md)；不维护另一套历史条款核验框架。

## 用户故事

- 作为使用者，我希望采集到歌曲的制作信息、简介和可用歌词，而不是因模板或页面排版不同得到空值、重复内容或错误版本。
- 作为运维者，我希望列表与详情请求使用应用身份，失败明确可观测，片段合并和模型调用可以分别关闭。
- 作为维护者，我希望模板槽位、字段别名可以通过受校验的规则资源调整，升级源码或安装包时资源都可加载。
- 作为审查者，我希望在干净检出环境复现内容回归与离线成本比较，并能区分产品行为、模型实验和历史人工记录。

## 验收标准

保留原验收 1–19，20–24 承接提取规则与离线验证范围。条款是目标，不是通过声明；原25–26的一次性提交认证、历史文档核验不再作为功能验收。标准 Ruff 检查与进行中 spec 生命周期仍按开发守则执行。

### 传输

1. **VCP-01 请求身份与形状**：列表或详情抓取输入为模板 URL/页面标题；向站点 `/api.php` 请求 `action=parse&prop=wikitext&redirects=1&format=json`，使用应用自述 UA。不得把客户端伪装为浏览器。此要求不是“浏览器 UA 在所有时点必然失败”的断言。
2. **VCP-02 挑战兜底**：直连命中 403 或非 JSON 挑战页面时，对同一请求尝试 curl，身份与直连一致，不使用 shell；GET 查询与 POST 请求体形状均受测试约束。
3. **VCP-03 失败与空页面**：超时、HTTP/JSON/API 错误、缺字段或非字符串正文不能当作成功的空页面；列表入口抛错，详情入口返回 `None`。合法的空字符串正文保留原语义。
4. **VCP-04 挑战词不是内容过滤器**：有效 JSON 正文包含 Anubis 等词时，不能仅因该词进入兜底；HTTP 403 的优先级保持明确。

### 详情抽取

5. **VCP-05 首框与 staff 归集**：识别首个外层歌曲框后，通用遍历归集 staff，直到第二个外层歌曲框；正文、标题、空行和注释不终止。首框之前、第二框及之后的 staff 不并入。首框非空值优先，staff 仅补缺/空字段，同名字段取先取得的有效值。不限定 staff 为页级兄弟，也不一律排除参数内 staff；无真实有效实例的嵌套构造沿用通用逻辑，不另立歌曲框计数验收。
6. **VCP-06 展示参数**：图片、宽度、样式、颜色等控制项不进入信息框，空的展示项与空角色名不产生业务缺项。
7. **VCP-07 独立抽取与候选顺序**：简介与歌词分别抽取，简介取首个完整的对应章节（包含所属子标题内容），不被总结模型的短摘要替代。歌词选择源码顺序首个候选，不按版本名称择取；保留原文换行、空段、括号与和声，`br` 变为换行，三级标题可以建立歌词节。Ruby 优先可见表层，表层为空才取标注回退，未选中的分支不贡献缺口。
8. **VCP-08 结构变化的效果边界**：对被冻结且有独立内容预期的页面，验证选定候选的歌词、简介事实和关键信息框值，而非只断言非空或字数增加。规则不能抽全时允许记录缺口进入可选补提；不得据此声称“任意陌生结构都已完整恢复”。

### 历史覆盖承诺与本轮效果证据

9. **VCP-09 原24首比较**：原承诺是当日列表前24首的同批新旧比较，无“旧有新无”。历史表格不等于可重跑证据；本轮精选缓存语料不等于该24首。只有补齐对应输入、版本和比较结果后才可标记通过；未补齐时保持“历史观察，原验收待补证据”，不得用26页快照顶替。
10. **VCP-10 两首歌词恢复回归**：对仓库已有“乐鸣东方”“人是猫”源码，当前实现产出非空歌词与长度6–50字的可检索片段，保留代表句检查。这个当前行为测试本身不证明迁移前 HTML 的逐页结果。
11. **VCP-11 刹那芳华历史差异**：原记录64→723是特定时点的人工观察。缺少同一捕获的输入时不能升级为当前自动化结论；保留其未验证状态，不能默默删掉原承诺或从其他页面推定通过。

### 模板规则

12. **VCP-12 加载、校验、冻结**：启动从随包交付的规则资源加载一次；文件/JSON/结构错误带文件与字段位置失败。`templates` 必须为列表，固定种类、描述符字段、别名冲突、非空条件值均校验。规则资源不读取部署配置目录，也不提供部署级覆盖路径；损坏即失败。
13. **VCP-13 数据驱动规则**：同一种既有算法的槽位、名称、字段别名和角色优先级由配置决定；新 `kind` 需要实现支持，不把配置扩展成可执行脚本。链接类 inline 模板通过 `target_params` 与 `text_params` 指定目标和显示文字，Ruby 通过 `base_params` 与 `annotation_params` 指定表层和标注；参数列表均按顺序取值，新增链接/Ruby列表必须非空。`section_aliases` 配置章节关键词，保持简介优先；`song_list_filters.exact/contains` 配置列表排除文案，保留既有大小写和匹配顺序；命名空间、锚点及协议判断仍由代码负责。`song_field_sources.uploader/singers` 配置字段取值顺序，采用第一个非空值，不改变信息框原键或将多字段强行合并。上述分组与字段名固定校验，未知项和错误类型不静默接纳。规则资源是随包交付的程序知识而非部署配置：修改默认规则随代码变更审查进行，不保留 `server/config` 副本。

### 缺口与可选模型

14. **VCP-14 缺口与非空内容**：已抽到部分内容仍可能需要补全，不能仅因非空就清除缺口或禁止补提；页外未知模板和展示参数本身不是业务缺口。已知误报与真实未抽取内容在测试证据中分别标注，不用 `needed=true` 自证模型调用必要。
15. **VCP-15 双开关与模型职责**：`crawler.merge_rendered_fragments` 与 `crawler.use_llm` 缺省均为 `true`；运维显式 `false` 必须被尊重。LLM关闭时，总结/补提模块均不注册、不调用；未配置的模块不注册、不用另一个模块冒名替代。缺项先由开启的片段渲染合并，再由已配置且启用的补提模型最多调用一次，只合并请求项，随后总结最终数据。片段已补齐则不再补提，补提失败仍执行总结。双关只保证无片段POST与模型调用，不禁止正常详情GET。模型服务存在且启用的模块配置无效时，初始化报可定位错误；模型服务缺失时保留可选功能未启用的降级。运行期可选调用失败保留降级。

### 关键词与部署

16. **VCP-16 索引格式**：按空白切分，保留6–50字符的片段，过滤含 `=>` 的片段，结果不得含换行；避免破坏 `keyword=>value` 索引行。上下界不因新的语料采样随意调整。
17. **VCP-17 非目标的关键词改动**：本次不实施降低长度下界、改变切分单位、过滤纯拉丁片段三项建议。早期小样本记录只是这一范围决定的背景，不等于全站或所有英文场景均无收益。
18. **VCP-18 部署与包内资源**：依赖清单包含 `mwparserfromhell`、`zhconv`，按项目约束安装。默认提取模块引用的 DeepSeek provider 必须在同一配置模板定义。wheel含规则文件，并能在无源码配置且不同cwd的隔离环境真实加载、解析最小页面。整个服务仍需要单独的部署资源，不将规则加载成功表述为wheel独立具备全部运行资源。
19. **VCP-19 存量数据边界**：本次不迁移数据库、不重建旧关键词索引。World只投递候选，由Agent接纳写知识。历史3414/3320/99.2%/59733等数字是当时本地数据观察，不是本轮测试分母；本轮不访问生产库时不得称已重新验证全部存量歌曲。

### 提取规则与离线验证

20. **VCP-20 计数清理**：名字以count结尾的模板不能离线展开。简介/散文材料剔除携带计数的整句；信息字段/模板参数仅剔除相关分句并保留其他资料。不为计数联网。共享标记函数返回“是否修改”，调用方继续渲染被标记的节点，不能输出布尔字符串。
21. **VCP-21 字形与保护顺序**：`nowiki` 在结构遍历前保护，无标志LC在最终转换边界保护；正文只转换一次。`material_text` 统一做保护转换、计数剔除、截断；补提答案假定为最终文本，不再重复转换。原文、译文与标注分支必须按选定候选解释，不能把全部HTML歌词容器总长度当首候选完整度。
22. **VCP-22 提示词实验**：默认离线，显式live才调用已配置的补提模型；无缺项不自动调用。实验复用生产材料、回答校验与合并，报告不启用片段POST以及并非完整生产端到端测试。非法JSON/非对象/超长回答或provider失败必须有可检测失败状态；A/B失败不能伪报全成功，输出不得含凭据。
23. **VCP-23 运行成本比较**：同批配对输入，旧侧使用merge-base真实HTML算法，新侧使用生产解析算法；读盘/导入/初始化/网络/LLM不计时。每页预热2轮、正式9轮交替先后，运行3组，保存原测量、各页中位数、配对比、整组比及本次实际样本身份。输入字节比不是网络传输比。样本仅由manifest声明，不设第二份锁文件或固定页数；更换集合后旧报告不代表新实验。`--check`要求3组新侧中位耗时总和均小于旧侧，仅说明本次方向性，不承诺最低裕量或统计显著性；缺输入或解析失败不能算通过。
24. **VCP-24 语料与内容预期**：已有原件的来源、必要hash、已知revision、权利信息及使用列表只维护在manifest，不同版本不按标题混配，未知身份不伪造。选材时的官方活跃页记录仅为背景信息，不是测试前置条件；操作数不是编辑数，最后编辑者不是结构作者。独立oracle不由当前解析器生成。内容报告保留已知缺口，`--check`仅在当前解析器满足本次声明范围全部独立预期时返回0；普通测试验证已实现内容及评分正确/错误行为，不要求旧错或新错永久不变。

## 模块与接口

| 模块 | 职责与边界 |
| --- | --- |
| `wiki_api.py` | 请求形状、身份、挑战兜底、解码和失败语义 |
| `wikitext_parser.py` | 源码顺序遍历，信息框/简介/歌词独立产出，首框归属与缺口 |
| `template_rules.py` | 规则位置、形状校验、冻结与查询 |
| `text_conversion.py` | 每次抽取的文本保护和一次转换 |
| `source_extraction.py` | 材料构造、片段渲染合并、补提回答校验与请求字段合并，不调用模型 |
| `vcpedia_fetcher.py` | 缓存读取、详情编排、独立补提与总结调用；关闭/失败语义 |
| `daily_new_song_fetcher.py` | 列表、候选规范化与关键词过滤，不写知识 |
| `task.py` | 框架初始化入口、必要依赖持有、世界事实投递 |
| `tests/support/vcpedia_samples.py` | 最小fixture读取与输入hash检查，由内容和性能比较复用；不是CLI |
| `vcpedia_prompt_lab.py` / `vcpedia_perf_baseline.py` / `oracle_support.py` | 提示词实验、离线性能及独立内容报告，不作为后台任务运行 |

稳定业务入口：
- `parse_details(source, title, *, with_missing=False)` 返回结果，启用缺口输出时返回 `(结果, needed)`。
- `needed` 为 `infobox`键列表及 `summary`、`lyrics`布尔标志；非空字段可以仍被请求补全。
- `VCPediaFetcher(config, llm_module=None, *, extraction_llm_module=None)` 的详情入口签名不变；关闭返回空字符串，失败返回`None`，缓存命中直接返回。
- `collect_materials(data, needed, source, base_url, title, *, post=None, merge_fragments=True)` 不接受无用途的`get`参数。
- `decode_extraction_response(response)` 校验纯JSON对象；字符串按原始字符数、dict按JSON序列化字符数限制24000，拒绝NaN/Infinity等非JSON数值，不增加Markdown fences宽容。实验与生产复用这一入口。
- `VCPediaNewSongTask.initialize(runtime)`保留框架入口，之后只持有必要窄依赖；不扩展为其他World任务的重构。

## 验证与不保证的范围

运行受影响的单元/集成、资源加载与工具测试；内容报告和受控性能运行单列结果，不把已知缺口刷绿。真实模型、站点活跃页、自动选材或历史文档断言不是普通离线测试依赖。Ruff锁定0.14.10，按项目规则显式检查PR变更Python文件，不设自制提交认证。

不保证全站任意页面解析等价、所有模型输出质量、实时网络速度、并发生产行为或重建旧索引正确性。不解析远程Lua/全量远程模板，不恢复缓存写回、SQL upsert或批次补偿。旧24首与刹那芳华历史承诺在材料未补齐时仍待验，不用其他语料掩盖。
