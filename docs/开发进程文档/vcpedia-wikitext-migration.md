# VCPedia 新歌采集改用站点 API 与 wikitext

本文是本次交付的功能 spec，覆盖两件事：把抓取来源从渲染后的 HTML 换成站点 API 的 wikitext，
并修复随之暴露的歌词抽取缺陷。验收基线见[歌词关键词可用性基线](vcpedia-keyword-baseline.md)。

## 用户故事

- 作为运维者，我希望新歌知识同步任务在站点启用反爬校验后仍能稳定取到列表与详情，以便每日新增歌曲不需要人工补录。
- 作为角色使用者，我希望天依"学会"的歌包含**页面上的完整歌词**——尤其是那些原实现取不到或只取到零头的页面，以便她能被正确检索到、也能聊起这些歌。
- 作为维护者，我希望模板取文槽与角色映射放在配置文件里，站点模板改名时只改配置、不改 Python。
- 作为部署者，我希望知道升级前要补装哪些依赖、以及本次改变了哪些对外行为。

## 验收标准

### 传输

1. **状态**：任务抓取列表或详情；**输入**：模板页 URL 或页面标题；**输出**：向 `/api.php` 发起 `action=parse&prop=wikitext&redirects=1&format=json` 请求，`User-Agent` 为应用自述身份；**不得**冒充浏览器。
2. **状态**：站点返回反爬挑战（403 或挑战页特征）；**输入**：同一请求；**输出**：curl 兜底，携带与请求头相同的 `--user-agent`，不使用 shell。
3. **状态**：直连与兜底都失败（超时、空响应、非 JSON、API 错误、缺字段、类型不符）；**输入**：上述失败响应；**输出**：列表入口抛错、详情入口返回 `None`；**不得**把失败当作"页面为空"的成功。
4. **状态**：响应是合法 JSON 且正文含 `Anubis` 等字样；**输入**：该类响应；**输出**：按正常响应处理，不进入兜底。

### 详情抽取

5. **状态**：页面存在歌曲框；**输入**：首个歌曲框及其相邻 staff；**输出**：信息框取首个歌曲框的开放业务字段与相邻 staff 的角色字段；首个歌曲框**之前**的 staff 不并入；后框不覆盖首个框；参数值里嵌套的同名模板不算新的歌曲框。
6. **状态**：歌曲框混有展示控制项；**输入**：`图片`/`宽度`/`style`/`颜色` 等键；**输出**：不进入信息框，且不因空值加入缺口。
7. **状态**：页面存在简介与歌词；**输入**：首个完整简介章节（含同级子标题段落）、歌词章节或歌词槽；**输出**：两者独立抽取；歌词保留原文行与括号；`br` 转为换行；三级标题下的歌词可识别；多候选时取源码顺序首个。
8. **状态**：页面使用原实现处理不了的歌词结构；**输入**：该类页面（如歌词位于 `poem` 或非首个 `p` 的容器）；**输出**：取到**完整歌词**而不是零头，或至少取到非空歌词。

### 覆盖率（本次的主要产品收益）

9. **状态**：同一批页面分别用迁移前实现与本次实现抽取；**输入**：当日列表前 24 首；**输出**：本次实现取到歌词的页面数**不少于**迁移前，且不得出现"迁移前有、本次没有"的页面。
10. **状态**：迁移前 `lyrics` 为空的页面；**输入**：`乐鸣东方`、`人是猫`；**输出**：本次取到非空歌词，并产出可检索关键词；该行为由回归用例锁定。
11. **状态**：迁移前只取到零头的页面；**输入**：`刹那芳华`；**输出**：歌词字符数显著增加（实测 64 → 723）。

### 模板规则配置

12. **状态**：服务启动；**输入**：`server/config/vcpedia_templates.json`；**输出**：按源码 resolved 路径加载一次并冻结；形状错误带字段位置直接失败，不回退内置规则。
13. **状态**：需要调整取文槽或字段别名；**输入**：修改规则文件中的 `text_params`、`field_aliases`、`role_priority` 等；**输出**：无需改 Python 即生效。

### 缺口与可选补提

14. **状态**：页面确认缺简介或歌词；**输入**：一次抓取结果；**输出**：记录该字段缺口，不因别处候选非空而被清除；页外未知模板与展示参数本身不构成缺口。
15. **状态**：确有缺项且配置了补提模块；**输入**：`crawler.extraction_llm_module`；**输出**：先合并可渲染片段再调用一次补提，只合并请求的缺项，随后用合并结果生成摘要；补提失败仍执行摘要。**未配置时不注册、不调用。**

### 关键词

16. **状态**：歌词进入关键词索引；**输入**：已抽出的歌词；**输出**：按空白切分并保留 6–50 字的片段，产出形如 `{片段}=>{片段}是《歌名》的歌词` 的行；关键词**不得**含 `=>` 或换行。
17. **状态**：评估"降低长度下界""改变切分单位""过滤纯拉丁片段"等候选改动；**输入**：真实页面数据；**输出**：均已被数据否决或无收益，**本次不实施**（依据见基线文档"三项被数据否决的改动"）。

### 部署

18. **状态**：存量环境升级；**输入**：未安装新依赖的环境；**输出**：依赖清单列出 `mwparserfromhell`、`zhconv`，部署说明指出缺包会导致整个 `src.world` 无法导入。
19. **状态**：存量知识库；**输入**：已入库的 3320 首歌；**输出**：检索行为不变——关键词在入库时已固化进 `song_lyric_keywords.txt`，库里 `lyrics` 不参与派生。

## 模块与架构

| 文件 | 职责 |
| --- | --- |
| `wiki_api.py`（新增） | API 传输：URL 与参数构造、传输身份、挑战识别、curl 兜底、响应解码与失败语义 |
| `wikitext_parser.py`（重写） | 按源码顺序遍历：信息框、简介、歌词三个独立结果，缺口与计数标记 |
| `template_rules.py`（新增） | 规则资源的加载、归一、校验与冻结 |
| `text_conversion.py`（新增） | `nowiki` 与无标志 LC 的字形保护，字段最终一次转换 |
| `source_extraction.py`（新增） | 模型材料构造与缺口合并；不调用模型 |
| `vcpedia_fetcher.py` | 详情入口；摘要与可选补提的调用时机 |
| `daily_new_song_fetcher.py` | 列表入口与候选规范化；关键词派生 |
| `task.py` | 注册可选补提模块并向下传递 |
| `config/vcpedia_templates.json`、`res/agent/prompts/song_knowledge_extraction_prompt.json`（新增） | 规则资源与补提提示词 |

不涉及 `src/domain/agent` 与 `src/infrastructure/persistence`：world 仍只投递候选，落库由 Agent 侧接纳。

### 接口规范

- `VCPediaFetcher(config, llm_module=None, *, extraction_llm_module=None).fetch_entity_description(entity_name, short_summary=True, *, source_title=None)`：签名与返回字段不变；关闭返回 `""`，失败返回 `None`，命中缓存直接返回。
- `parse_details(source, title, *, with_missing=False)`：返回结果字典；`with_missing=True` 时返回 `(结果, 缺口)`。
- `fetch_wikitext(base_url, title, get, timeout)`：成功返回源码，失败抛异常。
- `collect_new_song_candidates(config, llm_module=None, *, extraction_llm_module=None)`：返回 `discovered`/`skipped_existing`/`fetch_failed` 不变。
- `_split_spaced_lyrics(spaced_lyrics)`：返回进入索引的片段（6–50 字、不含 `=>` 或换行）。

## 备注

### 关键技术选型

- 结构遍历使用 `mwparserfromhell`；字形转换使用 `zhconv`（结构比较 `zh-hans`，正文 `zh-cn`）。
- 嵌入片段需要站点渲染结果，`source_extraction` 因此使用 `beautifulsoup4` 解析该 HTML 片段；抓取路径仍只取 wikitext。
- 渲染片段通过 POST 提交源码，长源码放请求体而非 URL。

### 非目标

- 不解析远程模板或 Lua 展开，不支持高级 LC（R/A/H）语法。
- 不做语义判卷、版本标签或多版本汇总；不恢复已退役的缓存写回、批次期限、SQL upsert 与关键词补偿。
- 不改变世界任务的落库与事实投递边界。
- 不实施已被数据否决的关键词改动（见验收标准 17）。
- 不承诺全站解析等价；验收以第 9–11 条的覆盖率对照与固化用例为准。
