# VCPedia 采集迁移与提取验证 spec

状态：进行中，关联 [Issue #196](https://github.com/SheepLiu712/Agent-LuoTianyi/issues/196) 与 [PR #195](https://github.com/SheepLiu712/Agent-LuoTianyi/pull/195)。staff 范围、默认开关与验证方案沿用此前项目负责人确认；本次歌词验收口径来自维护者于 **2026-10-07 的最新评论**（[确认内容](https://github.com/SheepLiu712/Agent-LuoTianyi/pull/195#issuecomment-6029627171)）。下文同步新验收及本轮接口、预算、缓存与失败处理方案，不表示整个 PR 的验收已全部通过；**完整 spec 仍待非作者开发者审核**，不以 AI 自审代替。

本文是本功能唯一 spec。操作见[World 测试说明](../../server/tests/unit/world/README.md)，历史报告与未完成项见[审查记录](../../server/tests/support/vcpedia_review/README.md)；不维护另一套历史条款核验框架。

## 用户故事

- 作为使用者，我希望采集到歌曲的制作信息、简介和可用歌词，而不是因模板或页面排版不同得到空值、重复内容或错误版本。
- 作为运维者，我希望列表与详情请求使用应用身份，失败明确可观测，片段合并和模型调用可以分别关闭。
- 作为维护者，我希望模板槽位、字段别名可以通过受校验的规则资源调整，升级源码或安装包时资源都可加载。
- 作为审查者，我希望在干净检出环境复现内容回归与离线成本比较，并能区分产品行为、模型实验和历史人工记录。

## 验收标准

保留原验收 1–19，20–24 承接提取规则与离线验证范围。条款是目标，不是通过声明；原25–26的一次性提交认证、历史文档核验不再作为功能验收。标准 Ruff 检查与进行中 spec 生命周期仍按开发守则执行。

### 传输

1. **VCP-01 请求身份与形状**：列表或详情抓取输入为模板 URL/页面标题；向站点 `/api.php` 请求 `action=parse&prop=wikitext&redirects=1&format=json`，使用应用自述 UA。不得把客户端伪装为浏览器。此要求不是“浏览器 UA 在所有时点必然失败”的断言。
2. **VCP-02 挑战兜底**：直连命中 403 或非 JSON 挑战页面时，对同一请求尝试 curl，身份与直连一致，不使用 shell；GET 查询与 POST 请求体形状均受测试约束。
3. **VCP-03 失败与空页面**：超时、HTTP/JSON/API 错误、缺字段或非字符串正文不能当作成功的空页面；列表入口抛错，详情入口返回 `None`。合法的空字符串正文保留原语义。
4. **VCP-04 挑战词不是内容过滤器**：有效 JSON 正文包含 Anubis 等词时，不能仅因该词进入兜底；HTTP 403 的优先级保持明确。

### 详情抽取

5. **VCP-05 首框与 staff 归集**：识别首个外层歌曲框后，通用遍历归集 staff，直到第二个外层歌曲框；正文、标题、空行和注释不终止。首框之前、第二框及之后的 staff 不并入。首框非空值优先，staff 仅补缺/空字段，同名字段取先取得的有效值。不限定 staff 为页级兄弟，也不一律排除参数内 staff；无真实有效实例的嵌套构造沿用通用逻辑，不另立歌曲框计数验收。
6. **VCP-06 展示参数**：图片、宽度、样式、颜色等控制项不进入信息框，空的展示项与空角色名不产生业务缺项。
7. **VCP-07 独立候选与分阶段选择**：简介与歌词分别抽取，简介取首个完整的对应章节（包含所属子标题内容），不被总结模型的短摘要替代。每个歌词候选的内容、缺口、渲染结果与模型材料独立，不共享歌词缺口，不跨版本、原文与译文拼接。先完成全部候选的规则抽取；有完整候选时，选择源码顺序最早的完整版本，不再为歌词渲染或补提，而非无条件取首个候选。没有规则完整候选时，若片段开关开启，全部候选各自完成可支持的缺口渲染后，再选择源码顺序最早的完整版本。仍无完整候选（含片段关闭或失败）时，按候选自身现有内容覆盖比例较高、剩余缺口较少的简单顺序排序，相同时取源码最早者，仅选一个候选供最多一次补提；不按绝对字数或版本名称排序，不先把第一版一路送到 LLM 再看后版。保留选定版换行、空段、括号、重复副歌与和声，不去重；`br` 变为换行，三级标题可以建立歌词节。Ruby 优先可见表层，表层为空才取标注回退，未选中的分支不贡献缺口。
8. **VCP-08 结构变化的效果边界**：对被冻结且有独立内容预期的页面，验证选定候选的歌词、简介事实和关键信息框值，而非只断言非空或字数增加。规则不能抽全时允许记录缺口进入可选补提；不得据此声称“任意陌生结构都已完整恢复”。

### 历史覆盖承诺与本轮效果证据

9. **VCP-09 原24首比较**：原承诺是当日列表前24首的同批新旧比较，无“旧有新无”。历史表格不等于可重跑证据；本轮精选缓存语料不等于该24首。只有补齐对应输入、版本和比较结果后才可标记通过；未补齐时保持“历史观察，原验收待补证据”，不得用26页快照顶替。
10. **VCP-10 两首歌词恢复回归**：对仓库已有“乐鸣东方”“人是猫”源码，当前实现产出非空歌词与长度6–50字的可检索片段，保留代表句检查。这个当前行为测试本身不证明迁移前 HTML 的逐页结果。
11. **VCP-11 刹那芳华历史差异**：原记录64→723是特定时点的人工观察。缺少同一捕获的输入时不能升级为当前自动化结论；保留其未验证状态，不能默默删掉原承诺或从其他页面推定通过。

### 模板规则

12. **VCP-12 加载、校验、冻结**：启动从随包交付的规则资源加载一次；文件/JSON/结构错误带文件与字段位置失败。`templates` 必须为列表，固定种类、描述符字段、别名冲突、非空条件值均校验。`non_lyric` 仅接受布尔值；描述符可仅含 `names` 与 `non_lyric`，也可将该标记附于既有 `kind`，其余必填字段约束不变。规则资源不读取部署配置目录，也不提供部署级覆盖路径；损坏即失败。
13. **VCP-13 数据驱动规则**：同一种既有算法的槽位、名称、字段别名和角色优先级由配置决定；新 `kind` 需要实现支持，不把配置扩展成可执行脚本。链接类 inline 模板通过 `target_params` 与 `text_params` 指定目标和显示文字，Ruby 通过 `base_params` 与 `annotation_params` 指定表层和标注；参数列表均按顺序取值，新增链接/Ruby列表必须非空。`section_aliases` 配置章节关键词，保持简介优先；`song_list_filters.exact/contains` 配置列表排除文案，保留既有大小写和匹配顺序；命名空间、锚点及协议判断仍由代码负责。`song_field_sources.uploader/singers` 配置字段取值顺序，采用第一个非空值，不改变信息框原键或将多字段强行合并。上述分组与字段名固定校验，未知项和错误类型不静默接纳。`non_lyric: true` 标记非唱词模板，仅在歌词文本提取中不输出其内容、不记录歌词缺口；省略或显式 `false` 不忽略，简介等其他路径仍按原规则处理。`refn`、`Photrans/button`、`LDC` 的名称由规则资源声明，不在解析器保留名单。规则资源是随包交付的程序知识而非部署配置：修改默认规则随代码变更审查进行，不保留 `server/config` 副本。

### 缺口与可选模型

14. **VCP-14 候选缺口、渲染边界与完整性**：规则或渲染得到的非空片段不等于完整；规则/渲染阶段的完整候选须有有效非空内容且自身无未解决缺口。未选版本或未选原译文/Ruby 分支的缺口不污染已选版，页外未知模板和展示参数本身不是业务缺口。已知误报与真实未抽取内容在测试证据中分别标注，不用 `needed=true` 自证模型调用必要。
    - 只渲染现有支持的 `embed`，不扩为任意模板或整页渲染。各候选独立归并自身片段；每版累计渲染文本预算 **12000 字符**、单次模板调用源码上限 **8000 字符**、单次 HTML 上限 **100000 字符**。超限、预算耗尽、空结果、渲染错误或无法分离为单版的结果保留对应缺口，不把截断片段或错误页文字当完整歌词。
    - 仅对已选单候选请求歌词补提；调用成功且经回答格式校验得到有效非空字符串（去除空白后非空）时，接受模型不确定性，乐观视为完整或覆盖绝大部分有效内容，合并最终歌词并清除 `needed.lyrics`。不新增全文覆盖认证、复杂评分系统或第二审核模型。请求失败、空/纯空白、缺少歌词字段或格式/类型错误不能清除缺口、标记完整。
15. **VCP-15 双开关、一次补提与独立总结**：`crawler.merge_rendered_fragments` 与 `crawler.use_llm` 缺省均为 `true`；运维显式 `false` 必须被尊重。LLM关闭时，总结/补提模块均不注册、不调用；未配置的模块不注册、不用另一个模块冒名替代。
    - 先完成 VCP-07 的规则及可选渲染阶段，再由已配置且启用的补提模型对剩余请求项最多调用一次，不按候选轮流调用或失败后改投另一候选。歌词材料仅来自选定候选；歌词已完整时不再请求歌词补提，但简介/信息框等仍可在同一次补提中补缺。没有歌词候选材料时不要求模型凭空生成歌词。只合并实际请求项，忽略未请求的歌词答案，不能覆盖已经完整的歌词。
    - 简介补提、歌词补提与独立短摘要职责不混用。“最多一次”限制补提模型，不包含独立总结；总结在补提结束后读取最终数据，不能改写原简介、歌词或充当完整性审核。补提失败仍保持独立总结调用及其既有降级；总结失败不抹掉已完整歌词。Song 在该流程结束后若 `needed.lyrics` 仍为 `true`，Fetcher 记录日志并返回 `None`，由 World 沿既有 `fetch_failed` 路径跳过，不把部分歌词交给 Agent，不修改 Agent 的接纳与持久化边界。
    - 双关只保证无片段 POST 与模型调用，不禁止正常详情 GET。模型服务存在且启用的模块配置无效时，初始化报可定位错误；模型服务缺失时保留可选功能未启用的降级。运行期可选调用失败保留降级，但不能因此放行仍不完整的 Song。

### 关键词与部署

16. **VCP-16 最终单版关键词与索引格式**：`spaced_lyrics` 与歌词关键词只从最终采用的单版歌词生成或同步更新；不沿用被替换候选、旧缓存或译文的关键词。按空白切分，保留6–50字符的片段，过滤含 `=>` 的片段，结果不得含换行；避免破坏 `keyword=>value` 索引行。保留符合条件的重复副歌与和声片段及原顺序，不去重；上下界不因新的语料采样随意调整。
17. **VCP-17 非目标的关键词改动**：本次不实施降低长度下界、改变切分单位、过滤纯拉丁片段三项建议。早期小样本记录只是这一范围决定的背景，不等于全站或所有英文场景均无收益。
18. **VCP-18 部署与包内资源**：依赖清单包含 `mwparserfromhell`、`zhconv`，按项目约束安装。默认提取模块引用的 DeepSeek provider 必须在同一配置模板定义。wheel含规则文件，并能在无源码配置且不同cwd的隔离环境真实加载、解析最小页面。整个服务仍需要单独的部署资源，不将规则加载成功表述为wheel独立具备全部运行资源。
19. **VCP-19 缓存与存量数据边界**：旧 Song、未知类型或含歌词的缓存不能证明符合单版约束，忽略并重新抓取、提取；仅 `type=Person` 且无歌词内容的缓存可直接使用。不得因为缓存非空、字段齐全或带旧关键词就放行 Song；重抓失败也不回退到该缓存。不删除缓存、不写回、不增加缓存认证框架。本次不迁移数据库、不重建旧关键词索引。World只投递候选，由Agent接纳写知识，不改变双方持久化边界。历史3414/3320/99.2%/59733等数字是当时本地数据观察，不是本轮测试分母；本轮不访问生产库时不得称已重新验证全部存量歌曲。

### 提取规则与离线验证

20. **VCP-20 计数清理**：名字以count结尾的模板不能离线展开。简介/散文材料剔除携带计数的整句；信息字段/模板参数仅剔除相关分句并保留其他资料。不为计数联网。共享标记函数返回“是否修改”，调用方继续渲染被标记的节点，不能输出布尔字符串。
21. **VCP-21 字形与保护顺序**：`nowiki` 在结构遍历前保护，无标志LC在最终转换边界保护；正文只转换一次。`material_text` 统一做保护转换、计数剔除、截断；材料截断不代表候选缺口已解决，补提答案假定为最终文本，不再重复转换。原文、译文与标注分支必须按选定候选解释，不能把全部HTML歌词容器总长度当某个候选完整度，也不能因合并相同文本而删除重复歌词。
22. **VCP-22 提示词实验**：默认离线，显式live才调用已配置的补提模型；无缺项不自动调用。实验复用生产材料、回答校验与合并，报告不启用片段POST以及并非完整生产端到端测试。非法JSON/非对象/超长回答或provider失败必须有可检测失败状态；A/B失败不能伪报全成功，输出不得含凭据。
23. **VCP-23 运行成本比较**：同批配对输入，旧侧使用merge-base真实HTML算法，新侧使用生产解析算法；读盘/导入/初始化/网络/LLM不计时。每页预热2轮、正式9轮交替先后，运行3组，保存原测量、各页中位数、配对比、整组比及本次实际样本身份。输入字节比不是网络传输比。样本仅由manifest声明，不设第二份锁文件或固定页数；更换集合后旧报告不代表新实验。`--check`要求3组新侧中位耗时总和均小于旧侧，仅说明本次方向性，不承诺最低裕量或统计显著性；缺输入或解析失败不能算通过。
24. **VCP-24 语料与内容预期**：已有原件的来源、必要hash、已知revision、权利信息及使用列表只维护在manifest，不同版本不按标题混配，未知身份不伪造。选材时的官方活跃页记录仅为背景信息，不是测试前置条件；操作数不是编辑数，最后编辑者不是结构作者。独立oracle不由当前解析器生成。内容报告保留已知缺口，`--check`仅在当前解析器满足本次声明范围全部独立预期时返回0；普通测试验证已实现内容及评分正确/错误行为，不要求旧错或新错永久不变。

## 模块与接口

| 模块 | 职责与边界 |
| --- | --- |
| `wiki_api.py` | 请求形状、身份、挑战兜底、解码和失败语义 |
| `wikitext_parser.py` | 源码顺序遍历，信息框/简介独立产出，首框归属；各歌词候选独立状态、规则抽取与确定性选择 |
| `template_rules.py` | 规则位置、形状校验、冻结与查询 |
| `text_conversion.py` | 每次抽取的文本保护和一次转换；最终歌词的空白切分材料，不去重副歌/和声 |
| `source_extraction.py` | 各候选受限片段渲染与选择、单候选材料及无歌词的其他材料构造、补提回答校验与请求字段合并，不调用模型 |
| `vcpedia_fetcher.py` | 缓存准入、详情编排、最多一次补提与独立总结调用；关闭/失败语义及不完整 Song 拒绝返回 |
| `daily_new_song_fetcher.py` | 列表、候选规范化与关键词过滤；歌曲入口拒绝缺介绍或空歌词，沿既有 `fetch_failed` 跳过，不写知识 |
| `task.py` | 框架初始化入口、必要依赖持有、世界事实投递 |
| `tests/support/vcpedia_samples.py` | 最小fixture读取与输入hash检查，由内容和性能比较复用；不是CLI |
| `vcpedia_prompt_lab.py` / `vcpedia_perf_baseline.py` / `oracle_support.py` | 提示词实验、离线性能及独立内容报告，不作为后台任务运行 |

稳定业务入口与本次内部接口：
- `parse_details(source, title, *, with_missing=False)` 保留原签名与返回形状，默认返回 `data`，启用缺口输出时返回 `(data, needed)`；歌词选择遵循规则阶段的 VCP-07，而非固定首候选。
- 新增内部 `parse_extraction(source, title)` 返回 `(data, needed, candidates)`，供 Fetcher 把解析状态传给后续渲染/材料阶段。`candidates` 按源码顺序保存 `LyricCandidate` 的内容、缺口、渲染等内部状态；候选对象不进入业务 `data`、缓存、World/Agent 负载或持久化字典，不增加多版本业务字段。
- `needed` 为 `infobox` 键列表及 `summary`、`lyrics` 布尔标志；非空字段可以仍被请求补全。`needed.lyrics` 随候选选择、渲染与有效补提更新，只反映最终选定版仍需补全（无可用候选时保留缺项），不是全页各版本缺口的并集。`data.lyrics` 与 `data.spaced_lyrics` 同步来自该版；内部部分结果不等于可交付 Song。
- `VCPediaFetcher(config, llm_module=None, *, extraction_llm_module=None)` 的详情入口签名不变；关闭返回空字符串，失败返回 `None`。缓存仅在 VCP-19 的 Person 无歌词条件下直接返回，其他缓存重抓；Song 最终仍缺歌词时记录日志、保持独立总结降级流程后返回 `None`，World 沿原 `fetch_failed` 跳过，不修改 Agent。
- `collect_materials(data, needed, source, base_url, title, *, post=None, merge_fragments=True, candidates=None)` 可选接收本次 `parse_extraction` 状态，省略时从同一源码取得候选，兼容既有调用；不接受无用途的 `get` 参数。按 VCP-07/14 处理候选后同步 `data`、`needed`，返回补提材料而非业务字段。
  - `materials["lyrics"]` 仅在歌词仍缺且有选定候选时提供，只有该版的 `source`、`rule_result`、`rendered`、`gaps`；分别为原文源码、规则阶段结果、该版成功渲染片段与剩余缺口。不得拼进其他候选或译文；原文与译文、标注分支按既有可见正文规则隔离。
  - 其他字段用的 `materials["text"]` 移除歌词域（含嵌套歌词槽、章节与容器），不能把整页歌词经备用材料重新带入模型。实际模型输入中的歌词业务值也只保留已选版。歌词已完整时不提供歌词补提材料、`needed.lyrics=false`，其他字段仍可请求补提；无候选时不能把全页当歌词候选。
- `decode_extraction_response(response)` 校验纯JSON对象；字符串按原始字符数、dict按JSON序列化字符数限制24000，拒绝NaN/Infinity等非JSON数值，不增加Markdown fences宽容。字段合并再校验请求项类型：歌词必须为有效非空字符串，缺失/空/错误类型不清除 `needed.lyrics`。实验与生产复用入口，不增加歌词认证器或复审调用。
- `VCPediaNewSongTask.initialize(runtime)`保留框架入口，之后只持有必要窄依赖；不扩展为其他World任务的重构。

## 验收失败与降级边界

- 规则/渲染阶段无完整候选不等于请求已失败：保留各版缺口，允许按排序只给一个候选一次补提；但非空部分内容、材料截断或其他版本的渲染成功均不能替该版清除缺口。片段关闭、超限或错误不会扩大渲染范围，也不转为整页渲染。
- 歌词经规则及可选渲染后仍有缺口时，若补提未启用、未配置、无单候选材料、请求异常、非法/超长回答、非对象或歌词字段无效，仍保留 `needed.lyrics=true`。通过整份回答格式校验后的有效其他请求项可按原字段契约处理；不重试另一个歌词候选，不用总结模型冒充补提。独立总结及其失败/关闭时的既有短摘要降级继续执行，不能据此把歌词标完整。
- Song 最终仍需歌词补全时，Fetcher 返回 `None` 并记录未取得完整单版的日志；World 记录为 `fetch_failed` 并跳过候选，不向 Agent 投递部分歌词。歌词已完整而其他字段补提/总结失败，不触发该歌词拒绝条件，继续既有其他字段降级。歌曲任务入口 `_fetch_candidate` 仍须同时取得有效介绍与非空歌词，缺介绍或空歌词的结果沿原 `fetch_failed` 跳过，不以 `type` 硬筛、不修改 Agent；Person 缓存可用不等于可提交歌曲。合法空页面的传输语义与 VCP-03 不变，不能把“传输成功”当“歌词验收通过”。
- 不合单版条件的缓存不能兜底：重抓或补提失败也不返回旧 Song/未知类型/含歌词缓存；缓存文件保持不变，不删除、不写回。此边界不是数据库迁移或新增认证流程。
