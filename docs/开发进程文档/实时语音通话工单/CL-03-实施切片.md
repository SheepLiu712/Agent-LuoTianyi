## 阶段 A 已明确候选

- JSON 控制帧 + 二进制音频帧；生产链路无 Base64 音频。
- 15 字节固定头：`version/route/flags` 各 1 字节，`stream_id/seq/payload_length` 各 4 字节大端无符号整数。
- `version=1`，`CHAT=1`，`CALL=2`，仅允许 `FINAL=bit0`。
- `seq=1..UINT32_MAX` 且不得回绕；payload 非空、最大 16384 字节，第一版 PCM16 单声道要求偶数字节。
- `stream_id=0` 可作为麦克风 wire 帧；服务端下行从 1 开始且不复用，但方向和登记规则由 Adapter 而非纯 codec 验证。
- `WireAudioFrame` 位于 Adapter wire 层，不进入 domain，也不复用供应商音频类型。
- 共享 fixture 覆盖 CHAT/CALL、麦克风流、final/non-final、seq 上界、最大 payload 和全部稳定 codec 错误。

## 验收与证据计划

- Issue #274 的验收 checkbox 保持未勾选，直到功能实现、测试和非作者开发者审核完成。
- 提供对应模块 unit 与跨模块 integration 测试；完整 call_ws 链路使用 fake Agent、TTS、RealtimeSpeech 的 e2e。
- 供应商、AEC、蓝牙、真机与性能目标使用独立 smoke、设备或 performance 证据，不冒充普通 CI。
- codec 首轮验证历史为 Python 42 passed、App 目标 29 passed、App 全量 279 passed；限制前复制修复后的最终证据为 Python 45 passed、App 目标 33 passed、App 全量 283 passed，且 TypeScript strict、App 新增文件 ESLint、Python Ruff/Black 与架构边界检查通过。跨端独立脚本确认 5 个有效 golden、11 个稳定错误和 7 组错误优先级一致。
- `npm ci --ignore-scripts` 没有新增依赖或修改 lockfile；安装器报告锁文件现有依赖树包含 69 个漏洞提示，本工单未运行 `npm audit fix`，该提示不构成安全审计结论。
- codec 只提供未来可替换编码的窄接口，没有 Base64 生产实现、自动嗅探、registry 或 plugin loader。

## 影响边界与失败原则

- 不修改产品 AC；实现发现冲突时先停止，由真实开发者修订 spec 或 ADR。
- 外部服务、网络、存储或设备失败不得静默成功。
- 不持久化 spec 禁止的 PCM、逐轮转录、工作摘要或完整上下文。
- 不把骨架 fake、端口、协议值对象或 reducer 当作生产能力。
- 不代表完整 F2、19 条 AC 或其他 CL 已完成。

## 未决项

- ADR 当前仍为 Proposed；15 字节帧头、字节序、payload 上限与 codec 错误集合只是已获用户批准继续实施的候选，不等同于非作者审核通过。
- 控制消息的 `seq` 归属、`call.switch_prepare` 与 `call_ws` 序号边界、ACK/NACK、resume、取消范围及 WebSocket close code 尚未冻结。
- 完整 spec 和接口仍需非作者开发者审核。

## 明确排除

- 当前候选与纯 codec 不完成或关闭 Issue #274，后续控制协议、生产接线、测试和审核完成后再关闭。

- 不增加控制消息 schema/parser/endpoint，不提前冻结 ACK/NACK envelope，不写生产 Base64 或生产 codec 接线。
- 不实现 Stage、完整 `call_ws` 或 F2 其他验收项；外部控制协议研究归并前不得宣称完整 CL-03 或上线能力。
