### AC-16 失败降级与启用资源

- 主回复生成失败时，Agent 发出预录歉意 `Say`，该内容为 provisional，不进入正式轮次或认知维护；Stage 记录失败轮次。
- CALL TTS 每个失败表达最多重试一次。已发送的旧流先停止，重试使用新的 response id，避免旧音频与重试混合；已成功表达不重复执行。
- 重试耗尽发送非终态 `error`，`code=CALL_TTS_FAILED`、`retryable=false`，供客户端播放内置提示音。这里的 `retryable` 表示不要求客户端重发动作；服务端已完成本轮重试。连续两轮主回复或 TTS 失败以 `SYSTEM_FAILURE` 结束通话；正式回复成功重置计数，取消和维护失败不计入。
- 启用前必须在角色的 `prepared_speech.manifest` 中配置稳定名称 `call_apology`，引用有效、非空的 **24 kHz / 16-bit / mono PCM WAV**。缺失或格式不符时 CALL 能力检查不通过。资源由部署者提供，本 PR 不包含实际角色语音；测试生成的 WAV 仅作为测试数据。

清单条目示例（沿用既有预制语音配置，路径相对清单目录）：

```json
{"name":"call_apology","audio_path":"call_apology.wav","text":"抱歉，我刚才没能回答好。","expression":"normal"}
```

客户端实际提示音与真实设备播放仍需 App 集成验收，服务端测试只证明错误事件、PCM 和生命周期契约。

## 恢复连接防御性加固候选

- 客户端三秒恢复故障的根因不是服务端竞态：客户端曾以 WebSocket 保留关闭码 `1012` / `1002`
  调用浏览器侧 `close()`，该调用抛出 `InvalidAccessError` 后又被吞掉，导致旧物理连接并未关闭。客户端已改用
  合法私有码 `4000` / `4001`；干净服务端 `878337d3` 上的真实 JavaScript WebSocket 三秒恢复已经通过。
- 服务端额外增加防御性连接释放门禁，但不把它描述为上述客户端故障的根因修复。`call.resume` 最多等待 2.5 秒，
  仅在旧 connection 真实释放后绑定；持续存活的连接仍稳定返回 `CALL_CONNECTION_ACTIVE`，不会被新连接抢占。
- 等待前后均校验 user、character、session、generation 与 reset admission；两个并发 resume 只有一个 owner。
  cancellation 不创建后台等待任务，terminal unregister、账户 reset 和 shutdown 会唤醒 waiter，迟到旧 finally 不能释放新 generation。
- 2.5 秒是 Hub admission 上限，不会重置或延长 CallStage 首次断线建立的固定三秒恢复期限；聊天恢复的十秒窗口是
  另一条生命周期契约，不能与通话恢复混用。
- handoff 回归只把过期的宽泛 `ValueError` 期待更新为稳定 `InteractionOwnedByCallAdmission` 类型与
  `INTERACTION_OWNED_BY_CALL` 精确错误码；旧租约必须完成收束后才能接纳 replacement 的实质断言保持不变。
- 本轮具名复验：transport 53 passed、endpoint 13 passed、handoff 34 passed、shutdown 5 passed；Black、Ruff、
  架构边界、diff check 与 UTF-8 源文件检查通过。真实付费供应商、Kotlin 编译、Android 设备、provider P95 与
  非作者审核均未验证。

## 启动恢复修正

启动恢复在旧 Runtime 已停止、新 Runtime 尚未开放 admission 的边界执行，扫描全部可恢复的遗留账本，不以 updated_at 超过 30 秒推断所有权。最近更新、与启动同刻更新或系统校时导致时间略晚的遗留记录均处理；保留原有状态/CAS、投影冲突和幂等约束。恢复失败仍阻止 readiness，不在在线运行期间调用这项启动扫描。快速重启与 SQLite 回归覆盖该边界。

## 通话阈值维护修正（N2）

- 正式回复（含开场和沉默续聊）后由 Agent 排入 `CognitiveMaintenance`。Stage 提供已结算轮次快照，Skill 沿用超过 60 条、保留 30 条的压缩配置，通过 Context 将摘要与窗口写入 Ephemeral Store。
- 带入的聊天种子仅参与工作摘要；长期记忆与画像只处理已覆盖的完整新通话轮次，未播放完成的角色回复不进入长期维护输入。候选/画像成功后 CAS 推进账本 `maintenance_turn_seq`，不提前标记结束结算成功。
- 阈值失败重试一次并复用冻结候选；结束维护先恢复旧批次，再处理剩余增量。批次只持久化候选、画像和摘要哈希，不保存转录或工作摘要。聊天的 entry marker 接口仍不用于通话。
- 回归覆盖真实 Agent/CallStage 的 32 轮链路、种子隔离、SQLite 进度、失败批次恢复、压缩提交时取消及取消期间新计划继续执行。模型/语音供应商使用测试替身，不代表真实供应商或设备验收。
