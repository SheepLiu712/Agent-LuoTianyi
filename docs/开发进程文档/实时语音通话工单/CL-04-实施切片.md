## 交付目标

实现独立 `call_ws` 鉴权入口、混合帧收发，以及 Adapter 的统一游标、有限重放、取消结算和有界背压。当前只允许恢复已显式注册的 `CallTransportSession`；新呼叫建立因缺少 CallStage、账本和供应商绑定而明确不可用。

## 实施步骤

1. 复核 F2 spec 对应 AC、当前生产调用链和依赖工单冻结的接口。
2. 先补失败测试或 characterization，再实现隔离 transport；生产能力保持默认关闭。
3. 保持 Web、Adapter、Stage、Agent、Infrastructure 与 App 职责边界。
4. 对失败、取消、重试、隐私、清理和幂等形成可观察证据。
5. 功能 PR 记录实际命令、通过、失败、跳过与未验证范围。

## 验收与证据计划

- Issue #275 的验收 checkbox 保持未勾选，直到功能实现、测试和真实开发者审核完成。
- 提供对应模块 unit 与跨模块 integration 测试；完整 call_ws 链路使用 fake Agent、TTS、RealtimeSpeech 的 e2e。
- 供应商、AEC、蓝牙、真机与性能目标使用独立 smoke、设备或 performance 证据，不冒充普通 CI。
- 三轮 Oracle gate 的历史结论均为 `BLOCKED`。其列出的 material findings 修复后，独立只读 focused 验证以 51 passed 和受控 `CountingEvent` 复现确认最后两项等待/退休问题已关闭；该证据只支持隔离 transport 阶段提交，不构成第四轮 Oracle、gate 通过、非作者审核或生产验收。
- 历史扩大回归记录为 WebSocket integration 119 passed、2 个既有 TIFF fixture 失败，以及 system/入口 7 passed；这些结果不冒充本轮复验。当前提交前复验结果记录在阶段验证文档。

## 影响边界与失败原则

- 不修改产品 AC；实现发现冲突时先停止，由真实开发者修订 spec 或 ADR。
- 外部服务、网络、存储或设备失败不得静默成功。
- 不持久化 spec 禁止的 PCM、逐轮转录、工作摘要或完整上下文。
- 不把骨架 fake、端口、协议值对象或 reducer 当作生产能力。
- 不代表完整 F2、19 条 AC 或其他 CL 已完成。

## 未决项

- 依赖 CL-03 Proposed 候选；本实现只消费共享 codec/schema，不把 ADR 标记为 Accepted，也不宣称生产采用。
- 完整 spec 和接口仍需非作者真实开发者审核。

## 明确排除

- 本计划 PR 不完成或关闭 Issue #275，后续功能实现和验收完成后再关闭。
- 不关闭或扩大 #270、#271，不实现本工单依赖之外的功能。
- 不实现 CallStage、账本、供应商、App、生产 ACK 业务语义或新呼叫所有权切换；`call.start` 不消费 intent、不创建账本。
