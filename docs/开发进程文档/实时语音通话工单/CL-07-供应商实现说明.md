## 交付接口

- `AliyunRealtimeSpeechConfig`：显式接收 `api_key`、`model` 以及 `workspace_id` 或受控 `endpoint`，不内置供应商型号。
- `AliyunRealtimeSpeechSessionFactory`：按 `call_id` 调用创建独立会话；本切片不接入生产组合根。禁用或配置不完整时抛出 `RealtimeSpeechUnavailable`。
- `AliyunRealtimeSpeechSession`：实现骨架 `RealtimeSpeechSession`，提供单接收循环、有限写队列与事件队列、初始化握手、16 kHz 单声道 PCM16 校验、事件归一化和幂等关闭。
- 回答清理按 `response_id` 隔离，状态包含取消请求/确认、`response.done`、assistant item 与待删除项；删除 ACK 可在 `response.done` 后于可配置期限内到达，默认期限为 2 秒。
- assistant item 分别记录“已经请求删除”和“正在等待删除 ACK”：重复 added/done、先 ACK 后 done 及已知 `conversation.item.created` 不会重复发送删除；新 item 仍独立删除，未知 item 不做归属猜测并 fail-closed。

## 官方协议证据

核对日期：2026-10-11。来源均为阿里云模型服务官方文档：

1. [Qwen-Audio 实时语音对话](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)
   - 工作空间地址格式为 `wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime?model=...`。
   - 上行为 PCM、16 kHz、16 bit、单声道。
   - 建连后先发 `session.update`，确认 `session.updated` 后再发 `input_audio_buffer.append`。
   - `turn_detection.type=smart_turn`；文档当前列举的 `qwen-audio-3.1-realtime-plus` 仅作为可配置候选，不作为代码默认值。
2. [WebSocket 接入指南](https://help.aliyun.com/zh/model-studio/fun-audiochat-realtime-websocket-api)
   - 供应商回答可用 `response.cancel` 取消；会话项目可用 `conversation.item.delete` 删除。
3. [Qwen-Audio 实时语音对话服务端事件](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-server-events)
   - 用户最终转写：`conversation.item.input_audio_transcription.completed`。
   - 环境声音：`conversation.item.ambient_audio_transcription.completed`，不写入对话上下文。
   - `input_audio_buffer.speech_stopped` 的 `reason=turn_invalid` 表示无有效语义。
   - 回答事件包含 `response.created`、output item、delta/done 和 `response.done`；用量仅从 `response.usage` 的数值 token 字段采集。

离线 fixture 直接按上述事件名与字段构造，并经过生产适配器真实异步收发路径，不复制真实凭据、音频或转录样本。

## 配置示例

```json
{
  "enabled": true,
  "api_key": "$ALIYUN_REALTIME_SPEECH_API_KEY",
  "workspace_id": "$ALIYUN_REALTIME_SPEECH_WORKSPACE_ID",
  "model": "$ALIYUN_REALTIME_SPEECH_MODEL"
}
```

也可用 `endpoint` 替代 `workspace_id`。环境变量替换仍应由上层现有配置加载机制完成；本模块不读取环境变量，也不记录凭据。`enabled` 必须是布尔值；队列和尺寸必须是正整数；超时必须是有限正数。禁用能力与启用但配置无效分别报告 `RealtimeSpeechUnavailable` 和 `RealtimeSpeechConfigError`。

## 已知限制与未验证范围

- 官方事件没有可证明的独立 `emotion` 或 `sound_description` 字段，因此有效用户轮次只提供最终逐字转写；二者保持 `null`。环境转写只映射为 `AmbientAudio`，不伪装成用户轮次声音描述。
- 取消或删除供应商回答失败、回答身份缺失、清理状态不确定时，适配器以 `ProviderFailed` 关闭会话，不继续复用可能被污染的供应商上下文。
- 事件队列默认上限 64；正常读取时以反压保留完整事件。终态使用队列外的单一状态槽：已成功入队的业务事件先按序排空，再产生唯一 `ProviderFailed` 或正常结束；失败和关闭都不为终态腾容量而丢弃轮次。
- `events()` 明确只允许一个消费者。通道不创建脱离生成器所有权的后台 `Queue.get`/terminal wait 任务；取消或 `GeneratorExit` 会释放消费者所有权，并把已取出但尚未稳定交付的事件放回队首。后续消费者可继续按 FIFO 恰好一次读取，取消后关闭也不残留 wait task。
- reader、writer 与单一 cleanup 调度器均为会话拥有任务；失败和关闭共享有界 teardown，socket `close()` 也受 `close_timeout_seconds` 约束。
- 本切片没有修改 Stage、Agent、Runtime、数据库或 App，也不宣称完整满足 AC-05 的上下文行为、情绪/声音语义或 AC-16 的整条通话降级链。
- 真实供应商 smoke 仅验证建连与 `session.updated` 握手，默认跳过；本次未运行、未发送音频、未产生付费请求。供应商型号能力、smart turn 实际效果和真实错误行为仍需有凭据的人工 smoke 验证。
