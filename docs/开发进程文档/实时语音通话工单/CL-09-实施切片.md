## 本次部分实现与边界证据

- `AsyncTTS.stream()` 在同步读取任务已完成、`pending.result()` 返回片段后，再次观察请求级取消；已观察到取消时抛出 `TTSStreamCancelled`，不把该已读片段交给消费者。
- `SayHandler` 在从 TTS 异步流取到片段后、调用 output emitter 前再次观察取消；已观察到取消时返回 `CANCELLED`，不开始新的音频块投递。已开始的 sink 投递不被宣称可撤销。
- 专属离线测试人为在两个精确边界发布 `CancellationToken`，先复现红灯，再证明不产生新的 `AudioChunkDraft` 或 `MessageEndDraft`。该测试不调用真实 TTS provider。

此切片不宣称满足 AC-07/08 的完整交付：当前输出模型仍没有 CALL 的 `audio_route`、`response_id`、`stream_id` 或通话序号，也没有 CallStage 的取消范围、tombstone 或 200 ms 的端到端测量。

## 未决项

- 依赖 CallStage 的 response/stream 生命周期和取消范围接口。
- 完整 spec 和接口仍需非作者真实开发者审核。
- sink 原子屏障有三种可选后续方案，均不在本切片擅自落地：
  1. **在现有 `OutputEmitter` 锁内检查取消**：可在 draft→sink 边界串行化，但必须定义已开始 `sink.emit()` 的不可撤销语义。
  2. **由 CallStage 提供每 response/stream 的投递许可**：最贴近 CALL tombstone 与取消范围，但依赖 CL-6 的稳定生命周期接口。
  3. **在 adapter 发送前检查取消登记**：可阻止尚未写 socket 的块，但跨越 Agent/Adapter 边界，且不能取代 Stage 的权威状态。

当前选择只修复 Agent 内可证明的两个观察边界；待 CL-6/CL-8 固定 response、stream、seq 和取消来源后，由非作者审核选择 sink 屏障归属。
