- `CallStartClaim.setup_deadline` 在 public `start_call` 首次 operation 接纳时捕获；并发与完成后 duplicate 不重置 deadline。`take_call_claim` 校验身份并生成 `CallStageOwnership`，`release_call` 使用 generation 防止旧 ownership 释放 replacement。deadline 只驻留当前 runtime，不写 SQL。
- 新增正式 Agent Stimulus / Snapshot：`CallInteractionSnapshot`、`CallAnswerRequested`、`CallStarted`、`CallTurnCompleted`、`CallSilenceElapsed`、`CallEnding`；以及 `AnswerCall` / `EndCall` actions。
- 新增 `CallSpeechDelivery`：默认 CHAT 完全兼容；CALL 必须 hidden、ephemeral、response-scoped，可标记 provisional。wire seq/stream ID 不进入 Agent 业务模型。
- `CallAudioSemantic` 允许 transcript、emotion、sound description 至少一个非空，补齐 spec 的 emotion-only 情况。
- 当前 consumer ownership：CL-6 CallStage 生产 snapshot/stimuli/final snapshot；CL-8 Agent 消费刺激并产出 `EndCall` / CALL `Say`；CL-9 TTS 消费 `CallSpeechDelivery` 并产出后续 transport stream。当前未接生产 handler。
- `CallTerminalFacts` 与 `CallFinalSnapshot` 分离终态和完成用户轮次；`CallReplyStatus` 允许已完成用户事实处于 NOT_STARTED / COMPLETED / INTERRUPTED / FAILED。只有 COMPLETED 必须有正式 Agent 文本；provisional、PCM、wire/provider 和 live Context 均不进入 snapshot。

## CL-06 Stage consumer 实现证据

- 新增真实 `CallStage`：消费 `CallStageOwnership` 后创建 `EphemeralCallConversationStore` Context，使用原始 monotonic setup deadline，显式把账本的 aware Beijing `requested_at` 转成 legacy naive Beijing 时间。
- Provider 初始化成功后进入 `RINGING`；Stage 暴露 `AnswerCall` 消费 seam，接受后进入 `ACTIVE` 并只提交一次 `CallStarted`。生产 Agent handler 属于 CL-08，当前不伪造默认 handler。
- 使用真实 `Agent.handle_stimulus` / `realize_action_plan`、串行 plan queue 和 response 级 `CallOutputPermit`；Stage transport sink 只有 awaitable `send_state` / `start_stream` / `send_pcm` / `stop_response`，不以 fire-and-forget 对象假装完成。
- 入站使用 `(call_id, direction, seq, fingerprint)` receipt 幂等；统一 wire seq 可合法穿插 control/audio，Stage 另行生成 provider 连续音频序号。receipt 只保留 bounded 元数据而不保存 PCM，PCM 仅存在 bounded queue/current push，队列满不接纳。
- CALL RAW PCM 只接受 canonical PCM16/24 kHz/mono。首次块先登记 playback、await `start_stream`，每块 await `send_pcm` 并维护 pending-send；只有成功发送 final 才标记 final。`MessageEnd` 只表示生成结束，不等于播放完成。
- playback completion/stopped 幂等结算；恢复成功按已确认工程选择重新开始完整 5 秒沉默窗；首次断线固定 3 秒恢复期限，未恢复时 monotonic duration 截止首次断线，成功恢复波动计入同一通话。
- `speech_started` 撤销当前 generation 的 permit、取消在途 handle/realize、tombstone response 并通过窄 sink 发出 stop；晚到块 fail closed。正式回复若前有 provisional，须等待对应 response 实际播放完成后才执行。
- 终态冻结 `CallFinalSnapshot`，保留所有已完成用户语义事实及 reply status；provisional 不写正式回复，cleanup 清 PCM/临时 turns/provider/context/tasks 并释放 generation-guarded ownership。终态 snapshot 可交给窄 settlement sink，Stage 不直接调用 Skill。
- 新增 `CallStageBinding`，作为真实 `CallBusinessAcceptanceSink` 与 Stage transport consumer：入站复用 CL-4 原始 wire fingerprint，出站通过同一 `CallTransportSession` 分配统一 control/audio seq、replay 与背压；未启用 endpoint capability。
- wire 状态映射遵守已发布 schema：仅 `PREPARING/RINGING` 使用 `call.state`，`ACTIVE` 使用 `call.active`，内部 `ENDING` 不发送非法状态；`ENDED` 从冻结的 `CallFinalSnapshot` 恰好一次生成 `call.ended`，接通前不可记录 `FAILED` 使用规范 `error`。
- receipt 使用固定容量滚动 LRU 元数据，超出容量淘汰最旧 ACK receipt，而不是让长通话永久拒绝；不保存 PCM。provider audio sequence 独立连续生成。
- 生命周期 CAS 由 transition lock 串行，候选状态只在 owned `to_thread` CAS 成功后提交到内存；CAS false 执行 owned readback identity 后 fail closed。终态先关闭 provider/context、释放 lease、设置 closed，再把不可变 snapshot 快速交给后台结算。
- 终态顺序现为：冻结并持久化 `ENDED` → Agent `CallEnding`（无可见输出）→ 关闭 provider/context、清实时任务、释放 ownership 并设置 closed → 快速接纳后台 settlement → bounded best-effort 唯一 `call.ended`。`terminal_delivery_timeout` 是本地可配置正有限值，默认 1 秒；它只约束任务收束，不声称能撤回已经写入 socket 的字节。永久阻塞或失败不再占用 CALL lease，也不会跳过 settlement 接纳。
- 三秒恢复使用首次断线时固定 `recovery_deadline=monotonic+3`；`resume` 在任何状态变更前按 `>= deadline` 判失败，延迟调度的 timer 不会延长窗口，resume/timeout 共用生命周期串行锁。
- transport 业务输出失败统一触发 owned abort：曾 ACTIVE 的呼叫以不可变 `CONNECTED/SYSTEM_FAILURE` 结束；后台 stop/end task 读取异常，不留下未观察 task。transport replay backpressure 仍是正常 await，不作为失败。
- 新增 application `CallSettlementCoordinator`：同 call 幂等后台接纳、15 秒上限，并在成功、失败或超时的 `finally` 通过 AgentRuntime 窄 `release_call_resources` port 清理 call recall pool；没有 summary/maintenance consumer 时不得将账本标为 SUCCEEDED。
- 持久化五类 transport failure 证据位于 `test_call_transport_failures.py`：ACTIVE state、stream start、PCM、stop 与双 response 并发 stop failure，均使用真实 CallStage/Agent/ContextFactory/SQLite，仅 provider/transport 为可控外部端口；断言单 abort、`CONNECTED/SYSTEM_FAILURE`、ledger `ENDED`、资源释放、settlement/terminal 各一次及无 pending task。
- 具名验证命令结果：coherent/Stage/binding/application/handoff/handlers（含上述五例）**69 passed**；受影响 control/transport/websocket 回归 **128 passed**。Black、Ruff、architecture、diff check 通过。此前独立 focused probe v2 为 **92 checks / 0 fail**，仅作为问题发现与交叉证据，不计入 pytest 数量。真实供应商、付费凭据、endpoint/runtime 最终装配、App/device/AEC、真实 summary/maintenance consumer 仍不在本证据范围。

## 已确认接口缺口

- 当前共享 Agent 计划身份编码不支持 `AnswerCall.call_id: UUID`，因此 CL-08 在不修改共享契约前无法通过真实 `PlanEmitter` 产出 `AnswerCall`；本切片只提供 Stage 的显式消费 seam，不用 fake AgentStageContext 掩盖缺口。
- 当前 Adapter/transport 没有供后台 Stage 主动推送 semantic output 的生产 binding；本切片注入窄 sink，保持生产 `call_transport_available == false`，由后续统一接线解决。
- `CallSpeechDelivery` 没有 `stream_id`、final 或 server seq range；Stage 能维护 response tombstone 和已登记 stream，但不能生成完整 wire `playback.stop` 取消范围，留给 CL-09 冻结接口。
