## 3. 待人工确认的决策

夜间不代替负责人选择。每项列出候选、取舍和推荐；除明确写出的已确认事实外，推荐均为**未选**。

### D-1：CL-3 `call.v1` 二进制帧头

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 固定窄头 | 小、解析快、夹具简单 | 扩展空间有限，须一次冻结全部语义 |
| 固定宽头 | 为 stream/seq/payload 留余量 | 首版每帧开销更高，仍须冻结语义 |
| TLV 头 | 可演进字段 | 校验、兼容与安全边界更复杂，不适合首版 |

**推荐但未选：固定窄头。** 协议/服务端负责人须冻结字节序、各字段宽度、最大 payload、flags、稳定错误码与取消范围；此前不得冻结 ADR、夹具或 CL-4 wire。

### D-2：ADR 拆分

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| wire、provider、Android 分三份 ADR | 各专家可独立审阅，回滚边界清晰 | 文档较多，需交叉引用 |
| 合成一个 F2 ADR | 单一入口 | 决策节奏互相阻塞，审阅过大 |

**推荐但未选：分三份 ADR。**

### D-3：CL-7 供应商接入

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 官方 SDK | 支持路径通常更完整 | 平台、依赖、线程模型和升级风险待核实 |
| 直连 WebSocket | 协议和资源生命周期控制直接 | 自行处理鉴权、重连、事件兼容与错误 |

尚未选择。需要供应商/成本负责人确认方案、预算与凭据授权；不得购买、申请或使用付费凭据，也不得把本地尝试连到 production。

### D-4：CL-10 时间语义

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 所有时间统一 aware UTC | 跨主机时区稳定，SQLite 可存 naive UTC、读回恢复 UTC | 是共享 CL-2 契约变更，调用方与测试须同步修改 |
| 所有时间统一服务端本地 naive | 与部分旧字段形式相近 | 跨时区、夏令时与数据库搬迁语义不稳定 |

**推荐但未选：aware UTC。** 共享契约 owner 必须正式批准后再改 `CallSessionRecord`、调用方和测试；无论选择哪项，`create_if_absent`、`update_if_state` 与 `list_stale` 都必须拒绝另一种 datetime 形式，不得猜测主机时区或静默转换 naive cutoff。

### D-5：多 worker 闸门与 namespace

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 多 worker 时拒绝启动通话能力 | 不会静默绕过进程内 lease | 需要权威拓扑来源与启动配置 |
| 多 worker 时仅禁用 call | 聊天/管理仍可用 | 需稳定能力暴露、错误码与运维说明 |

worker 来源、部署 namespace 与允许失败模式未确认；不猜配置键或自行加启动逻辑。UUIDv5 namespace 仍可在固定项目常量、URL 派生或部署配置中选取，**推荐但未选**固定项目常量；必须由项目/运维负责人确认具体值与来源。

### D-6：CL-12 Android 实时音频

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 第三方原生模块 | 可能较快获得 AEC/路由能力 | 维护、许可、Expo 兼容、性能与安全待评估 |
| 自有 `AudioRecord` / `AudioTrack` | 可控制采样、消费回执和通信模式 | 实现和真机验证成本高 |

尚未选择。WebView 或文件式 AAC/M4A 录音不等价于 16 kHz PCM 实时采集、24 kHz CALL 实际播放完成。需要 Android 技术与设备测试负责人确认。

### D-7：快速模型与过渡语

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 沿用现有快速模型 | 复用模型治理与装配 | 延迟、成本、质量仍须测试 |
| 新本地 Judge | 潜在较低延迟和成本 | 数据集、质量、部署与安全未验证 |

尚未选择，不采购、不付费。`RECALL` 过渡语是用户可感知内容，须产品/内容负责人批准后进入资源。

### D-8：CL-11 界面推进

| 候选 | 优点 | 风险/代价 |

| designer 确认隐藏入口、视觉和状态演示后实现 | 与 AC、既有 App 和真实状态一致 | 需设计审阅排期 |

### D-9：CallAudioSemantic 最小有效内容

Spec 规定 `transcript`、`emotion`、`sound_description` 至少一个非空，但现有 `CallAudioSemantic` 骨架是否拒绝仅有 `emotion` 的输入尚未与该规则校准。

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 接受 emotion-only | 严格遵循“至少一个非空” | Agent 上下文文本格式须补充可观察语义 |
| 拒绝 emotion-only | 避免没有语音内容的轮次 | 可能收紧 spec，必须先修订并审核 spec |

**推荐但未选：按 spec 接受 emotion-only，先由 spec/领域 owner 确认文本映射。** 不擅改值对象或 spec。
