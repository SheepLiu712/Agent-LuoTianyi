## 3. 待人工确认的决策

以下内容涉及协议、供应商、客户端原生能力、部署拓扑或用户可见体验。夜间不替代主人作决定；每项给出候选、取舍和建议，等待具备相应权限的确认者。

### D-1：CL-3 二进制帧头

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 固定窄头 | 小、解析快、实现和夹具简单 | 字段扩展空间有限，须现在冻结字节序、宽度、payload 上限和错误码 |
| 固定宽头 | 为更大 stream/seq/payload 留余量 | 首版每帧开销更高，仍不能免除冻结语义 |
| TLV 头 | 可演进字段 | 解析、校验、兼容和安全边界复杂，不适合当前首版 |

**建议：固定窄头。** 仍需要协议负责人确认字节序、各字段宽度、最大 payload、flags、稳定错误码和取消范围；未确认前不能冻结 ADR、夹具或 CL-4 wire 实现。需要：协议/服务端负责人确认。

### D-2：ADR 的拆分范围

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| wire、provider、Android 分成三份 ADR | 每项由对应专家审核，决策和回滚边界清晰 | 文档数量更多，需要交叉引用 |
| 合成一个 F2 ADR | 单一入口 | 不同决策节奏互相阻塞，审阅范围过大 |

**建议：分开。** wire ADR 仅覆盖 `call.v1`，provider ADR 仅覆盖实时语音供应商接入，Android ADR 仅覆盖采集/播放和系统音频路线。需要：架构/项目负责人确认。

### D-3：Spike-A 供应商接入方式

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 官方 SDK | 厂商支持路径通常更完整 | 平台、依赖、线程模型和升级风险需核实 |
| 直连 WebSocket | 控制协议与资源生命周期更直接 | 需自行实现鉴权、重连、事件兼容与错误处理 |

尚未选择。夜间仅可收集官方文档证据和在获授权凭据下执行 smoke；不得购买、申请或使用付费服务，亦不得把未验证方案写成生产能力。需要：供应商/成本负责人授权并确认。

### D-4：UUIDv5 项目 namespace

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 固定项目专属 UUID 常量 | 稳定、跨部署一致、便于长期幂等 | 一经发布很难更改，必须审查并记录来源 |
| URL 派生 namespace | 无需额外常量 | URL 迁移或 fork 容易造成身份含义混乱 |
| 部署配置 namespace | 环境隔离直观 | 同一逻辑呼叫跨环境/恢复的稳定性变差，配置漂移风险高 |

**建议：固定项目专属 UUID 常量，但本文件不选择具体值。** 需要：项目负责人确认值和 ADR 记录。

### D-5：多 worker 闸门

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 发现多 worker 时拒绝启动通话能力 | 避免进程内 lease 被静默绕过 | 需要权威识别现有部署拓扑和启动配置 |
| 发现多 worker 时仅禁用 call 能力 | 保持聊天/管理服务可用 | 需要稳定的能力暴露、错误码和运维说明 |

当前权威拓扑来源未确认；不应猜测配置键或自行加启动逻辑。需要：部署/运维负责人确认实际 worker 来源、允许的失败模式和配置入口。

### D-6：Spike-B Android 实时音频

| 候选 | 优点 | 风险/代价 |
| --- | --- | --- |
| 第三方原生模块 | 交付可能较快，可能已有 AEC/路由支持 | 依赖维护、许可、Expo 兼容、性能与安全需评估 |
| 自有 `AudioRecord` / `AudioTrack` 原生实现 | 控制采样、实际消费回执和通信模式 | 实现与真机测试成本高，需要原生维护能力 |

尚未选择。WebView 或既有文件式 AAC/M4A 录音均不等价于 16 kHz PCM 实时采集或 24 kHz CALL 实际播放完成。需要：Android 技术负责人和设备测试负责人确认。

### D-7：快速决策模型与过渡语

| 候选 | 优点 | 风险/代价 |

| 沿用现有快速模型 | 复用当前模型治理与装配 | 延迟、成本和决策质量仍需测试 |
| 新本地 Judge | 潜在更低延迟和成本 | 数据集、质量、部署与安全尚未验证 |

当前不付费、不采购、不选择模型。`RECALL` 的过渡语是用户可感知内容，必须经人工批准后才进入产品资源。需要：模型负责人和产品/内容负责人确认。
