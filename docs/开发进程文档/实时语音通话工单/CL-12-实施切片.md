5. 功能 PR 记录实际命令、通过、失败、跳过与未验证范围。

## 验收与证据计划

- Issue #283 的验收 checkbox 保持未勾选，直到功能实现、测试和真实开发者审核完成。
- 提供对应模块 unit 与跨模块 integration 测试；完整 call_ws 链路使用 fake Agent、TTS、RealtimeSpeech 的 e2e。
- 供应商、AEC、蓝牙、真机与性能目标使用独立 smoke、设备或 performance 证据，不冒充普通 CI。
- 当前离线证据：原生 adapter/pipeline Jest 2 suites / 18 tests，App 全量 Jest 36 suites / 390 tests，`tsc --noEmit`、相关 ESLint、Expo autolinking 与 `git diff --check` 通过。
- `npx expo-modules-autolinking verify --verbose` 实际从默认 `./modules` 搜索路径解析 `agent-luotianyi-call-audio@0.1.0`；本地模块无需写入根 `dependencies` 或额外 config plugin 也能被该命令识别。
- Android SDK、ADB、Gradle wrapper、`kotlinc` 与预构建原生工程均不可用；Kotlin helper 仅完成源码审阅，未编译或执行。
- New Architecture 加载、真实 16/24 kHz 格式、AEC/降噪/焦点、蓝牙路由、实际消费回执与延迟仍需原生构建和真机证据。

## 影响边界与失败原则

- 不修改产品 AC；实现发现冲突时先停止，由真实开发者修订 spec 或 ADR。
- 外部服务、网络、存储或设备失败不得静默成功。
- 不持久化 spec 禁止的 PCM、逐轮转录、工作摘要或完整上下文。
- 不把骨架 fake、端口、协议值对象或 reducer 当作生产能力。
- 不代表完整 F2、19 条 AC 或其他 CL 已完成。
