# 语音通话迁移至实时模型：第一版修改计划

状态：待评审的实施计划。基线为 `codex/voice-call-latency` 上的提交 `2bb3b826a4ca8bedd5766bbf2b38beebe6945473`，包含此前工作区的 30 个服务端文件改动。本文中的“新增”均指相对该提交的拟议变更。下文代码位置以仓库根目录为起点。

## 目标和非目标

一通已接通的电话使用一个 Qwen Realtime 会话。模型持续接收用户音频，给出输入转写、回复文本和记忆查询请求。沿用天依现有的语音合成（TTS）和播放确认链，首个可朗读短句一旦形成即可合成。用户可以插话、挂断，天依可以在接通及沉默时主动发言。通话结束后用本次通话全文生成总结。

采用单条生产链路，替换 Fun-ASR 识别、提前检索及随后单独调用文本模型回复的组合。第一版只实现一种供应商、一个记忆工具和文本回复输出。视频、游戏画面、原生音色、动态同步或删除云端记忆、断线续接模型上下文、通话内压缩、自定义断句算法、额外防抢话等待和管理员统计页面均不在本次范围。保留现有客户端协议；不以重做通用 Agent 或一次达到 1 秒作为上线前提。

## 模块边界及验收标准

| 模块和落点 | 负责的决定 | 验收时如何辨别越界 |
|---|---|---|
| `CallStage`（现有，`server/src/stage/call/call_stage.py`），管理一通电话的生命周期 | 为本次通话打开、持有、关闭会话；分配业务轮次；把会话事件送给 Agent；决定开场、沉默、播放许可、打断与结束 | Stage 能用一个假会话完成通话。代码中没有 Qwen 事件名、提示词组装、文本切句或向量查询。播放停止不依赖云端取消成功 |
| `Agent.open_omni_session`（拟增，`server/src/agent/facade.py`），创建角色专属会话 | 校验角色和交互身份，从上下文读取一次初始背景，调用注入的工厂。由 `server/src/agent_runtime/agent_runtime.py` 装配依赖 | 两通电话得到两个句柄；共享 Agent 不保存当前通话连接。现有 `handle_stimulus`（处理业务事件）和 `realize_action_plan`（执行动作计划）签名保持兼容 |
| `OmniSession`（新增，公共接口拟放 `server/src/domain/call/omni.py`），代表一次持续的模型交互 | 外部只看有类型的输入、业务事件和取消；Qwen 实现拟放 `server/src/infrastructure/models/realtime_speech/omni.py`，封装连接、协议编号映射、短句拼接、工具回填与续答 | 向同一接口输入音频和控制文本即可测试。实现不查询数据库、不写通话记录、不直接向手机播放。供应商原始事件不进入领域层 |
| 通话刺激与动作处理器（现有位置 `server/src/agent/handlers/stimulus/call.py`、`server/src/agent/handlers/action/`） | 转写处理器追加用户发言；回复片段处理器只编排朗读；检索动作处理器使用当前交互身份执行授权检索 | 回复片段经 Agent 控制，但处理期间没有第二次模型生成。查询处理器不持有云端连接，查询参数不能指定用户或角色 |
| `InteractionContext`（现有，`server/src/agent/context/interaction_context.py`）及其记忆池 | 持有用户资料、近期原文、更早概括、已确认的业务记录和本次召回。供应商会话只借用初始快照 | 初始化不把历史聊天复制成本次发言；缓存容量淘汰不会触发云端消息。关闭一通电话不影响另一通 |
| `Say`（现有动作，`server/src/domain/agent/action_plan.py`）及其 TTS 处理器（`server/src/agent/handlers/action/say.py`） | 按指定文本合成语音，沿用 Stage 的片段播放许可与客户端确认 | 此模块不识别 Qwen 会话、工具或话轮；发送成功或收到网络 ACK（客户端收包确认）不能当作片段播放完成 |

## 会话接口与数据契约

以下是逻辑签名。新增类型优先放在上述契约文件；已有等价字段或数据类直接复用，不另建一套通用事件总线。

```python
# Agent 门面。context 为 Stage 持有的 InteractionContext，call_id 为业务通话 UUID。
async def open_omni_session(context: InteractionContext, call_id: UUID) -> OmniSession: ...

# OmniSession。方法形式与供应商协议无关。
async def push(frame: AudioFrame | InstructionText) -> None: ...
def events() -> AsyncIterator[OmniEvent]: ...
async def submit_tool_result(tool_call_id: str, result: MemoryLookupResult) -> None: ...
async def interrupt(response_id: str) -> None: ...
async def close() -> None: ...
```

- `AudioFrame` 是既有的 PCM（脉冲编码调制）音频帧，现位于 `server/src/infrastructure/models/realtime_speech/contracts.py`。将其定义提到共享契约，原处按需重导出，保留载荷、编码、采样率和声道信息。`push` 只等待本地写入背压，不等待本轮回复或记忆结果。
- `InstructionText(kind, text)` 是新增的控制文本，`kind` 首版只取 `opening` 或 `silence`。一次有效投递请求一次主动回复。它不占用户轮次，不进用户转写。通话时限等既有控制流程保留原有语义。
- `events()` 由 Stage 的单一读取任务消费，与音频写入并行。初始背景使用已有快照拼装，不给 Stage 新增“同步上下文”接口。会话打开失败、供应商错误或异常关闭从原位置记录并沿现有失败流程结束；正常关闭与异常失败可区分。`close()` 可重复调用，收回本会话任务。
- `response_id` 表示一条模型回复；`segment_index` 是该回复中从零开始的短句序号。二者组成稳定片段键，可派生现有播放链所需的片段交付标识。输入 `item_id` 标识一条用户发言，`tool_call_id` 标识一次工具调用，均按会话隔离。业务 `call_id`、用户轮次、模型回复和播放流编号不可混用。

| 新增或复用的会话事件 | 字段及含义 | Stage 如何处理 |
|---|---|---|
| 用户开始说话 / 句末已判定 | `SpeechStarted(item_id)`、`SpeechStopped(item_id)`，复用已有语义。句末判定与转写完成是两个事件 | 依据输入标识建立轮次、暂停沉默计时并处理插话；回复可以先于最终转写开始 |
| `TranscriptFinal(item_id, text)` | 一条用户输入的最终文本；首版不消费中间转写 | 按输入标识关联原轮次并去重，转成已有 `CallTurnCompleted`（用户发言记录刺激）。拆开基线中“记录发言”和“发起回复”的耦合 |
| `ReplyStarted(response_id, item_id?)`、`ReplyFinished(response_id)` | 标记模型生成的活动区间；主动发言没有用户输入标识。工具回填后若供应商另起回复，仍关联原输入或主动发言 | 登记可取消的回复，跟踪生成是否结束。生成结束后可能仍有本地音频在播 |
| `ReplySegment(response_id, segment_index, text)` | 文本累积到可朗读标点后发出；正常生成结束时只冲刷一次剩余非空文本，取消时丢弃残段 | 转成新增 `CallReplySegmentReady` 刺激。沿用业务身份并携带片段键、可空轮次和文本。处理器生成一个现有 `Say`，首版使用现有默认语气；同回复短句按序播放 |
| `MemoryLookupRequested(response_id, tool_call_id, query)` | 模型提交完整的记忆搜索参数。协议参数增量不产生动作 | 转成新增 `CallMemoryLookupRequested` 刺激，处理器产生 `ActionPlan` 中的新增 `LookupCallMemory` 动作，携带相同的回复、调用标识和查询文本 |

工具回程新增 `MemoryLookupResult(hits)`，其中 `hits` 是按检索顺序排列的只读命中序列，复用既有记忆映射为稳定编号和正文；零命中用空序列。动作执行时从既有 `ExecutionContext.interaction_context` 取得交互身份与池，调用现有记忆技能，对仍有效的调用将新增命中去重入池。通过既有输出接收器发出内部结果 `CallMemoryLookupCompleted(response_id, tool_call_id, result)`，由 Stage 的输出接收器调用 `submit_tool_result`。每个有效调用只回填一次；本次命中即使已在池内仍完整返回。该内部结果不编码成客户端消息。输入事件读取任务只投递检索工作，不就地等待动作完成；挂断或所属回复失效后，迟到结果不得启动续答。正常等待工具的生成阶段结束不等于调用失效，调用有效期延续至回填或业务取消。

## 记录与时序约束

1. **接通。** Stage 创建当前交互，在接通流程内打开会话。Agent 加载角色指令、用户背景、更早概括、近期原文和已有记忆池。会话就绪且通话已接通后，Stage 仅发送一次开场控制提示。替换原开场回复生成入口。
2. **普通回复。** 音频持续写入；模型文本分段后经刺激、计划、TTS 到播放端。转写只记账，晚到时依据输入标识归位。沿用现有播放确认刺激 `CallReplyConfirmed`，只将完成确认的片段记为天依发言。全文按业务轮次和片段顺序组织，不用异步事件的抵达顺序推断对话顺序。
3. **沉默和打断。** 沿用 Stage 的沉默计时，用户在说话、工具调用未结算或已有回复待播时不另起主动发言；播放结束后恢复计时。用户插话先撤销旧片段的播放许可并通知客户端停播，再调用 `interrupt(response_id)`。供应商仍在生成才发送取消。重复取消或已结束生成不得触发非法取消；已排队的 TTS 片段也受同一许可约束。
4. **挂断。** 冻结本次通话已收到的用户最终转写与已确认播放的天依片段，不做通话内滚动压缩。沿用 `CallEnding → FinalizeCall` 和现有通话记录结算，以本次全文生成总结。优先扩展已有 `CallFinalSnapshot`（`server/src/domain/call/contracts.py`），使它包含主动发言及多片段已确认文本；不新增平行的持久化转写库。初始化背景、工具原始结果、开场提示和未播文本不纳入全文。末句没有最终转写时只结算已获得内容。

## 修改流程与交付检查

| 顺序 | 修改内容 | 通过条件 |
|---|---|---|
| 1. 定义契约、接通供应商 | 增加共享类型、Agent 工厂装配和一个 Qwen 实现；真实供应商配置仅走既有配置和密钥机制。首版配置实时模型文本输出并开启同会话输入转写 | 独立输入一段音频，可以分别收到转写和回复短句；控制提示能触发一次回复；并行两通电话不串数据，关闭后无残留读取任务 |
| 2. 打通发言和播放 | 替换 Stage 的语音接入，注册新增刺激处理器；复用计划队列、朗读输出和播放确认。接通、普通回复和沉默各保留一个触发源 | 首句可在整段生成结束前送入 TTS；主动提示不伪装成用户发言；迟到转写不导致第二次回复；首句被打断后第二句不能继续播放 |
| 3. 接入记忆并完成结算 | 注册唯一模型工具、检索动作与内部输出；补齐转写、播放确认与挂断快照关联。复用现有授权范围、记忆池和总结处理器 | 已知事实可查到并正确续答，未知事实返回空结果；慢查询期间可继续收音和挂断；仅背景中出现的事情不被记成本次通话；打断时未播放片段不进入总结 |
| 4. 移除替代路径并验证 | 删除生产通话的 Fun-ASR 装配、专属中间转写提前检索和旧 `CallReplyRequested` 生成入口；按引用清理死代码及旧配置。保留普通聊天检索、通话记忆池、音频耗时分析和现有失败诊断 | 检查正常运行只建一条实时连接、每轮只有一个回复来源。回归通话接入、拒接、时限、沉默、打断、挂断留痕及聊天不受影响。先在开发服验证，再决定部署 |

**性能与体验验收口径。** 同批录音回放闲聊、句中停顿、记忆命中、记忆缺失和故事中插话，和基线分别记录样本数、中位数、抢答及错误答复。保留原有生成、暂存、发送、客户端确认埋点，并按用户输入、模型回复和播放片段关联。实机再验证接通、主动问好、正常对话、插话和挂断记录。句末估计、供应商停止说话事件、最终转写到达和设备开始播放分别命名；拿不到实际播放起点时，明确使用客户端确认做代理。提前抢答或只回应了半句话不计为成功提速。首版允许据此记录模型表现问题，不在本工单预先实现新的断句模型。
