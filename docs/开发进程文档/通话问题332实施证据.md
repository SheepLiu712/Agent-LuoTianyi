# 通话问题 332 实施证据

## 原 AC 与实现边界

- 原 Issue 332 AC：正式通话播放时 Live2D 嘴型随语音变化；停止、打断、结束后静止；旧流、重连、页面卸载不残留驱动或重复音频；自动化覆盖正式生产接线；无真实设备证据不宣称同步体验通过。
- 本修复只增加视觉桥：`production_resolver → AndroidCallAudio → native onPlaybackProgress → setCallMouthRms`。
- 可听播放仍只有 Android `AudioTrack`；聊天 `feedAudioChunk` 未被通话复用，因此没有第二个 WebAudio 输出、第二个完成信号，也没有把 enqueue 当成播放完成。
- 原生 `onPlaybackCompleted` 仍由 AudioTrack playback head 消费到 final sample 后产生；`playback.completed`、stop/stopped、generation 和 327 early-completion/reservation 逻辑未旁路。
- 非 final 流下，若 playback head 已追平全部 submitted frames、且 `PlaybackQueue` 没有该 stream 的 queued chunk，`PlaybackVisualIdleGate` 只发一次 RMS=0；不发 completed/stopped。后续真实提交重新 arm，playhead 再推进后才恢复非零 envelope。
- RMS envelope 绑定尚未被 playback head 消费的提交窗口，不再使用“最近写入 chunk”作为当前嘴型值，避免排队未来 PCM 提前张嘴。

## 接口与视觉时序限制

- 原生每次 AudioTrack playback head 实际前进后，以不高于约 30Hz 发出当前 PCM chunk 的有界 RMS envelope；事件不是 enqueue 回调，因此排队 PCM 不会在收到时瞬时爆发嘴型。
- WebView 只接收固定函数调用和有限 `[0, 1]` 数字：`window.setCallMouthRms(number)`；不传 transcript、token 或无界 base64。
- 停止、tombstone、completion、close、native 初始化失败都会 best-effort 写入 0，并取消视觉订阅；旧 session/generation 的原生事件由既有 session/generation ledger 丢弃。
- 提示音使用独立 `ReplyFailureTone` identity，不发送嘴型进度。
- WebView 不存在、页面正在卸载或注入失败时只跳过视觉更新，不能使通话音频失败。
- 本实现没有新增第二 AudioContext；既有聊天路径的 AudioContext 仍只服务聊天音频，通话 PCM 不注入 `feedAudioChunk`。

## review attempt 2：初始化失败视觉清理

- 根因：native initialize 正常返回 unavailable 时，`finally` 先把 attempt 标为 closed；之后 `session.close()` 命中
  `if (closed) return`，导致 playback progress listener 不解除且嘴型不归零。
- 修复：attempt 内使用幂等 `cleanupMouth`，先失活 listener guard，再 unsubscribe 与 reset。所有关闭状态转移——正常 close、
  unavailable、initialize reject、timeout、resolver close、native close 抛错——均调用同一个清理边界。stop/tombstone 只在
  visual subscription 仍 active 时做逐流 reset，不能在 attempt 已清理后重复归零。
- timeout 在 `settleInitialize` 返回 false 时同步清理视觉；底层 initialize 后续返回 available 时仍按原所有权契约只关闭 native
  一次，不重复视觉清理。旧 progress callback 即使被外部保留，也会因 active guard 失效而不能更新新 attempt。
- 红测：`cleans the visual subscription exactly once when native initialization is unavailable`，修复前 listener 仍存在，
