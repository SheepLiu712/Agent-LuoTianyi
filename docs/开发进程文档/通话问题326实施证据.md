# 通话问题 #326 实施证据

## 范围与策略

- 固定基线：`4304212985e7917af6edcd332aeb99d45fdd1706`（含 #334 本地前置提交）
- 只处理 `CALL_TTS_FAILED` 单轮业务降级；其他协议错误、身份错误、序列错误和服务端终止仍走原有 fatal 路径
- `CALL_TTS_FAILED` 必须带当前 `call_id` 且只在 `connected` 状态降级；不会关闭 socket、停止采集或伪造 `playback.completed`
- 提示音失败被隔离，不会把单轮回复失败升级为整通失败；同一提示音尚未结束时收到重复错误只合并播放，不重复响铃
- 连续两轮失败结束、成功轮重置计数继续由服务端 `CallStage` 持有，本修复不复制客户端计数

## 实际错误音路径与许可来源

生产路径为：

`CallTransportSession.handleProtocolError` → `CallNativeAudioPort.playReplyFailureTone` →
`AndroidCallAudio.playReplyFailureTone` → Expo 原生 `CallAudio.playReplyFailureTone` →
既有通话 `AudioTrack` 队列。

提示音不是日志、网络请求或付费 TTS。`ReplyFailureTone.kt` 在本地按 24 kHz / 16-bit / mono PCM
程序生成两个带淡入淡出的短正弦音（520 Hz、390 Hz，总长 215 ms），源码为本 PR 原创，无第三方音频资产或外部许可依赖。
它使用既有 `USAGE_VOICE_COMMUNICATION` AudioTrack、焦点和收尾所有权，不进入采集输入，不产生 wire stream 身份或播放完成回执。
关闭会话时既有队列清理和 AudioTrack 释放同时清除提示音。

## 中文 PR 草稿

### 标题

`fix(call): 单轮 TTS 失败播放本地提示音并保持通话`

### 说明

修复客户端把服务端非终态 `CALL_TTS_FAILED` 当作 fatal 协议错误、从而关闭整通的问题。现在只对带当前
`call_id`、发生于 connected 状态的该错误播放原生离线提示音，并保持 socket 与采集继续可用；其他错误仍失败关闭。
提示音通过既有通话 AudioTrack 播放，不生成 `playback.completed`，播放失败也不结束通话。服务端既有连续两轮失败终止、成功轮清零策略保持不变。

验证：App 7 suites / 80 tests、TypeScript、ESLint 通过；服务端相关 25 tests 通过；真实 Android 模块
`compileDebugKotlin` 与 `testDebugUnitTest` 通过，Kotlin 共 11 tests passed。真机听感、AEC、焦点和路由未验证。
