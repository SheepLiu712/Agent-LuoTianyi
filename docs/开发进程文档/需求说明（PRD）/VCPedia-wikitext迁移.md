# VCPedia wikitext 迁移

## 目标与边界

本次只改新歌抓取的内部实现，不新增功能或公开契约，外部接口与行为应保持不变。直接沿用重构前已有的[项目架构中 world 的 get_new_songs 说明](../../项目说明/项目架构与接口（spec）/项目架构.md)和[world 对外接口的任务与新歌使用示例](../../项目说明/项目架构与接口（spec）/接口文档/world/README.md)，不另建抓取接口文档。

内部将模板与详情的数据通道从渲染 HTML 迁移到 MediaWiki API/wikitext，实现仍归属 `server/src/world/get_new_songs`。全站包括 API 均可能反爬，须保留挑战识别与 curl 兜底，不将 API 视为免挑战通道。请求参数、节点解析与模板处理属于内部实现，不上升为公开契约。

## 验收边界

- 既有调用方式、歌曲发现结果、详情内容与字段语义、正常与失败行为，以及数据库、关键词文件、每日调度等外部可观察结果均应保持不变；仅调用签名不变不足以证明兼容。
- 不借此调整失败缓存、批次上限、查重/更新、节流或 LLM 摘要策略，不新增跨模块服务、向量库或外部调度。
- 从既有抓取入口及任务入口对比迁移前后的可观察结果；离线固定样例和临时数据库/文件用于回归，不以新解析器的当前输出来重新定义预期。
- 歌曲目标与显示名选择、过滤结果、实体分类、简介、歌词和 infobox 的差异都应作为兼容问题核对，不能把新解析规则写成已获批准的需求变更。
- 离线回归通过不等于与旧实现完全等价，也不证明真实 API 或 curl 能通过当前站点反爬。真实联网测试直接运行，不添加外网标记、启用开关或默认跳过逻辑；离线回归通过 `-k 'not live'` 单独选择，联网结果单独记录。此要求按用户明确授权覆盖本次迁移的默认外网标记要求，不改变真实 LLM 等其他测试规则。

### 恢复原行为的验收

- 以 git HEAD 重构前两个抓取入口的可观察输出核验人工匹配的 HTML/wikitext 固定样例；列表恢复显示文本、旧过滤顺序、去星号与按显示名去重，详情请求及入库身份仍使用该显示名，不顺便修复旧别名抓错问题。
- 恢复歌词 h2 判定 Song、Person 不附加 short_summary、创作者不追加 summary；歌词恢复首个可采集 poem 和 span 优先的旧格式，不汇总多版本或章节外歌词。简介遵守旧 h3 截断及“截至…收藏”删除规则，不整句删除含统计模板的正文。
- infobox 的明确展示控制参数不得泄漏为业务字段。未知模板、远程 Lua、动态计数和未覆盖的渲染布局不能由源码可靠还原，须明确限制，不用广泛 HTML fallback 掩盖。
- 离线匹配样例仅证明所覆盖结构，不声称真实全站样例或完整行为等价。
