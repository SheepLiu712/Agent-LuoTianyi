# 管理 HTTP 接口

[返回总览](服务端接口文档.md) · [客户端 HTTP](服务端接口-HTTP.md) · [WebSocket](服务端接口-WebSocket.md)

本篇所有路径都以 **`/admin/api`** 开头。以下用完整路径作为接口标题。除健康检查、管理员初始化状态、初始化、登录外，全部要求管理员 session；与用户的 `login_token`、`message_token` 是不同认证体系。

主要来源：[admin_interface.py](../server/src/web/admin/admin_interface.py)、[管理员认证](../server/src/application/admin/auth.py)、[RuntimeSupervisor](../server/src/application/admin/runtime_supervisor.py)。

## 1. 认证与通用规则

管理员令牌优先从 `Authorization: Bearer <admin_session>` 读取，否则从 Cookie `agentluo_admin_token` 读取。令牌存在进程内，TTL 12 小时，管理进程重启后失效。Cookie 为 HttpOnly、SameSite=Lax、Path=/admin、Max-Age=43200，当前设置 `Secure=False`；浏览器管理 UI 使用同源 Cookie。

管理员密码直接以 JSON 字符串提交，不使用用户密码的 RSA 公钥加密流程。跨公网部署应由实际部署提供 HTTPS。

| HTTP | `detail.code` | 含义 |
| --- | --- | --- |
| 401 | `ADMIN_AUTH_REQUIRED` | 缺失 session |
| 401 | `ADMIN_SESSION_EXPIRED` | session 不被识别或已过期 |
| 403 | `ADMIN_SETUP_REQUIRED` | 管理员密码尚未配置 |
| 401 | `BAD_ADMIN_PASSWORD` | 密码错误 |
| 503 | `ADMIN_AUTH_BUSY` | 密码校验工作槽繁忙 |
| 400 | `ADMIN_ALREADY_CONFIGURED` | 已初始化，不允许再 setup |
| 403 | `BAD_SETUP_TOKEN` | 初始化令牌不正确 |
| 400 | `WEAK_ADMIN_PASSWORD` | 密码不足 8 字符 |

认证错误形式：`{"detail":{"code":"...","message":"..."}}`。登录按 IP 和固定 subject 限制为 5 次/300 秒，超限 429 `{"detail":"请求过于频繁，请稍后再试"}`。认证以外的错误也可能使用字符串 detail。

管理接口的数值 Query 范围由 FastAPI 校验，不合法返回 422；它们不同于用户列表在业务层截断数值的行为。多项管理写入接收普通 dict 而不是严格 Pydantic 业务模型，应提交下文规范结构；不是所有错误嵌套结构都保证转换成友好的 4xx。

## 2. 健康检查与管理员账号

### `GET /admin/api/health`

无需鉴权，无参数：

```json
{
  "status":"ok",
  "admin_auth":{"configured":true,"setup_required":false},
  "runtime":{
    "state":"running","running":true,"busy":false,"error":null,
    "last_started_at":null,"last_stopped_at":null
  },
  "observability":true
}
```

`status="ok"` 仅表示该管理健康入口可服务，不能据此断言角色业务可用；应检查 `runtime.running`。`error` 非空时含 `code`、`trace_id`，公开状态不暴露完整内部错误。

### `GET /admin/api/admin-auth/status`

无需鉴权，无参数。返回 `{"configured":false,"setup_required":true}`，表示是否需要首次配置管理员。

### `POST /admin/api/admin-auth/setup`

无需 session，JSON：`{"setup_token":"<初始化令牌>","password":"<至少8字符>"}`。令牌由服务端首次初始化生成，存放在 `server/config/admin_setup_token.txt`，需要部署者从服务端取得，不能从公开状态接口读取。

成功 `{"ok":true}`，保存加盐密码哈希并移除初始化令牌文件；不自动签发登录 session。错误见第 1 节，setup 完成后调用 login。

### `POST /admin/api/admin-auth/login`

JSON：`{"password":"<管理员密码>"}`。成功返回 `{"ok":true,"token":"<admin_session>","expires_at":1793548800.0}`，并设置上述 Cookie。`expires_at` 为 Unix 秒；这里的数值仅示意。

### `POST /admin/api/admin-auth/logout`

需鉴权，无业务参数；注销该 session 并删除 Cookie，返回 `{"ok":true}`。

## 3. 业务运行时

### `GET /admin/api/runtime/status`

无参数，返回 RuntimeStatus：

| 字段 | 说明 |
| --- | --- |
| `state` | 当前状态，如 `stopped`、`starting`、`running`、`stopping`、`blocked`、`failed` |
| `running` | 业务运行时是否运行 |
| `busy` | 是否有启动/停止等过渡任务 |
| `last_error` | 最近内部错误说明，可空 |
| `last_error_code` | 最近错误码，可空 |
| `last_error_trace_id` | 错误调用链标识，可空 |
| `last_started_at`、`last_stopped_at` | 最近启停时间，可空 |
| `validation` | 最近配置校验结果，可空，结构见第 4 节 |

### `POST /admin/api/runtime/start`

无业务参数。提交异步启动任务，立即返回当前 RuntimeStatus；可能仍为 `starting`。启动会加载本地密钥、展开环境变量、验证配置、装配业务运行时。

### `POST /admin/api/runtime/stop`

无业务参数。提交异步停止任务，立即返回 RuntimeStatus；可能仍为 `stopping`。会先撤销对外业务运行时引用再关闭资源，期间普通用户接口可能返回 503。

### `POST /admin/api/runtime/restart`

无业务参数。提交异步重启任务并返回 RuntimeStatus。启停过渡中重复请求返回现状，不应理解为每次请求都排入一个新任务。

上述 POST 返回 HTTP 200 不表示后台启停成功；轮询 `/runtime/status` 直至 `busy=false` 并检查 `running/state/last_error_code`。配置读取失败可进入 `blocked` / `CONFIG_READ_FAILED`，核心配置校验失败 `blocked` / `CONFIG_VALIDATION_FAILED`；停止失败可为 `failed` / `RUNTIME_STOP_FAILED`。部分可选 world 功能不满足配置时会禁用对应功能，不一定阻止核心启动。

## 4. 原始配置、校验、密钥

来源：[配置存储](../server/src/infrastructure/config/store.py)、[校验器](../server/src/infrastructure/config/validation.py)、[密钥存储](../server/src/infrastructure/config/secrets.py)。

### `GET /admin/api/config`

无参数。直接返回原始 `config.json` 的完整对象，不额外包 `config` 字段，不承诺对其中硬编码的密钥进行脱敏。配置 JSON 无效/读取失败：400，`detail.code=CONFIG_JSON_INVALID` / `CONFIG_READ_FAILED`。

### `PUT /admin/api/config`

body 是完整新配置 object。默认先备份原文件到 `config/backups/config.<timestamp>.json`，原子替换后执行校验，返回 `{"ok":true,"validation":<Validation>}`。

这是整体替换，不能只发想修改的子字段。该接口**先写再验证**，即使返回校验不通过，配置也已经写入；`ok=true` 不表示 `validation.core_ok=true`。不会自动重启运行时；需要另行调用重启。接口不是任意配置 schema 的静态保证，完整字段以配置读取结果和校验项为准。

### `GET /admin/api/config/validation`

返回 Validation：

```json
{
  "ok":true,
  "core_ok":true,
  "items":[{"scope":"core","name":"示例检查项","status":"ok","severity":"error","message":"说明"}],
  "world_disabled":[]
}
```

`items` 中 `scope/name/status/severity/message` 均为字符串；上例只演示结构，检查项名称和 scope 取实际值。`core_ok`/`ok` 表示无核心错误，`world_disabled` 中可含 world 的 disabled/warning 项。检查包括 JWT/地图等密钥、LLM/VLM 接口、模块绑定、模型需求类型、资源路径、消息令牌有效期及可选 world 功能。

### `GET /admin/api/secrets/status`

无参数。返回以环境变量名为 key 的对象：

```json
{
  "JWT_SECRET":{
    "configured":true,"source":"secret_store","masked":"abc******xyz",
    "required":true,"referenced":false,"category":"required"
  }
}
```

字段：`configured:boolean`，`source="secret_store"|"environment"|null`，`masked:string`，`required:boolean`，`referenced:boolean`，`category="required"|"llm_api_key"|"custom"`。固定必需键为 `JWT_SECRET`、`AMAP_KEY`；模型配置 api_key 引用 `$NAME` 或 `${NAME}` 的变量及已存自定义键也会列出。返回脱敏值，不返回密钥明文；短值全星号，长值保留首尾各 3 字符。

### `PUT /admin/api/secrets`

JSON：`{"JWT_SECRET":"<新值>","OLD_KEY":null}`。按键更新 `config/secrets.local.env`；null/空字符串删除键，其余值转字符串保存，并更新进程环境。

成功 `{"ok":true,"secrets":<脱敏状态>,"restart_required":true,"changed_keys":["JWT_SECRET","OLD_KEY"]}`。`restart_required` 表示有变化且业务当前运行；不会自动重启。删除本地键后可能恢复/使用原有系统环境值，应以再次查询的状态为准。

## 5. 模型配置编辑

来源：[model_editor.py](../server/src/infrastructure/config/model_editor.py)。

### `GET /admin/api/llm/config`

返回编辑视图：

```json
{
  "available_llms":{
    "example":{"api_type":"openai","model":"model-name","base_url":"https://example.invalid/v1","api_key":"$EXAMPLE_KEY"}
  },
  "available_vlms":{},
  "client_model_types":[{
    "id":"chat-model","name":"对话模型","description":"能力说明",
    "model_kind":"llm","requires_json":false,"requires_thinking":false
  }],
  "module_bindings":[{
    "path":"<原始配置中的模块路径>","kind":"llm","interface_name":"example",
    "prompt_name":"<模板名>","enable_thinking":false,"use_json":false,
    "client_model_type":"chat-model","params":{"temperature":0.7}
  }]
}
```

接口集合为 name→配置对象；`module_bindings.path` 是配置路径，须使用读取结果中现有模块路径。此视图从原配置产生，api_key 若原本硬编码也会直接出现在结果中，不等同于 `/secrets/status` 的脱敏视图。配置读取错误返回第 4 节的 400。

### `POST /admin/api/llm/config/apply`

body 使用上述完整编辑视图。接口集合和 `client_model_types` 会按本次 payload 替换，省略会按空集合处理。接口条目规范化 `api_type`（默认 openai）、model、api_key、base_url；模型类型去重并规范化 id/name/description/model_kind/requires_json/requires_thinking。

bindings 用 `path`、`kind`（llm/vlm）、`interface_name`、`client_model_type`、`enable_thinking`、`use_json`、`params` 修改现有模块。`prompt_name` 是读取视图信息，当前应用函数不写回此字段；未知路径/不支持 kind 被跳过。不要把它当任意路径创建接口。

它与原始配置 PUT 的差异是：先在内存规范化、解析环境变量并验证；核心失败则 HTTP 200 返回：

```json
{"ok":false,"written":false,"restarted":false,"validation":{},"runtime":{}}
```

核心成功后写盘；业务原先运行则等待一次 supervisor 重启，否则仅更新校验状态：

```json
{"ok":true,"written":true,"restarted":true,"validation":{},"runtime":{}}
```

上例 `{}` 是结构占位，分别为 Validation 和 RuntimeStatus。`restarted` 反映原先运行并执行了重启流程，最终是否运行成功仍需检查 `runtime.running/state`，不能只看顶层 `ok`。

## 6. QQ 音乐凭据

来源：[qq_music_credential_refresh.py](../server/src/application/admin/qq_music_credential_refresh.py)。

### `GET /admin/api/qq-music/credential/status`

返回刷新状态对象：`state`（idle/running/success/failed）、`running`、`message`、`started_at`、`finished_at`、`success`、`credential_file`、`legacy_file`、`qr_file`。尚未完成的时间、结果及二维码路径可能为空，文件字段是服务端路径，不是可直接打开的公网 URL。

### `POST /admin/api/qq-music/credential/refresh`

无业务参数；启动单个后台线程的扫码刷新，固定超时参数 30 秒，立即返回当前状态。重复发起时返回现有刷新状态，不另建并发任务。随后轮询 status 并通过 qr 获取扫码图。成功会保存/同步凭据并通知运行时相关学习模块。

### `GET /admin/api/qq-music/credential/qr`

无业务参数，成功返回 `image/png` 文件；不存在时 404 `QQ 音乐登录二维码尚未生成`。需管理员鉴权；在使用 Bearer 的客户端中，不能仅把 URL 丢给不带认证头的图片控件。

## 7. 可观测查询

这些接口使用管理进程的可观测服务，不要求角色业务运行时正在运行。时间、耗时单位分别看字段：`*_ms` 为毫秒，调用时间通常是 ISO 字符串。来源：[observability/service.py](../server/src/infrastructure/observability/service.py)。

### 7.1 `GET /admin/api/dashboard`

query：`days:integer=1`，1–90。返回：

- `window_days`：窗口天数。
- `llm`：`call_count,total_tokens,prompt_tokens,completion_tokens,avg_latency_ms,failed_calls`。
- `pipeline`：第 7.4 节的耗时统计字典。
- `logs`：`warning_count,error_count`（没有匹配记录时 SQL 聚合可能为 null）。
- `recent_logs`：最近最多 10 条 WARNING 及以上日志。
- `slow_spans`：最近查询中最慢的最多 10 条 span。

`recent_logs/slow_spans` 是各自的最近/最慢查询，不能假定也被 `days` 过滤。

### 7.2 `GET /admin/api/llm/summary`

query：`days:integer=7`（1–90）、`recent_limit:integer|null`（1–1000）、`bucket_hours:integer=2`（1–24）。

普通天数模式返回 `window_type="days"`、`window_days`、`totals`、`by_module`、`time_buckets`、`daily`。传 `recent_limit` 则优先以最近 N 次调用为窗口，返回 `window_type="recent"`、`recent_limit`，不返回 `window_days`，两个时间分桶数组为空。

`totals`：`call_count,prompt_tokens,completion_tokens,total_tokens,avg_prompt_tokens,avg_completion_tokens,avg_total_tokens,avg_latency_ms,failed_calls`。

`by_module` 每项含 `module_name,interface_name,model_name` 及上述统计，按调用数降序。`daily` 每项含 `day` 及统计。`time_buckets` 含 `bucket_start,bucket_label,bucket_hour` 及统计，按上海时间的日内小时段合并窗口内多天数据，不是每两小时一个连续时间线点。

### 7.3 `GET /admin/api/llm/calls`

query：`limit:integer=100`（1–1000）、可选 `module_name:string`、`trace_id:string`，均精确过滤。按 `ts DESC` 返回**数组**，无分页 envelope：

```json
[{
  "id":1,"ts":"2026-11-01T04:00:00.000+00:00","trace_id":"trace-1","user_id":null,
  "module_name":"main_chat","interface_name":"example","model_name":"model-name",
  "prompt_tokens":10,"completion_tokens":20,"total_tokens":30,"latency_ms":800.0,
  "success":1,"error_type":null,"error_message":null,"metadata":{}
}]
```

`success` 是存储的 0/1 整数，metadata 已从数据库 JSON 解码为对象。

### 7.4 `GET /admin/api/pipeline/latency`

query：`days:integer=7`（1–90）。返回按 `span_name` 为 key 的字典，每个值含 `count,avg_ms,p50_ms,p90_ms,p99_ms,max_ms`。不包含 p95 字段，不是数组。

```json
{"example.span":{"count":2,"avg_ms":50.0,"p50_ms":50.0,"p90_ms":90.0,"p99_ms":99.0,"max_ms":100.0}}
```

### 7.5 `GET /admin/api/pipeline/spans`

query：`limit:integer=100`（1–1000）、可选 `trace_id:string`、`slow:boolean=false`。默认按 `start_ts DESC`；slow=true 按 `duration_ms DESC`。返回数组，字段：`id,trace_id,user_id,topic_id,span_name,start_ts,end_ts,duration_ms,status,metadata`。

### 7.6 `GET /admin/api/traces`

query：`days:integer=7`（1–90）、`limit:integer=100`（1–1000）。聚合 span 与 LLM 记录，按结束/开始时间降序返回数组。每项含：

`trace_id,user_id,topic_id,start_ts,end_ts,duration_ms,span_count,total_span_ms,max_span_ms,llm_call_count,prompt_tokens,completion_tokens,total_tokens,total_llm_latency_ms,failed_llm_calls`。

`duration_ms` 是整体时间跨度，`total_span_ms` 是片段耗时之和；有并发/嵌套时不能互相替代。

### 7.7 `GET /admin/api/traces/{trace_id}`

Path：trace ID，无其他参数。返回 `{"summary":<聚合对象>,"spans":[...],"llm_calls":[...]}`，明细按时间升序，分别最多 1000 条。未找到 summary 时使用 `{"trace_id":"<请求ID>"}`，明细可为空；不是固定 404。summary 使用可观测保留周期内的有限聚合查询，不承诺无限历史完整性。

### 7.8 `GET /admin/api/logs`

query：`limit:integer=100`（1–1000）、`min_level:string="WARNING"`。级别 DEBUG/INFO/WARNING/ERROR/CRITICAL；大小写归一，未知级别按最低阈值处理。

返回按 `ts DESC` 的数组，每项字段：`id,ts,level,logger_name,message,traceback,trace_id,user_id,module_name`，关联字段可空。当前实现先取最近 `3*limit` 条再按级别过滤，因此高阈值查询可能不足 limit，即使更早还有匹配记录。

## 8. 管理动态与评论

本节要求业务运行时存在，否则 503 `{"detail":"system runtime is not running"}`。对象字段见 [HTTP 文档的动态与评论数据对象](服务端接口-HTTP.md#5-动态与评论数据对象)。

时间过滤统一接受 `YYYY-MM-DD HH:mm:ss`、`YYYY-MM-DD HH:mm`、`YYYY-MM-DD`，允许 T 替代空格；`created_before` 仅日期时扩展至当日 23:59:59。格式错误 400 `无效的时间格式: ...`。不是含任意时区偏移的通用 ISO 解析器。

### `GET /admin/api/dynamics`

| Query | 默认/要求 |
| --- | --- |
| `limit` | integer=100，1–500 |
| `cursor` | 可选 string |
| `owner_user_id` | 可选 string，用户 UUID |
| `author_type` | 可选 string |
| `source_type` | 可选 string |
| `status` | 可选 string |
| `created_after`、`created_before` | 可选上述格式时间 |

返回 `{"items":[<DynamicPost>],"has_more":false,"next_cursor":null}`，按创建时间/ID 倒序，可管理查询用户视图之外的动态。游标按返回值继续传入。

### `POST /admin/api/dynamics/system`

```json
{"content":"系统公告","visibility":"global","source_type":"system_notice","source_id":null,"allow_comment":false}
```

`content` 应为非空字符串；`visibility` 默认 global 且目前只支持 global；`source_type` 默认 system_notice，`source_id` 可空；`allow_comment` 默认 false，兼容 true/false 及 `1/true/yes/on`、`0/false/no/off` 字符串，未知值按默认 false。

成功 `{"ok":true,"item":<DynamicPost>}`，作者类型/ID 强制为 system，owner 为空，记忆接纳禁用。空内容 400 `系统动态内容不能为空`；非 global 400 `系统动态目前只支持全局可见`；保存失败 400 业务消息。

### `GET /admin/api/dynamics/{dynamic_id}/comments`

Path：`dynamic_id:string`；query：`limit:integer=200`（1–500）、可选 `owner_user_id`、`created_after`、`created_before`。返回 `{"items":[<DynamicComment>]}`，不含 `has_more/next_cursor`，没有用户评论列表同款 cursor 参数。

## 9. 邀请码管理

本节同样要求业务运行时存在，否则 503 `system runtime is not running`。body 均为 JSON object。

### `POST /admin/api/invite-codes/query`

```json
{"limit":100,"offset":0,"status":"unused","search":"关键词"}
```

`limit` 默认 100，1–500；`offset` 默认 0，≥0；`status` 可省略/为空，或 unused/used/disabled；`search` 可省略/为空，trim 后长度 ≤128。分页参数由 int 转换后检查。

返回 `{"items":[...],"total":123}`，item 字段：`code,is_used,disabled,created_at,used_at,user_id,username,nickname,can_use`。`can_use` 为未使用且未禁用。400：`分页参数无效`、`邀请码状态无效`、`搜索内容过长`。

### `POST /admin/api/invite-codes/generate`

body `{"count":5}`，默认 1，规范输入为 1–100 整数。明确拒绝 bool，其他输入当前先尝试 int 转换后由业务检查范围。成功 `{"ok":true,"codes":["<10位大写字母数字邀请码>"]}`；失败 400，例如 `生成数量需在 1-100 之间`。

### `POST /admin/api/invite-codes/disable`

body `{"code":"<邀请码>"}`。code 必须是字符串，trim 后非空、长度 ≤256。成功 `{"ok":true,"message":"已禁用"}`；缺失/错误类型/空白/过长为 400 `邀请码不能为空` 或 `邀请码格式无效`；不存在或写入失败为 400 业务消息。

### `POST /admin/api/invite-codes/set-disabled`

body `{"code":"<邀请码>","disabled":false}`。code 校验同上，disabled 必须是真实 boolean，不接受字符串 `"false"`。成功 `{"ok":true,"message":"已启用"}` 或 `已禁用`；错误 400，类型错误为 `disabled 必须是布尔值`。

### `POST /admin/api/invite-codes/delete`

body `{"code":"<邀请码>"}`，code 校验同上。只能删除未使用且未禁用的邀请码；已使用、已禁用、不存在或存储失败返回 400 业务消息。成功 `{"ok":true,"message":"删除成功"}`。

邀请码同时承担用户注册和账号重置凭证用途。管理员禁用邀请码后，该邀请码不能再用于账号重置；启用不等于把已使用的邀请码恢复成可再次注册的未使用状态。
