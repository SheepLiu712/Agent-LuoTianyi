# utils 对外接口

## 模块职责

`server/src/utils` 放置可被多个模块复用、但不包含具体角色业务的技术工具。工具应尽量是浅依赖和稳定函数；如果一个工具需要知道 Agent、world 或 system 业务对象，它通常已经不再是通用工具。

## 当前对外接口

### 日志

- `get_logger(name)`：取得项目统一配置的 logger。
- 日志 setup/handler 安装接口：配置控制台、文件和 observability 桥接。

### 配置与通用处理

- `load_config(...)`：读取项目配置。
- `apply_env_variables(...)`：把配置中的环境变量引用替换成运行值。
- `ensure_directory(...)`：确保指定目录存在。
- `get_unified_song_name(...)`：统一歌曲名称，便于查找和去重。
- 枚举、农历日期和图片转换等辅助函数：供需要相同基础算法的模块使用。

### 异步任务

- `run_sync_owned(...)`：以明确所有者运行同步工作，避免阻塞事件循环。
- `cancel_task_once(...)`：只取消一次指定任务。
- `wait_for_owned_tasks(...)`：等待某个组件拥有的任务退出。

### 模型基础封装

- `LLMService`：登记和取得命名的 LLM 模块、查询模块信息。
- `LLMModule.generate_response(...)` 及最近请求/配置读取：以项目统一方式调用文本模型。
- `LLMAPI` 与 factory：创建 OpenAI 兼容模型客户端。
- `VLMModule.generate(...)`：调用视觉模型。

这些类当前位于 utils，但已是基础设施服务而非普通小工具；目标上应通过 SystemRuntime 注入，不要在业务模块里随意新建全局实例。

## 正常与异常行为

- 纯文本、名称和日期工具不应产生外部副作用。
- 配置读取、目录创建、图片处理和模型调用分别会访问文件、环境或网络。
- 缺少环境变量、配置格式错误、模型响应内容不合法时应明确失败，不能用空字符串伪装成功。
- 取消任务时应只处理调用者拥有的任务，避免误取消共享服务。

## 使用示例

world 和 capabilities 都需要统一歌曲名时，可以共同调用 `get_unified_song_name(...)`。如果逻辑开始需要查询愿望单或用户记忆，就应放回对应业务模块，而不是继续塞进 utils。

## 应覆盖的契约场景

- 环境变量替换成功、变量缺失和配置类型错误都有稳定结果。
- 取消/等待异步任务只影响传入且由调用者拥有的任务。
- 模型响应为空或格式不合法时返回明确错误，不被记录为成功响应。

## 当前边界问题

部分 utils 代码目前反向导入 system 的全局服务，形成 `system -> utils -> system` 的隐性环。新增工具不应继续使用全局定位器；需要基础设施时通过参数传入。
