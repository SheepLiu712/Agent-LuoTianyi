# Godot 客户端总体设计

本文规定已授权目标的架构边界，不表示所有模块已实现。当前可用接口以 [interface](接口文档/client_godot/README.md) 为准；交付事实以 [进度](../../开发进程文档/开发进度/Godot-Windows客户端.md) 为准。

## 产品与技术基线

功能基线为 `79ae2c0`。新工程位于 `client_godot/`，旧端与 App 保持原路径。

用户提供本机引擎后，实际核实为 `4.7.1.stable.official.a13da4feb`；本轮明确采用 **Godot 4.7.1 标准版 x64**，替代原计划的 4.7.2。使用 Compatibility 渲染器，导出模板必须同版本。不得只凭文件名判断版本。

GDScript 承载界面和业务；`gd_cubism v0.9.1` 提供 Live2D；有限 C++ GDExtension 提供 Windows CNG OAEP/SHA256、DPAPI 及音频处理。不引入 Python 辅助进程或嵌入 Qt。插件、SDK、工具和下载校验值必须锁定，不能运行时下载依赖。

## 依赖方向

```text
Application（组装、关闭资源）
  ├─ UI scenes -> 会话/消息控制器 -> Network -> 现有 HTTP/WebSocket
  ├─ 会话/消息控制器 -> Media -> 原生音频
  ├─ 会话/消息控制器 -> AvatarDriver -> gd_cubism
  └─ Storage / 本地模型执行（明确注入所需依赖）
```

UI 不发送原始协议包、不访问插件内部对象。状态控制器通过 signals 通知 UI。角色驱动以项目中的表情/动作/口型语义封装插件。Media 区分接收、缓存和实际播放完成。原生层不理解聊天业务。

媒体持有由组装根注入的 AudioCache；存储模块负责服务器/账户隔离及完整文件提交，原生解码器提供格式、时长和低分辨率波形。缓存仅手动清理，不能引入自动淘汰；未完成与失败的临时文件仍须释放。重放结束与在线回复结束使用不同信号，避免本地回放推进聊天回复队列。

## 跨切片不变量

- 正常产品入口与离线演示入口分开；演示只使用固定模拟数据，不连服务器。
- 同一回复 UUID 的分片不重复创建气泡。后续句可以提前缓存，但展示和播放顺序受控制器管理。
- 网络、音频和模型请求不阻塞 UI；修改场景树和模型参数在主线程执行。
- 窗口最小化只抑制绘制，不暂停整个 SceneTree，避免停止网络和声音。
- 本地数据写入独立 `user://`，按服务器/账户隔离；安装目录只存程序和资源。
- 图片不信任服务端历史绝对路径；音频按新端缓存存在性提供回放。
- 构图按角色区域的相对坐标保存，调整窗口不拉伸模型；右键拖动不产生左键触摸。
- 资源从旧端复制后保留来源和哈希；不修改旧端原始资源。模型入口使用引用完整的 `model.model3.json`，不使用含缺失动作引用的旧 `model.json`。

## 检查点

### 0.1.0 的模块边界与预留方向

Application 持有账户、聊天、声音及业务控制器，桌面 Window 只展示状态与提交操作。历史 HTTP 适配器负责协议，同步控制器维护首次分页边界与发送屏障，ChatSession 合并消息；阅读位置通过独立本机存储访问，历史正文仅在内存。设置和动态的异步控制器不依赖桌面窗口；退出统一取消在途任务并隔离回调。

平台凭据与文件选择/分享、生命周期为明确的适配边界；现有 WindowsSecurity 实现当前平台，PCM 解码职责独立于 CNG/DPAPI。后续 Android 优先、iOS 保留适配方向，本轮不声称交付移动端适配。

角色稳定身份与模型资源变体分离，资源描述承载模型入口和表情/动作/口型/触摸映射；失败加载保留现有模型。换装页面与优先级为未来需求。HD-2D 箱庭作为未来独立呈现页，页面切换不重建会话或网络；未来接收世界状态/事件、提交互动意图，公共世界与私人关系区分，不用聊天文本伪装世界事件。依据 gh-pages 4.5/4.6，HD-2D 为本项目新增呈现方向，不更换当前 Compatibility 渲染器。

跨设备已读仅预留替换本机存储的方向，公共服务器暂无对应接口。以上未来能力不增加假成功方法；公开 interface 只随实际行为切片交付。

版本来源为工程内 release.json；运行标题/诊断读取同一资源，构建脚本读取同一文件。交付包不可覆盖已有包；临时构建与最终交付分开，不因重建自动提升版本。

1. 技术验证：真实模型、导出包及媒体/认证互操作分别通过后才扩大相关业务。
2. 视觉验证：真实模型与模拟聊天的可运行样板供用户确认；确认前不铺开账户、设置、动态页面。
3. 替换验证：完整功能矩阵、真机性能和安装测试通过后才切换交付入口。旧路径清理单独审核。

遇到依赖无法构建、模型无法正确渲染或导出失败时，保留证据并修正该切片；不得用静态图片冒充 Live2D 完成，也不得悄悄换引擎或增加浏览器辅助进程。

## 0.1.1 动态与下拉边界

DynamicsController 仍由 Application 持有；原生非附属 DynamicsWindow 管理列表选择与各动态详情草稿/阅读位置，原生非模态 PublishWindow 归属动态窗口。关闭窗口不关闭应用会话；退出账户统一取消控制器请求并销毁窗口。评论全量刷新临时收集完整分页后一次合并；未读轮询只更新汇总提示。UnifiedDropdown 封装原生弹层、稳定ID、缩放和键盘行为，页面不访问弹层内部节点。两者均沿用既有服务端协议，不新增移动端或服务端实现。


## 0.1.2 界面场景资源边界

UI 固定节点与静态样式由 `.tscn` / `theme/app_theme.tres` 承载，脚本负责行为、数据绑定与运行时组件实例化。业务视图使用 `PackedScene.instantiate() → setup(...) → add_child()`，内嵌视图由父级就绪后注入并只初始化一次。主场景允许引擎直接启动，保留 `user://window_layout.cfg` 默认值；离线入口为 `scenes/preview/chat_preview.tscn`。草稿确认框与 Live2D 模型/特效节点是明确保留的代码建树例外。具体节点和失败行为以客户端 interface 为准，迁移前 `client_godot/architecture/` 系列仅保留为历史快照。
