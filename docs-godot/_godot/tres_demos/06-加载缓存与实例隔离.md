# 06. `load`、`preload`、缓存与实例隔离

## `load` 和 `preload`

```gdscript
const THEME: Theme = preload("res://theme/app_theme.tres")

func _ready() -> void:
	var theme: Theme = load("res://theme/app_theme.tres")
```

`preload()` 在解析脚本时要求路径是常量，适合固定依赖；`load()` 在运行时取资源，适合动态路径。两者都会通过 Godot 的资源加载机制取得对象。项目主要通过场景中的 `ExtResource` 加载平台 `.tres`；例如 [`main.tscn`](../../../client_godot/scenes/main.tscn)。测试脚本则直接 `load()` [`app_theme.tres`](../../../client_godot/theme/app_theme.tres)。

## Demo A：缓存导致共享

```gdscript
extends Node

func _ready() -> void:
	var first: Theme = load("res://theme/app_theme.tres")
	var second: Theme = load("res://theme/app_theme.tres")
	print(first == second) # 通常为 true，同一路径命中 ResourceLoader 缓存

	var local_copy: Theme = first.duplicate(true)
	print(local_copy == first) # false
```

同一资源对象的运行时属性更改可能被其他持有者看到。`duplicate(true)` 建立独立副本；当你要修改内嵌 StyleBox、字体等对象时，仍应检查目标子资源是否共享，并在必要时显式复制。

## Demo B：`resource_local_to_scene`

[`window_host.tres`](../../../client_godot/resources/platform/window_host.tres) 设置了 `resource_local_to_scene = true`；[`window_chrome.tscn`](../../../client_godot/scenes/ui/window_chrome.tscn) 引用它。运行临时 `Node` 脚本：

```gdscript
extends Node

func _ready() -> void:
	var scene: PackedScene = load("res://scenes/ui/window_chrome.tscn")
	var a = scene.instantiate()
	var b = scene.instantiate()
	print(a.get("host") == b.get("host")) # 预期 false
	a.free()
	b.free()
```

Godot 实例化场景时为这类资源生成场景本地副本。这里不调用 `add_child()`，因此不会启动窗口宿主的附着逻辑。对比 Demo A：直接反复 `load("res://resources/platform/window_host.tres")` 不是“实例化两个场景”，不能把 `resource_local_to_scene` 理解成每次加载都自动得到新对象。

## 选择规则

| 需求 | 做法 |
| --- | --- |
| 多个场景共用只读资源 | 引用同一 `.tres`。 |
| 每个场景实例保存独立可变状态 | 在资源上启用 `resource_local_to_scene`。 |
| 在脚本中临时修改资源 | `duplicate(true)` 后修改并赋给当前使用者。 |
| 重启后保留数据 | 写入 `user://`；实例隔离不负责持久化。 |

## `duplicate()` 的深浅区别

```gdscript
var shallow = shared_theme.duplicate(false)
var deep = shared_theme.duplicate(true)
```

- `duplicate(false)` 复制根对象，但内部 Resource 子对象可能仍然共享。
- `duplicate(true)` 会递归复制可复制的子资源，适合准备修改 Theme、StyleBox 或复杂材质。

复制不是万能的：外部文件本身不会被改写，脚本对象的外部引用也可能有自己的生命周期。复制后仍要检查目标对象是否真的拥有所需属性。

## Demo C：观察场景本地资源

可以在临时脚本中更明确地打印脚本路径和实例身份：

```gdscript
extends Node

func _ready() -> void:
	var scene: PackedScene = load("res://scenes/ui/window_chrome.tscn")
	var first = scene.instantiate()
	var second = scene.instantiate()
	var first_host: Resource = first.get("host")
	var second_host: Resource = second.get("host")
	print(first_host.get_instance_id(), " != ", second_host.get_instance_id())
	print(first_host.get_script().resource_path)
	first.free()
	second.free()
```

资源实例 ID 只在当前运行中有意义；它不是可持久化 ID。第二行应打印 `desktop_window_host.gd` 的 `res://` 路径。

## 什么时候不要使用 `resource_local_to_scene`

只读的全局 Theme、共享图标、固定的安全适配实现不需要为每个场景复制。项目的 `windows.tres`、`runtime.tres`、`decoder.tres` 等平台资源没有这个标记，它们作为共享依赖注入。盲目给所有资源加上本地化会增加对象数量，也可能让你误以为实例状态会自动保存。

## 资源释放和场景卸载

`load()` 返回的资源可能被 ResourceLoader 缓存；释放节点不一定立即让资源文件从内存消失。通常不需要手工清理 `.tres`。需要控制长生命周期缓存时，使用明确的资源管理策略，不要依赖 `free()` 解决共享 Resource 的引用关系。
