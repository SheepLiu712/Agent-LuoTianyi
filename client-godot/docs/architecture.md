# 现行架构与客户端行为

本文说明 ..1.5.3 源码及 PR #186 第四轮整改后的行为，不是旧阶段记录。验证入口见 [测试说明](testing.md)，实际执行结果见 [归档的整改证据](../../archive/worklog/pr-186/review-186-4th-round.md)。

## 模块与依赖

固定 UI 位于 `scenes/`，动态消息、动态行、评论和确认框实例化已有场景；`src/ui` 只展示状态和提交用户意图。`src/composition` 装配服务；`src/application` 管理本地风格、账号作用域和窗口；`src/session` 管理账号、聊天、历史、动态及模型委托。网络、存储、媒体、角色通过独立能力接口连接平台实现。

账号生命周期先校验必要依赖，再启动服务；失败逆序回滚。退出登录、切换账号和退出应用释放所属资源；异步结果通过作用域/generation 防止迟到结果污染新账号。默认的换装、箱庭、设备互联接口返回不可用，不提供伪成功页面。

## 界面与窗口

聊天、动态、设置、日志四个入口保留原头像和 SVG/emoji 素材。扁平为默认，清透为独立外观；风格保存成功才更新共享内存 Theme，不改写资源文件。默认聊天窗口 128.×8..，角色/聊天双栏约为 1:2，分栏与窗口几何优先使用已有本地设置。

主聊天采用系统窗框；角色重置为右下角悬浮按钮。图片和音量图标位于输入区上方，发送为右侧方形图标；不增加清空输入按钮。输入区上沿那条分隔线本身就是拖动带：只有贴线 6px 内按下才算抓到它，横向铺满整条线，上下拖动在 48–32.px 内改高度，松手才写盘并按账号记住；带外的点击照旧交给输入框和按钮。文本自动增高只作下限，不会把手动拖过的高度压回去。成功、排队和发送中不占用状态栏，只有发送失败留一行「发送失败」；送达结果不确定的消息整条不出现，也不拦退出。角色顶部卡片仅展示最新未读动态；仅评论未读时不展示。左键点击卡片会播放缩放与亮度反馈，随后打开对应动态详情并隐藏卡片；失败时提示后同样隐藏。点开一条只在本机消退它的未读圆点，不写服务端。

动态和日志为独立窗口；设置跟随主窗口。全局图片窗口复用一个实例，归属于当前来源。退出登录关闭业务窗口但保留日志；退出应用汇总草稿，默认取消，不自动保存或发送。窗口几何可持久化，聊天/发布/评论文字草稿只在本次运行保留。本地记录写入 SQLite 只尝试一次：失败即放弃该条写入并计入丢弃数，不排队重放；失败对整个界面完全静默，不提示、不告警、不拦退出，退出流程与写入成功时一致。诊断日志按九类归档，规范、字段、隐私与检索方式见 [日志规范](logging.md)。

## 聊天时间与媒体

ChatSession 记录本地消息排队时间；回复取首个有效事件时间，流式后续和 ACK 不重写时间。历史按 UUID 合并，采用历史 timestamp 并保留实时正文。ChatTime 只负责解析和展示：首条有效消息给出定位，相邻实际消息间隔至少 3.. 秒才新增时间气泡；连续对话不按累计时长插入。时间条不进入业务消息 ID 或阅读锚点。

Unix/带时区时间按当前系统偏移显示，无时区日历串保留墙上时间；本轮不改变该语义。图片按实际内容校验，BMP 读取后归一化为 PNG；语音按 UUID 聚合、顺序播放，仅完整且成功提交的缓存可重放。错误/断线清理不会伪造成功或自动重复写入。

Python 客户端媒体导入只认用户显式选择的 exe（取其所在目录）或客户端目录，不再按仓库/可执行文件相对位置猜路径。`python_client_locator` 用 `config/config.json` 的 Live2D 模型路径或 `temp/user.json` + `temp/` 做只读指纹，定位 `temp/tts_output` 与 `temp/images`；`python_media_migration` 在同一后台队列里把 UUID 对齐的 WAV 与 PNG/JPEG/WebP 复制进当前账号缓存，源文件不改动、已有条目不覆盖。图片在 `history_images` 缓存未命中且联网之前按需查同一来源；聊天正文不导入，历史仍由服务端提供。选择结果保存在 `user://window_layout.cfg` 的 `[migration] python_client_path`，打开“缓存与导入”页时才重新校验。

用户可见错误统一由 `ErrorDialog` 按当前窗口懒加载弹出：串行队列、重复文本短时去重，并写入 `warning_ui_error` 日志。聊天、设置、动态、日志、图片窗与主窗只保留连接/加载/草稿/重试等中性状态，不再内联错误原因；表单校验与移除项按 `docs/user-visible-errors.md` 的判定执行。

服务端 `audio_error=true` 是失败终止包，不是本地解码异常；客户端标记 `REMOTE_AUDIO_ERROR`，中止该条播放与不完整缓存，但保留文字、顺序推进后续回复。同一 UUID 的错误提示只由展示队列报告一次，完成回调和重复终包不再重复提示。`reply_received` 仅记录白名单 `TTS_EMPTY`、`TTS_STREAM_ERROR`、`TTS_CANCELLED`；未知原因归为远端音频错误，不写入任意服务端异常原文。`system_error` 携带脱敏回复标识，便于与媒体链路关联。本地解码失败仍使用原有 `AUDIO_ERROR` 提示。

## 动态与逐条阅读位置

初次打开不自动选中；列表/详情默认约 35:65，可拖动分隔条。点击卡片，包括当前选中项，自动刷新完整评论；请求运行中不重复发起。列表与评论通过滚动加载，无手动加载框。点开一条只在本机记下已读位置（服务端没有单条已读入口），徽标与跨会话的已读状态只由“全部已读”明确成功才更新。

每条详情拥有独立的恢复目标。窗口切换通过 `get_reading_position()` 保存当前位置或尚未应用的目标，通过 `restore_reading_position(position)` 登记恢复；等待评论请求结束与布局稳定后，将目标限制到 `max_value - page` 的合法范围。

隐藏详情不会抢占当前详情位置，旧请求不会把新页面拉回。真实滚轮、触摸平移及滚动键/滚动条操作取消旧恢复目标。刷新失败保留既有内容、阅读位置和草稿，并明确提示点击卡片重试。此状态仅属于 UI，不修改网络协议或聊天历史阅读位置文件。
