## 指标语义

`call.first_audio` 是服务端首包指标，不代表客户端开始播放，也不能替代端点判断延迟。

- **计量单位**：`duration_ms`，来自注入的单调时钟
- **起点**：一个有效 `TurnCompleted` 经 provider `events()` 被 `CallStage._consume_events` 接纳为正式通话轮次的时刻
- **终点**：属于该轮次的任意 `Say` response 第一个非空 canonical PCM 块经 `websocket.send_bytes` 成功返回的时刻。包含业务队列和网络发送等待，不等同于客户端已收到或开始播放
- **每轮定义**：每个正式通话轮次至多记录一个成功样本。一个轮次内的多个 `Say`、多个 stream 和后续 PCM chunk 不会重复记录；`RECALL` 的 provisional 过渡语属于该轮次，符合 AC-06「可计入首包」的口径
- **重连排除**：`disconnect()` 会标记当时尚未记录首音频的已有正式轮次为不连续。即使 Adapter 在 resume 事务中缓存并随后重新投递输出，该轮次也不产生成功样本；不会在重试时重置原 `TurnCompleted` 起点。恢复成功后的新轮次正常测量；已经记录的旧轮次不会因重放重复记录。负责人确认保留断线状态异步落库窗口内新接纳轮次的行为，它们可能恢复后记录成功；本次不修改该窗口，不承诺排除所有跨连接样本
- **其他排除**：setup 中的音频不计；没有关联正式轮次的输出不计；PCM 发送失败、输出取消或被用户打断而从未成功发送 PCM 时不产生成功样本。重试在同一轮次内：若先前未成功发送，重试的首个成功 PCM 可记录；若已经记录，不重复记录
- **标签**：仅 `result=succeeded`。没有 `call_id`、`turn_seq`、response ID、文本、转写或音频作为 metric label；观测存储仍以既有 `call_id` trace 关联

首次 PCM 的记录点位于 `provider → CallStage → Agent → OutputSink → Adapter → Session → Delivery → Binding → Web send_bytes → complete_output → Stage.audio_sent` 链上。业务 sink 完成仍只表示接纳，不等待网络；Binding 只在有效在途投递成功时调用通知，失败、取消和关闭释放通知。Stage 复核状态、generation、tombstone、断线排除及逐轮去重。ACK 和实际播放完成仍走原路径。

4. `test_first_audio_excludes_turns_crossing_reconnect_and_accepts_new_turn_after_resume`：生成前跨 disconnect/resume 的轮次没有成功样本；恢复后的新轮次有一个正确样本

6. 同一轮次的首次 Say 失败后重试，首个成功 PCM 仅记录一次且仍从原 `TurnCompleted` 起点计量
