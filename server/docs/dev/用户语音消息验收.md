## 离线端到端入口

在安装 Server、CLI 的项目依赖及 pytest 的 Python 环境中，从 `server` 目录运行：

```sh
python -m pytest tests/e2e/chat/test_voice_offline.py -q
```

此测试由常规 pytest 自动发现，不需要预先启动服务、生产配置、供应商密钥、Redis 服务或真实用户账号。CLI 使用已有内部驱动，没有新增用户可见语音命令。每次启动独立子进程，绑定 loopback 随机端口；账号、SQLite、RSA、媒体及日志均位于 pytest 临时目录。结束时请求退出并等待资源关闭，超时则终止子进程；异常退出或断言失败使 pytest 非零退出。启动最多等待 30 秒，回复事件分别有 10 秒等待上限。失败时可查看临时目录的 `server/server.log`。

真实执行：CLI NetworkClient / HeadlessSession、HTTP 登录、WebSocket、生产路由和服务、Adapter、媒体校验及持久化、StageManager / ChatStage、Agent 的预处理、音频理解 Skill、回复生成及 ActionPlan 实现、历史查询与鉴权下载。测试装配替换模型供应商和长期记忆重依赖，使用项目内存缓冲实现；不伪造 ACK、Stage 输出或回复事件。不是生产组合根启动测试，也不证明实际供应商识别质量。

输入来自仓库真实 AAC-LC fixture，等长修改为 Android 的 mp42/isom 品牌，增加合法 free box 使上传跨三个分片；这不是 Android 真机录制证据。断言包括：

- begin、三个 chunk、finalize 均收到成功 ACK，且 listening → thinking → 完整预期回复按序出现。
- 同 upload_id 重传返回同一消息身份，音频理解和回复模型各执行一次；额外观察窗口内没有第二次回复。
- 历史只有一条用户语音及一条角色回复，不暴露内部理解字段。
- 本人 Bearer 下载字节 SHA-256 一致；无效或缺失 Bearer、其他用户及删除后访问被拒绝，删除可重复执行。

端到端测试发现并补齐了语音理解开始时的 listening 输出；已有 thinking 状态不会被覆盖。App 同时明确将原生 metering 回调间隔设置为 80ms，避免默认间隔不符合反馈要求。
