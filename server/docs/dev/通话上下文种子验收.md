## 已实现行为

- `ContextFactory.create_call(interaction_id, *, user_id, requested_at)` 要求非空用户和服务器本地 naive 时间，不用当前时间替代调用方事实。
- seed 查询按同用户、同角色和 `requested_at` 读取一个 SQL snapshot，不调用聊天 Redis/context state 路径，也不创建或修改 Conversation、ConversationContext、维护 batch 或 Redis seed 状态。
- 三分钟只决定是否加载：最新 eligible 记录必须位于闭区间 `[requested_at - 3 分钟, requested_at]`；命中后保留安全摘要并取最新最多 30 条正式记录，按 `(timestamp, entry_id)` 正序提供。
- 若存在 future 记录、摘要覆盖无法证明、保留数不是合法 suffix 或最新 eligible 记录超过三分钟，整个 seed 返回空快照，不拼接不可信摘要与部分历史。
- `EphemeralCallConversationStore` 复制并规范化 seed；append/compact 仅修改内存，close 清除 Store 自身 snapshot，关闭后的 Context 公开引用拒绝访问。
- profile/preferences 仍从正式用户存储读取；“seed 查询只读”不等于整个 Context 创建过程不访问用户资料缓存或数据库。
- Factory 在 Store 创建成功但 profile/preferences 或 Context 构造失败时关闭临时 Store；创建被取消时等待 owned read 完成，并关闭未交付 Context。
- 默认 `ContextFactory.create()` 继续使用聊天 Database Store；CL-1 维护进度与 ChatStage 行为未改变。
