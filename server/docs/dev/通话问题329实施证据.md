## 修复与绿证据

生产路径将 Aliyun provider 的 `item_id` 透传到 `SpeechStarted`、`SpeechStopped` 与 `TurnInvalid`；`CallStage`
仅在该 item 仍是当前 speaking 所有者时解除 speaking 并刷新 silence。无效轮次不创建 `CallTurnCompleted`、不创建
正式 turn、也不改变认知维护进度。

回归测试由 `FakeRealtimeSpeechSession` 经 `CallStage._consume_events` 消费正式事件，使用可控单调时钟，覆盖：

- 持久回归 `test_invalid_turn_without_identity_releases_speaking_without_formal_turn_or_reply` 使用基线兼容构造
  `SpeechStarted()` → `TurnInvalid("turn_invalid")`；断言 speaking 解除、generation 与认知维护进度不变、无正式
  turn、无未完成 turn、无 `CALL_TURN_COMPLETED` handler 请求、无计划残留
- `SpeechStarted → TurnInvalid` 后 speaking 解除，已有播放完成资格可恢复 silence 起点
- 将可控单调时钟前进五秒后，Stage 自己的 silence task 经 `Agent.handle_stimulus` 向
  `CALL_SILENCE_ELAPSED` handler 交付一个 `CallSilenceElapsed`，不是直接伪造 stimulus
- 无效轮次不新增正式 turn 或未完成 turn
- 新轮次开始后，晚到或重复的旧轮次 `TurnInvalid` 不清除新轮次 speaking、不改变 generation，也不推进维护进度
